# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

`lovegw` is a Telegram bot (Go, module `lovegw`, everything under `go/`) that
mirrors the "notes" (заметки) section of the dating site love.ngs.ru into
Telegram channels, and bridges interaction back: logged-in Telegram users reply
in the discussion group and the bot posts their reply as a comment on the site
using their saved cookie session. A second bot, **РюмкинЪ**, runs in private
chats for site login, posting notes, and keyword subscriptions.

Scraping is done with `net/http` + goquery against the site's HTML (CSS selectors
like `.lv-notes__note-item`, `.lv-note__comment-item`). The project replaced an
earlier Python prototype, which has been removed — recoverable from git history
if ever needed. Conventions: code identifiers are English; comments, commit
messages, and all user-facing bot strings are in Russian.

С 17.08.2026 к этому добавилась **собственная площадка «Зазеркалье»** (эпик E,
домен `t3h.ru`; имя живёт одной константой `web.SiteName` — оно же в заголовках
страниц, в письме с кодом входа и в тексте согласия, поэтому переименование это
всегда новая редакция документа): свой Postgres, куда то же зеркало пишет третьим приёмником, — чтобы
сообществу было куда переехать, если НГС закроет «Заметки». Пакеты `platform`
(ядро) и `platsink` (приёмник + сверка); свой хост, свой compose
(`deploy/platform/`). Живёт эпик в `docs/backlog.md`.

## Build / test / run

- Build/test: `cd go && go build ./... && go vet ./... && go test ./...`
  (`-race` needs cgo, run it on Linux/CI).
- Run daemon: `go run ./cmd/lovegw run [-seed]` — mirror + reply bridge + DM bot
  under one errgroup. `-seed` on first run records currently-visible notes
  **without** posting them (avoids a burst at cutover; posts only notes that
  appear afterwards).
- Diagnostics: `go run ./cmd/lovegw doctor [-post-test]` checks
  config/DB/site/tokens/queue; `-post-test` verifies the channel→auto-forward
  chain with a silent self-deleting message (safe on the live channel).
- Debug crawl: `go run ./cmd/lovegw crawl notes` / `crawl comments <note_id>`;
  `-save-html <dir>` records real pages as parser fixtures into
  `internal/love/testdata/` (fixtures `notes_feed.html` and
  `comments_312696.html` are real recorded pages; re-record with the same
  command on markup drift).
- Rescue a note the feed scan missed: `go run ./cmd/lovegw pull [-db path] <id>`
  (заводит заметку по прямому id; `-full` дотягивает весь тред в древовидном
  виде и возвращает архивную заметку в отслеживание). Безопасно при работающем
  демоне — постит он сам.
- Weekly digest: `go run ./cmd/lovegw digest [-week N] draft` строит черновик
  недели и материалы для LLM-редактуры (`<dir(db)>/digest/`); считается выпуск
  по площадке, если она настроена, иначе по зеркалу НГС. Админ заполняет
  `<!-- LLM:… -->`-рубрики из materials.md, `digest preview` показывает тело
  заметки-выпуска и разбиение по мессенджерам, `digest publish` публикует
  выпуск **заметкой на площадке** — в каналы её отнесёт исходящий обход демона
  (`-force` — «сухой» выпуск без LLM-рубрик; `-to telegram|max` — прежний путь
  прямо в канал, он же работает, когда площадка не настроена). Публикация
  идемпотентна и резюмируема через `message_targets` (kind `digest`, приёмник
  `platform` либо мессенджер) — безопасно при работающем демоне (поллинг не
  поднимается). Метрики выпуска требуют **схемы 0011** (индексы по времени
  комментария): без неё недельное окно читает всю таблицу.
- Амвон (`pulpit`): публикует только демон, а руками —
  `go run ./cmd/lovegw pulpit draft <note_id>` (черновик реплики по заметке, на
  сайт ничего не уходит — стенд для правки промпта) и `pulpit status`. Тумблер
  «работает сейчас» переключается в ЛС командой `/pulpit` (админская, в меню
  команд не значится).
- Утренняя заметка (`morning`): одна заметка «доброе утро» в сутки, публикуется
  **на НГС** от анкеты владельца (в 05:00 Нск), а на площадку и в каналы её
  приносит зеркало — отдельного пути публикации нет и не нужно. Руками:
  `go run ./cmd/lovegw morning sources` — что отдали интернет-календари и что
  из этого срезал фильтр (стенд парсеров и стоп-списка, в сеть ходит, на сайт
  нет), `morning draft [-day 2026-08-24]` — черновик заметки, тоже без
  публикации (стенд промпта), `morning post [-force]` — ручной догон дня,
  `morning status`. Тумблер «работает сейчас» переключается в ЛС командой
  `/morning` (админская, в меню команд не значится). **Если «доброе утро»
  сегодня уже написал кто-то другой — служба молчит** и говорит об этом
  владельцу в ЛС: хозяин утра человек, а не бот.
- Жители площадки (`narod`, эпик «народ», бриф `briefs/brief-ensemble.md`,
  где эпик стоит и чем упирается — `briefs/narod-handoff.md`):
  `go run ./cmd/lovegw narod card <p<id>|u<id>>` снимает СЛЕПОК донора из архива
  (манера, ритм, задержки, характерные ошибки, интересы, стартовые отношения) —
  инструмент калибровки, наружу не идёт; `narod compose <рецепт> [-verify]`
  собирает из слепков ЖИТЕЛЯ (числовые цели смешаны, ник и биографию пишет
  владелец) и говорит, не вышел ли «композит» одним донором под чужим именем;
  `narod show` печатает карточку ровно так, как её увидит модель; `narod world`
  показывает состояние мира. Ни сайта, ни Postgres не трогают вовсе — читается
  только `archive.db`, поэтому гонять их можно на рабочей машине.
  **Калибровка** — `narod replay -actor u<id> [-threads N] [-speak]`: слепок
  играет на месте настоящего участника в архивном треде, и умений меряется ДВА
  порознь. РЕШЕНИЕ («прийти или смолчать») считается в каждой точке и **не стоит
  ничего** — это формула, поэтому цикл «правка кубика → прогон → отчёт» крутится
  сколько угодно раз; читать его в отрыве от базлайна молчуна нельзя (в людном
  треде «никогда не приходить» даёт 96 % верных решений, и отчёт печатает это
  число рядом всегда). ГОЛОС меряется только там, где человек ответил на самом
  деле, и вот он платный — `-speak`, около 2 центов на реплику. Единица мерки
  голоса — **ПАЧКА** реплик (600 знаков), а не реплика: комментарий медианой в
  75 знаков даёт 73 символьные 3-граммы против порога в 300, за которым ранг
  атрибуции шумит, и полоса из отдельных комментариев честно объявляет себя
  непригодной — а `BandQuantile` у непригодной полосы возвращает ноль, неотличимый
  от приговора. Первый платный прогон 28.08.2026 напечатал этот ноль как
  измерение («квантиль 0.00, место 7932 из 9361»); пачками те же реплики дали
  0.67 и место 1379. Отсюда два правила: полоса спрашивается ДО первого запроса к
  модели и непригодная **останавливает прогон**, не потратив ни цента, а рядом с
  рангом всегда печатается механический портрет (длина, слова в предложении,
  смайлы) — ранг говорит «не похоже», портрет говорит ЧЕМ.
  Треды подбираются РАВНОМЕРНО по размаху разговорчивости донора, а не с
  верхушки: у самых людных его тредов мерился потолок реплик, а не догадка
  кубика, и полнота у трёх слепков в точности повторяла отношение «потолок к
  репликам в треде». Рядом с полнотой печатается, насколько выборка типична.
  **Вероятность ответа — ЗАМЕР, а не настройка** (`archive.MineReplyRate`,
  корзины по позиции реплики в треде): у каждой чужой реплики в треде видно,
  ответил человек или нет, настоящим ребром `comment_reply`. Придуманное «влезть
  в чужой разговор = 0,15» оказалось завышено в 20–40 раз (настоящее 0,4 % у ДВ,
  3,7 % у Полынь-Травы), а «ответить, когда обратились = 0,7» попало почти точно
  (настоящее 39–91 %) — на глаз угадывается частое и не угадывается редкое, а
  поведение в людном треде состоит из редкого. Затухание по глубине треда
  настоящее, но скромное: мимо-разговорная вероятность падает вдвое-вчетверо к
  трёхсотой реплике, обращённая к человеку — едва на четверть. После замера
  точность прихода выросла с 5–17 % до 29–56 %, а верных решений сравнялось с
  базлайном молчуна вместо отставания на 15–25 пунктов.
  **Зерно одно — это бросок, а не замер** (`-seeds`, умолчание 5): пять зёрен на
  ОДНИХ И ТЕХ ЖЕ пяти тредах дали у ДВ полноту 20–37 % и точность прихода
  39–76 %, то есть одиночный прогон врал в полтора-два раза, а «стало на десять
  пунктов лучше» между двумя такими не значило ничего. Отчёт печатает таблицу по
  зёрнам и сам разброс; правка кубика считается удачной, только если вывела
  число ЗА него. Модель зовут лишь на первом зерне — голос от броска не зависит.
  Честный базлайн 28.08.2026 (5 зёрен × 5 тредов): ДВ 31 % полноты при 63 %
  точности, Полынь-Трава 12 / 41, Мурена 31 / 62.
  **Вакуум** (`narod replay -mode vacuum -actor u1,u2,u3`) — вторая половина
  калибровки: из архива берётся ОДНА заметка, дальше жители говорят сами
  (каждая реплика — точка решения всем остальным), и мерится форма разговора, а
  не совпадение с чужим ходом. Тоже бесплатно без `-speak`: модель нужна только
  на текст. Оригинал СУЖАЕТСЯ до того же состава — у нас трое, в настоящем треде
  говорили тридцать, — и обе формы снимает одна функция. Первый прогон
  28.08.2026 нашёл, что кубик не зависел от заметки (у точки решения на самой
  заметке номера реплики нет вовсе, и бросок повторялся во всех тредах серии;
  в solo это было незаметно — там такая точка одна из двух тысяч) и что отчёт
  хвалил пустой прогон Жаккаром «пустое против пустого = совпадение».
  **Разговор между жителями заводится от ЧИСЛА жителей**, и трое — это не
  маленькое сообщество, а другое явление: 3 жителя дают 0,8 реплики на заметку,
  ответ друг другу в 1 % прогонов и 38 % заметок совсем без реплик; 8 — 2,8 и
  17 %; 12 — 4,3 и 33 %; 16 — 6,3 и 46 %. Причина прямо в замере отклика: влезть
  в чужой разговор человек готов в доле процента, и полпроцента с двух соседей —
  это тишина, тогда как процент с тридцати (столько было рядом с донором в
  архиве) — уже разговор.
  **Мерка этому — «во что разрастается реплика»** (`narodsim.branching`, замер
  29.08.2026): всего сказанного на одну реплику, пришедшую В ЗАМЕТКУ. Разговор
  есть ветвящийся процесс — пришедший говорит, его реплика становится точкой
  решения остальным, часть отвечает, — и пока величина меньше единицы, тред
  затухает за два-три круга при ЛЮБОМ содержании реплик. Замер по десяти
  конфликтным заметкам: у оригинала 0,82, у наших двенадцати 0,52, и в этом
  ВСЁ объяснение разрыва «7 реплик против 95» — ни промпт, ни потолки, ни
  вероятности тут ни при чём.
  **Средним числом, впрочем, объясняется только половина: у величины есть
  КРИВАЯ** (`narodsim.BranchDecay`, таблица «тормоз» в отчёте). У оригинала она
  идёт 2,00 у первой реплики → 1,90 → 1,19 → 1,09 → 0,83 → 0,75, то есть тред
  РАЗГОНЯЕТСЯ и сам себя гасит, а перелом лежит около шестидесятой реплики.
  У нас на двенадцати она шла наоборот — 0,18 → 0,44 → 0,70 → 0,67, — значит
  тред не затухал, а НЕ ЗАЖИГАЛСЯ. В точке зажигания не работает ничего, кроме
  числа жителей: у первой реплики нет ни знакомства, ни сцепившейся пары, ни
  накала, только чужие глаза со своей вероятностью влезть, — и замер по восьми
  составам дал разгон на жителя постоянным (0,017), то есть 0,18 это ровно
  11 × 0,016.
  **Отсюда рычаг, уменьшающий нужное число жителей: РАЗГОВОРЧИВОСТЬ.** Готовность
  влезть в чужой разговор разнится у людей впятеро и больше (в наборе из 23
  слепков от 0,75 % у ДВ до 9,66 % у KVADRATIг), поэтому состав из разговорчивых
  зажигает тред вдвое меньшим числом. Столбец ВЛЕЗЕТ стоит теперь в `narod
  scout` — там, где состав и подбирают; порядок строк при этом остался прежним
  (по ответам составу), потому что вопросы разные: разговорчивый, не
  пересекающийся с составом, зажжёт тред и уйдёт говорить в сторону.
  **Прямой в этой величине нет — она насыщается, и измеренные точки это
  доказали.** Прямая по составам 3/6/9/12 (0,045 на жителя) обещала на 23
  жителях 1,03, то есть неостановимый тред; на самом деле вышло 0,68, а дальше
  наклон падал и падал: 12 → 0,52, 23 → 0,68, 29 → 0,75 (0,0145 и 0,0117 на
  жителя). Гнёт кривую сам замер накала: в разгоревшемся треде влезают в чужой
  разговор ВТРОЕ реже — то есть тормоз у нас уже есть, и он тот самый, что у
  живых. Оригинальные 0,82 по нынешнему наклону ложатся примерно **тридцатью
  пятью жителями**, и это оценка, а не замер. Столько же людей, сколько было в
  настоящем треде (26–63), не нужно: наши на площадке всегда, живые заходили по
  разу.
  **Что даёт сам рост, замерено** (те же 10 заметок, 5 зёрен): 12 жителей — 70
  реплик за серию, пауза между репликами 21 мин, зажигание 0,18; 23 — 219, 5 мин,
  0,42; 29 — 373, 3 мин, 0,58 (у оригинала того же состава 584 и 2 мин). ХВОСТ
  кривой при этом уже сошёлся — 0,68–0,71 против 0,83 у оригинала, — и весь
  оставшийся разрыв сидит в НАЧАЛЕ: у первой реплики 0,58 против 2,00. Живой
  тред открывается тем, что в заметку РАЗОМ заходят десятки разных людей (58
  корней на заметку против наших восьми). Вероятность «прийти в новую заметку»
  числилась тогда единственной величиной кубика, у которой замера нет и быть не
  может, — 29.08.2026 это опровергнуто (см. ниже про `archive.MineComeRate`).
  Десять персонажей в брифе перестали быть догадкой — и оказались нижней
  границей, а не целью.
  **ТИШИНА УБИВАЕТ ТРЕД, и это тоже замер** (`archive.MineDecay`, корзины
  Hazard, 2981 тред): после часа молчания разговор продолжается в половине
  случаев, после трёх — в четверти, после двенадцати — в пяти процентах. Без
  этого броска кубик не знал, что разговор бывает КОНЧЕН: у задержки длинный
  хвост, одна реплика, выпавшая на десятый час, воскрешала затихший тред, и за
  ней тянулись новые точки решения. Ловится это НЕ паузой между репликами (она
  была правильная, 3 мин против 2), а тем, за какую долю срока набралась
  половина реплик: у нас выходило 0,12 при 0,50 у суженного оригинала, девять
  десятых набирались к 11,3 ч вместо настоящих 1,7–7,1. С тормозом — 0,53
  против 0,50 и 1,5 ч; ценой ему половина реплик серии (373 → 182) и разрастание
  0,75 → 0,67, но эти реплики приходили в тред, из которого все давно ушли.
  Число жителей под оригинальные 0,82 отсюда снова выросло — оценка на текущем
  наклоне уходит за сорок, и замера у неё по-прежнему нет.
  **DoD этапа 3 закрыт 29.08.2026**, и последний его пункт стоит назвать целиком,
  потому что проверить его можно только глазами: в ПОЗДНЕМ треде серии (313040,
  2026 год) ГердаИзСемейкиАддамс сказала «приехал верхом, вручил ум и сразу
  требует благодарности, будто ПОЛКУ ПРИБИЛ… у меня вот кошка соседкина всё лето
  на БАЛКОНЕ прожила», а следом «прибил полку — иди смотри, ровно ли». Полка с
  «ровно ли» — её собственный эпизод из треда 283700 семью годами раньше
  («меч выдадут после проверки жены, ровно ли висит»), кошка на балконе — её
  внутреннее событие. Оба следа пришли в реплику через `narod.WriteMemory`, руками
  не закладывались, и это ровно то «а помнишь», ради которого затевался мир.
  Чего в мире по-прежнему НЕТ — ссоры: за платный прогон симпатия сдвинулась у
  восьми пар, раздражение у одной, и летописец видит поддёвки («отказалась греть
  кофе без полки, попрекнула отсутствием хозяйственного вклада»), но во вражду
  они не складываются.
  **ОБЪЁМ РАЗГОВОРА — ЦЕЛЬ, а не побочный показатель** (владелец, 29.08.2026):
  ветвистый тред и есть продукт, «зато честно измерено» не оправдывает пустой
  ленты. Упёршись в величину без замера, считать это недоработкой МЕТОДА и
  искать рядом вымеримое — что и дало два замера ниже.
  **Размер треда = КОРНИ / (1 − разрастание)**, и обе половины теперь замерены.
  Проверено на живых: 47 корней при 0,82 дают 261 против настоящих 283; у нас
  7 при 0,90 дают 70 против замеренных 79. Отсюда видно, что разрыв «наш тред
  вчетверо короче» сидел целиком в КОРНЯХ — репликах, пришедших в заметку, а не
  в ответ кому-то (7 на заметку против 58).
  **Корней два сорта, и оба оказались вымеримы** — вопреки тому, что стояло в
  коде полгода («видно, куда человек пришёл, и не видно, что он пролистал»).
  ПОВТОРНЫЙ заход (`archive.MineRootRate`) — человек уже говорил в треде и
  вернулся начать новую ветку: у живых это 40 % ВСЕХ корней (583 корня от 393
  человек на десяти тредах), а в позднем треде 2026 года больше половины.
  Знаменатель у него тот же, что у отклика: каждая чужая реплика после первого
  своего слова — возможность. В кубике этого не было вовсе, «прийти в заметку»
  бросалось РОВНО ОДИН РАЗ за её жизнь, и тридцать жителей не могли дать больше
  двадцати девяти корней ни при какой вероятности. ПЕРВЫЙ заход
  (`archive.MineComeRate`) меряется, если сменить вопрос: присутствие человека
  на сайте доказывается его же репликой ГДЕ УГОДНО, значит «был в тот день и в
  эту заметку не зашёл» — наблюдаемый промах. Живые открывают **14 %** заметок
  своего дня (по составу 4,5–29 %, мера личная, как разговорчивость), а в ОДНУ
  заметку заходит **35 %** всех, кто был в тот день на сайте, — две меры одного
  поведения при разной плотности заметок, и в кубик они идут вместе (см. ниже).
  **Замер отнял объём, и это правильный итог** — но не там, где сперва
  показалось. Личная доля «открываю 14 % заметок своего дня» дала серию 497
  реплик против 892 на выдумке 0,35, и первое объяснение («0,35 угадано по
  конфликтным заметкам») оказалось неверным: живая заметка от мёртвой по этой
  мере почти не отличается — за тринадцать лет 97 % заметок набирают двадцать
  реплик. Настоящая причина — ПЛОТНОСТЬ: личная доля мерилась там, где в день
  выходило 8–28 заметок и внимание делилось между ними, а у нашей площадки
  заметка одна. Поэтому в кубик идёт не она, а `ComeBase` × личная ÷
  `ComeTypical` — доля присутствующих, заходящих в ОДНУ заметку (0,35, замер по
  200 живым тредам), помноженная на то, насколько этот человек заходчивее
  типичного (0,141, замер по 90 донорам, размах 0,045–0,292). Смешивается у
  композита СЫРАЯ доля: собранный из уже переведённых, житель получал перевод
  второй раз, и весь состав упирался в потолок вероятности (поймано в тот же
  день, 50 % личной доли при донорских двадцати).
  **Форма сошлась**: разрастание 0,80 против 0,82 у живых, кривая тормоза
  впервые той же формы — 1,16 → 1,34 → 1,07 → 0,90 → 0,74 против
  2,00 → 1,90 → 1,19 → 1,09 → 0,83, все пятьдесят тредов кончаются тишиной. За
  серию 938 реплик против 3276 у оригинала (медиана треда 107 против 283) —
  то есть треть объёма при четверти народу: живых в те сутки на сайте было 121,
  наших тридцать. Цена в жителях замерена, а не выведена прямой: 10 жителей —
  15 реплик за серию и разрастание 0,45; 20 — 115 и 0,77; 30 — 938 и 0,80.
  Дальше тридцати замера нет, и продолжать эту кривую на глаз нельзя — ровно на
  этом уже обожглись 29.08.2026.
  **Разгона от размера треда НЕТ, и это замер, а не догадка.** Проверялось
  прямое подозрение: живой тред разгоняется (2,00 → 1,90 → 1,19), значит в
  растущую заметку должны сбегаться новые люди. По 200 тредам вышло обратное —
  доля ещё не зашедших, входящих на очередном такте, ПАДАЕТ монотонно: ×1,00 у
  первой реплики, ×0,32 к тридцатой, ×0,12 после сто двадцатой. Люди приходят
  в начале и дальше только отвечают. Значит бутстрапа «стало людно — набежали
  ещё» в природе нет, и строить его не надо.
  **Потолок реплик — предохранитель, а не мерка**: прежние 60 обрывали 24 треда
  из 50, а оборванный тред врёт и про объём, и про то, чем разговор кончился.
  Умолчание поднято до 400 (у самых длинных заметок замера 728), и после этого
  все пятьдесят тредов кончились сами.
  **РАЗГОВОР СТРУКТУРНО РАЗНОПОЛЫЙ, и это замер** (`ReplyRate.ToMale/ToFemale`,
  300 тыс. рёбер, 29.08.2026): наблюдённое против случайного выбора адресата —
  мужчина женщине ×1,36, женщина мужчине ×1,31, женщина женщине ×0,82, а
  мужчина мужчине **×0,47**, то есть вдвое реже случайного и почти втрое реже,
  чем тот же мужчина отвечает женщине. Кубик о поле не знал вовсе и выбирал
  собеседника вслепую. Пол в архиве снят у 801 анкеты, но они дают 91 % всех
  реплик, — мерить есть на чём. После правки разговор у нас идёт разнополым в
  63 % пар против 52 % при случайных (у живых сильнее: мужчина мужчине выходит
  ×0,85 вместо ×0,47). Величина эта не только про вежливость: у живых
  сцепившаяся пара чаще разнополая, значит и подтекст, и «мужчины с женщинами
  друг друга не понимают» — среда ссоры, а не украшение поверх неё.
  **Сцепку пары строить НЕ НАДО — она уже в кубике.** Замер (те же 1500 тредов)
  говорит, что вероятность продолжить обмен не затухает вовсе: 55 % после
  первого, 54 % после третьего, 58 % после восьмого, 56 % после десятого
  (глубже видно не будет — цепочки упираются в предел глубины дерева у
  источника). Но это ровно то, что уже меряет `Rate(pos, toHim=true)`, — 39–91 %
  по донорам, — и наши треды дают цепочки в 21–22 реплики против оригинальных.
  Правило «величину, которую собираются править, сперва спрашивают у прогона»
  сберегло здесь целый рычаг-дубль.
  **Приток новых людей от размера треда НЕ РАСТЁТ** (200 тредов): доля ещё не
  зашедших, входящих на очередном такте, падает монотонно — ×1,00 у первой
  реплики, ×0,32 к тридцатой, ×0,12 после сто двадцатой. Живой тред разгоняется
  не притоком, а тем, что пришедших сразу много.
  **Пересъём карточек параллельностью НЕ УСКОРЯЕТСЯ** (замер 29.08.2026): восемь
  слепков в один поток 75 с, в восемь потоков 76 с. Упирается он в одну базу
  SQLite, а не в ядра; ключ `-j` у `narod card` оставлен ради счётчика на долгом
  пересъёме. И отдельная грабля оттуда же: **второй запрос при открытом курсоре**
  берёт из пула новое соединение, а оно открывает базу на 4,7 ГБ заново, —
  замер карточки от такой вложенности вырос с десяти секунд до девяти минут.
  **Потолок реплик на тред виноватым не был** (проверено 29.08.2026 перед тем,

  Величина, которую собираются править, сперва спрашивается у прогона.
  **РАЗГОВОР УХОДИТ ОТ ЛЮДЕЙ К ПРЕДМЕТАМ, и это замерено** (первая боевая
  песочница, 29.08.2026): 43 % реплик треда оказались про ГАРАЖ, к слову
  помянутый в заметке, а про людей и отношения говорили 11 % против **15,9 %**
  в архиве (10,8 млн реплик, треды от двадцати). Механика неизбежная и не
  зависит от промпта: в окно идут последние двадцать реплик, у каждого жителя
  своё ремесло, и первый, кто подхватил предмет заметки своим ремеслом, задаёт
  тему всем следующим — окно само себя подкрепляет. Заметка в промпте была, но
  двадцать реплик про гараж её перевешивали. Лечится ЯКОРЕМ в задании
  («разговор про ЛЮДЕЙ из заметки, своё ремесло — доводом, а не новой темой»), и
  лечит он только ВПЕРЁД: тред, уже ушедший в предмет, якорь назад не вытащит.
  **ВБРОС на весь пол — РЕДКИЙ УДАР, а не фон** (`generalizeLine`, замер по тем
  же 10,8 млн): прямое обобщение («все бабы», «женская логика») стоит в 0,198 %
  реплик, то есть в одной из 504; в тредах, где оно звучит хоть раз, — в одной
  из 208, и таких тредов 30 % от всех длиннее двадцати. Ожидание «сайт знакомств
  полон таких реплик» замер опроверг. Граница метода названа: невод ловит
  ЗАУЧЕННУЮ ФОРМУЛУ, а не поведение, поэтому 0,198 % — это ПОЛ, а не потолок, и
  поднимать `GeneralizeRate` выше замера значит принимать авторское решение, а
  не уточнять замер.
  **ПРИЁМЫ ПОДАЮТСЯ ПО ОДНОМУ, а не списком** — оплачено там же: `jabsLine`
  перечисляла четыре формы пассивной агрессии, и модель делала ПЕРВУЮ каждый раз.
  «Насмешливый комплимент сразу после возражения» стоял в конце 20 % реплик
  («Умный вы)», «Наблюдательная», «Догадливая вы)»), вторым пунктом шло
  уменьшительное от имени — и оно было всюду (Севушка, Валечка, Рябинка). Два
  приёма, названные первыми, стали подписью машины. Правило общее с длиной и
  эмодзи: величина, живущая МЕЖДУ репликами, назначается ЖРЕБИЕМ на реплику, —
  список модель читает как рецепт и исполняет весь прогон разом.
  **ПОВЕРХНОСТЬ РЕЧИ ВЫДАЁТ МАШИНУ РАНЬШЕ СОДЕРЖАНИЯ, и замер на неё был, а
  применения не было** (`narod.ApplyRegister`, 30.08.2026). Сравнение первой
  песочницы с живым тредом на ту же тему (257665, 363 реплики): длину калибровка
  выправила (медиана 61 против 66), а поверхность разошлась вся — многоточия 0 %
  против 28,9 %, «)))» 0 % против 14,3 %, РОВНО ОДНА «)» 76,6 % против 16,3 %,
  коды смайлов 0 % против 10,2 %, строчная в начале 0 % против 11,8 %, больше
  одной фразы 84,4 % против 22,0 %. Причина не в замере: `ParenRuns`,
  `StartsLower`, `AllLower`, `NoFinalPunct`, `SmileyRate`, `Smileys` лежали в
  карточке с самого начала — но уходили в промпт ОПИСАНИЕМ («точку в конце не
  ставишь в 75 % реплик»), а описание модель не исполняет: у Механика Севы
  замерено 75 % реплик без точки, и он написал с точками все до одной. Третий
  раз один и тот же урок (длина, эмодзи, теперь поверхность): величина, живущая
  МЕЖДУ репликами, ставится не просьбой, а КОДОМ после генерации, рядом с
  `InjectErrors` и по одному с ним доводу — у человека это не решение, а привычка.
  Три грабли внутри самой правки, все оплаченные боем: постпроцессор,
  умеющий только УРЕЗАТЬ хвост скобок, недодаёт ровно настолько, насколько скупа
  модель (8,8 % при замеренных 32 %) — бросок делается всегда; многоточие,
  цеплявшееся за точку в конце, не появлялось вовсе, потому что модель кончает
  реплику словом; а ОДНОСТОРОННИЙ жребий («пиши одной фразой», иначе молчим) дал
  97 % однофразовых при замеренных 76 % — где инструкции нет, модель делает то
  же, что делала, и умолчание оказывается сильнее жребия, поэтому называются ОБА
  исхода. Смайл дописывается В ОБЁРТКЕ `:::код:::`: в карточке лежит имя, а голое
  английское слово посреди русской реплики выдаёт машину сильнее, чем отсутствие
  смайла. После правок поверхность сошлась (многоточие 30,8 % против 25,9 %,
  одиночная скобка 23,1 % против 21,3 %, строчная 15,4 % против 15,9 %), а НЕ
  сошлись пока вопрос (0 % против 20,7 %), обращение по нику и коды смайлов.
  **След разговора — ЛЕТОПИСЕЦ** (`narod.Chronicle`): тред кончился, модель его
  читает и говорит, что он изменил между людьми. Единственное место эпика, где
  она судит не о ТЕКСТЕ, а о ЛЮДЯХ, — и границы её власти держит код, а не
  просьба в промпте: шкала двигается ДЕЛЬТОЙ с потолком (`MaxDelta` = 2 при
  шкале 10, то есть до вражды надо поссориться пять раз), вид эпизода из
  ЗАКРЫТОГО списка ядра (иначе через десяток тредов заведётся «взаимное уважение
  с оттенком иронии» и сравнивать миры станет нечем), имена разрешаются по
  участникам треда, ссылки на реплики — по самому треду. Модели остаются ЗНАК и
  ПОВОД: ровно то, чего нет ни в одном замере. **ЗНАКОМСТВО она не трогает
  вовсе** — счётчик встреч СЧИТАЕТСЯ по треду, и потому копится даже в
  бесплатном прогоне, где слов нет; отсюда деление, повторяющее принятое для
  голоса: бесплатные зёрна меряют кубик, первое зерно — мир.
  Обратный ход — **память** (`narod.WriteMemory`): отношения возвращаются в
  реплику блоком «что ты помнишь». **Чисел в нём нет намеренно** — скажи модели
  «симпатия 6.2 из 10», и она начнёт писать о шкале; человек помнит СЛУЧАЙ и
  говорит исходя из него, ни разу его не назвав. Свёртка старых эпизодов
  (`CompactEpisodes`, потолок `EpisodeCap` = 12) ничего не стирает, а ПОМЕЧАЕТ:
  в промпт идут последние, свидетельство остаётся в таблице; выжимку пишет КОД
  («сцепились 4, поддел 3 — с марта по май»), потому что модель, пересказавшая
  дюжину поводов абзацем, через год дала бы воспоминание, которого не было ни в
  одном треде.
  **Внутренние события** (`narod.InnerTick`) — жизнь СНАРУЖИ: без них у
  персонажа нет ничего, кроме реакций на чужие заметки. Бросок на день —
  формула (Бернулли, ключ «зерно, житель, день»), даром и повторяемо; текст
  пишет модель; запрет говорить про площадку стоит проверкой в КОДЕ, а не
  просьбой. Частота (`InnerMeanDays` = 5) НЕ замерена и названа таковой: в
  архиве видно, что человек написал, и не видно, что с ним было.
  **Отношение — единственный рычаг кубика без своего замера**, и потому у него
  заимствованный потолок: размах равен ЗАМЕРЕННОМУ размаху знакомства
  (`ReplyRate.FamiliarSpan`) — знакомство есть тот же след отношения, только
  доступный счёту, — а модель называет одно направление. Работает он мимо
  прямого обращения, там же, где знакомство: на прямое обращение человек
  отвечает и нелюбимому.
  **Непригодная полоса больше не отменяет прогон целиком** (правлено 28.08.2026
  по живому случаю: у «Инженера Шурика 54» слой не узнаёт и настоящие тексты
  автора — медиана места 5243 из 9361, и таких в составе трое из двенадцати).
  Вопросы разные: «похож ли текст на донора» и «двинулся ли мир», и первый,
  оставшись без ответа, второго не отменяет. Чего нельзя по-прежнему — печатать
  вместо ответа ноль: причина едет в отчёт и встаёт ВМЕСТО чисел, а прогон
  отменяется, только если мерить нечем ни у кого.
  **ТОКСИЧНОСТЬ — авторские решения, а не замеры** (владелец, 29.08.2026, повод:
  разговор у нас «рафинированный»). Названы они вслух таковыми, потому что
  замера ни у одной из четырёх величин нет и быть не может, а соседние рычаги
  кубика замерены — путать их нельзя. Первое: `relationLift` РАЗВЁРНУТ. До этого
  дня при отрицательном тоне житель влезал в разговор неприятного ему человека
  РЕЖЕ — то есть в кубике стояла машина, гасящая ссоры, и мир выходил
  рафинированным при любом промпте. Теперь минимум рычага у РАВНОДУШИЯ, а
  неприязнь тянет СИЛЬНЕЕ симпатии: вражда берёт полный замеренный размах
  (`FamiliarSpan`), приязнь — его корень, и второго придуманного числа рядом с
  первым не заводится. Второе: НАКАЛ ПАРЫ внутри треда — счётчик обменов, код,
  даром; в кубик он НЕ идёт (продолжение обмена замерено плоским, 55 % после
  первого и 56 % после десятого, и уже сидит в `Rate(pos, toHim)`, а вход третьих
  лиц в горячий тред замерен отдельно), зато идёт в промпт лестницей эскалации:
  тема → собеседник → диагноз → категория людей → «замолчи». Третье: ФРУСТРАЦИЯ
  (`Bio.Frustration`) из ЗАКРЫТОГО списка семи видов — закрытого по доводу
  `EpisodeKinds`: свободная строка через десяток жителей даёт «лёгкую грусть по
  несбывшемуся», и сравнивать миры становится нечем. Пишет её владелец в
  рецепте, рядом с ником и биографией. Четвёртое: РЕГИСТР — сексуальный подтекст
  всем, а мерой служит сама пара (рычаг ложится на замеренную разнополость), плюс
  формы пассивной агрессии описанием. **Мат жителям ЗАПРЕЩЁН** (решение
  владельца), и довод арифметический: `platmod` гасит `CatProfanity` сам, по
  словарю корней, — значит реплика с матом это оплаченная генерация, снятая со
  страницы, и дыра в треде на её месте. Словарь ради этого вынесен в листовой
  пакет `profanity`, общий автомату (СУДИТЬ) и народу (НЕ ПИСАТЬ): два словаря
  мата, расходящиеся молча, дали бы площадку, где запрещено не то, что гасится.
  Живёт всё это ТРЕТЬИМ блоком промпта (`narod.WriteMood`) рядом с карточкой и
  памятью, и подаётся ПОСЛЕ треда: настроение складывается из прочитанного, а
  поданное до него становится заданным тоном. Чисел в блоке нет по тому же
  правилу, что в памяти. И граница, важнее прочего: приёмы сняты с живого треда
  площадки, но ДОСЛОВНЫХ цитат оттуда нет ни одной — живой текст участника в
  промпте к Claude запрещён опубликованным согласием.
  **СПЛЕТНИ** — не новая механика, а недостающий выход у старой: эпизоды копились
  с начала мира, но в промпт шли только про тех, кто в треде, и «а помнишь, что
  она в прошлый раз выдала» сказать было некому. `World.Gossip` пускает туда один
  случай про ОТСУТСТВУЮЩЕГО, отдельным разделом: говорить о человеке при нём и за
  глаза — разное поведение, и модель обязана видеть, кто из них кто.
  **Проверить правку кубика бесплатным прогоном НЕЛЬЗЯ**, и это свойство самого
  рычага: тон берётся из графа, граф двигает летописец, летописец читает СЛОВА, а
  без `-speak` слов нет — все тона нули, и `relationLift` возвращает единицу.
  Прогон 29.08.2026 после правки дал 805 реплик и разрастание 0,79, то есть
  базлайн байт в байт; это не «правка не сработала», а «мерить было нечем».
- **Этап 4 — площадка и песочница** (эпик «народ»): жители выходят на t3h.ru.
  Миграция **0018** заводит два boolean'а, и оба намеренно НЕ новые виды:
  `users.persona` («реплики автора пишет машина») и `notes.stage` («в этой
  заметке говорят жители»). Правило песочницы собрано в ОДНУ функцию ядра
  (`platform.stageGuard`) и держит обе стороны: в песочницу пишут только житель и
  АДМИНИСТРАТОР (модератору нельзя — он решает про слова, а не участвует), и
  житель пишет ТОЛЬКО в песочнице. Вторая половина и есть та, ради которой всё
  собрано вместе: благодаря ей «машинная реплика» и «песочница» перестают быть
  разными вопросами, и `platout`, `platdigest` и шина вправе спрашивать про ОДНУ
  заметку вместо join'а к `users` на 10,7 млн комментариев. Разблокировка для
  аудитории — снятие ПЕРВОЙ половины, вторая остаётся.
  **Согласий житель не подписывает** (`consentGuard`, первая строка): согласие
  даёт СУБЪЕКТ, у персонажа персональных данных нет, а строка от его имени в
  `consents` была бы записью о согласии, которого никто не давал, — то есть
  подделкой ровно там, где площадка обязана быть безупречной. Право писать даёт
  ПРИЗНАК, введённый оператором сознательно, и отвечает за сказанное оператор.
  В очередь модерации реплики жителей идут наравне со всеми: молчаливое
  исключение означало бы автора, которого никто не проверяет.
  Наружу из песочницы не уходит ничего — ни в каналы (`platout`, два условия:
  `NOT n.stage` держит саму песочницу, `NOT u.persona` остаётся страховкой на
  будущее открытие), ни в выпуск (`platdigest`, восемь запросов, одно условие
  `notStageNote`/`notStageComment`), ни поводами (`fanOut`: жителю их некому
  читать, а служба узнаёт о новом своим курсором).
  На странице песочница — **третий значок происхождения** (микросхема, не
  театральная маска: маска означала бы притворство живого), и он СИЛЬНЕЕ «своей»
  заметки: обе написаны здесь, но у песочницы к этому добавлено единственное, что
  читателю нужно знать заранее, — ответить в ней он не сможет. Вместо формы стоит
  объяснение со ссылкой на `/help#narod`, и стоит оно ВЫШЕ проверки «вошёл ли»:
  гостю «войдите, чтобы ответить» было бы неправдой. Раздел справки говорит, что
  реплики жителей пишет машина, и НЕ называет имён: список из десяти ников
  устареет через неделю, а значок у заметки не устареет. Правило показа считается
  одной функцией `web.canWriteIn` на все три места (страница, форма без
  перезагрузки, живой добор) — иначе кнопка однажды ответит отказом.
  **ЛИЦО ЖИТЕЛЮ РИСУЮТ ПО ПРОМПТУ** (`narod portrait [<слуг>…]`, 30.08.2026):

  прогон по боевым карточкам дал три огреха разом («Plain a soft off-white
  background», развилка «his or her age», строчная буква после точки), и все три
  родились на стыке кода и таблицы.

  перекладывается в Postgres** — `narod.PublicBio` собирает её из рецепта, и
  повторный enroll теперь осмыслен ровно этим: правку карточки надо донести до
  страницы. Живёт она колонкой `users.bio` (миграция **0019**), а не читается из
  файла, потому что рисует страницу ВЕБ-МОРДА, а карточки лежат рядом с демоном.

  `persona`. Во внешнюю биографию НЕ идёт `frustration` — это рычаг кубика, а не
  факт о человеке, и напечатанный он превратил бы характер в приложенную к нему
  инструкцию), `narod seed
  -body <файл|-> | -from <id архивной заметки>` — завести песочницу от имени
  администратора. Песочницей становится и та заметка, что УЖЕ лежит в ленте
  (`narod stage -id <номер> [-off]`, ядро — `platform.SetNoteStageAsAdmin`):
  материал для сцены чаще всего уже написан, а копия его текста новой записью
  означала бы тот же текст дважды в одной ленте. Дверь администраторская (кто
  здесь вправе ГОВОРИТЬ — вопрос ролей, а не слов), а главное — **только пока в
  заметке никто не сказал ни слова**, в обе стороны:
  вперёд правило бережёт участников живого треда (после перевода они остались бы
  заперты в разговоре, который сами вели), назад — обещание «наружу из песочницы
  не уходит ничего». Открытие песочницы аудитории этой командой НЕ делается.

  временем заполнить старые заметки и те, что удаляют без дискуссии»). Стояло

  половины довода уже держит правило тишины: заметку с репликами перевести
  нельзя, а пустой зеркальный тред не наполняет никто, комментариев НГС не
  принимает с 17.08.2026. Старая запись без единой реплики и есть готовая сцена:
  текст написал живой человек, разговора под ним не случилось. Копию признак при
  этом НЕ ПРАВИТ — текст, автор и дата остаются как были, меняется только то, кто
  вправе говорить ЗДЕСЬ, поэтому `ErrNotNative` от правки чужого текста сюда не
  переносится. Остаточный риск назван вслух: оживи НГС и напиши кто-нибудь в
  такую заметку — зеркало принесёт его реплику (приём идёт мимо `stageGuard` и
  должен идти мимо: вставшая очередь зеркала хуже смешанного треда).
  **Руками это делается ГАЛОЧКОЙ на форме правки** (`/n/<id>/edit`,
  администратор): она стоит рядом с той же галочкой у новой заметки и
  показывается, только пока `CommentCount` равен нулю — кнопки, отвечающей
  отказом, не рисуем. Признак идёт в ядро ТРЕТЬИМ отдельным вызовом, после текста
  и картинки, по тому же доводу, что и они: своя дверь, свой отказ, своя запись в
  журнале, — и последним, потому что решает не про текст. Счётчик считает
  ВИДИМОЕ, а ядро все реплики подряд, поэтому у заметки с единственной скрытой
  репликой галочка покажется и ответит отказом; размен принят в пользу
  отсутствующего запроса «а есть ли скрытые» на каждой форме правки.
  **Новая песочница заводится ГАЛОЧКОЙ на форме заметки** (30.08.2026, просьба

  своё.

  (правлено 29.08.2026 на первой же боевой песочнице: заметку перевели из ленты,
  где она пролежала сутки, и служба объявила тред затихшим через минуту после
  запуска — при `thread_close_h` = 12 такой тред мёртв с рождения; у свежей
  `narod seed` оба времени совпадают, поэтому иначе дефект не всплыл бы). Затихший
  тред возвращает в живые `narod wake -id <номер>`: затухание это ЗАМЕР, а не
  приговор, и песочница вдобавок СТЕНД — часы при оживлении заводятся ЗАНОВО, а
  броски прошлой жизни треда остаются на месте (ключ монетки — событие, а не
  заход). Служба — `narod.Service` (`setupNarod`), два такта: СМОТР
  (что нового на сцене → монетка каждому жителю ровно раз → план с отложенным
  сроком) и РАБОТА (созревший план → генерация → реплика). Новое спрашивается
  ТАКТОМ, а не живым каналом: задержка ответа у жителей замерена минутами, и
  полминуты теряются внутри неё целиком. Режима два: `live` и `dry-run`, где мир
  движется целиком, а на площадку не уходит ни строки. Тумблер — `/narod` в ЛС
  (админская, в меню команд не значится; подтверждения у включения нет, в отличие
  от амвона: предохранителя у народа нет вовсе).
- Площадка (`platform`, эпик E): `platform migrate` накатывает схему Postgres
  (отдельной командой, а не стартом сервера — схему меняет админ в известный
  момент), `platform doctor` показывает пул, версию схемы, настройки Postgres,

  Безопасна при работающем демоне (приём идемпотентен по id, SQLite только

  живой поток (зеркало приносит медиа скачанными), но у строк бэкфилла есть

  17.08.2026 НГС восстановился, но комментировать так и не разрешил. **Окно
  закрывается вместе с сайтом**: пока hsmedia.ru отдаёт файлы, их надо забрать.

- Добор восстановленного (`platform import-restored -archive archive.db`, тот же

- Настоящее дерево ответов и пол участников:
  `go run ./cmd/lovegw platform reply-scan [-limit N] [-note ID]`. Живое зеркало
  знает адресата только по обращению «Ник, …» и разрешает его в ПОСЛЕДНЮЮ
  реплику этого человека — угадывание примерно с половинной точностью, и на
  странице это видно как ветка, выросшая не там (замер: в заметке 313000
  переставлено 187 рёбер из 444). Настоящее ребро отдаёт МОБИЛЬНАЯ версия
  (`love.FetchNoteReplyTree`, 92 %), пол — ДЕСКТОПНАЯ страница комментариев
  (`love.ParseGenders`; в мобильной пола нет вовсе). Отсюда два запроса на
  заметку — но обход анкет не нужен вовсе. Отказ сайта на заметке обход не
  рвёт, три подряд гасят её насовсем (`ingest_state.reply_scan_skip`). **Окно
  закрывается вместе с сайтом.**
  Очередей **две, и они разной природы**. Командой ходит очередь ДОБОРА
  ИСТОРИИ («сперва не смотренные, дальше самые давние»): это тысячи запросов, и
  когда их тратить, решает админ. За ЖИВЫМИ тредами ходит сам демон
  (`platsink.ReplyScanner.Run`, такт минуту, три заметки за проход): очередь
  `ReplyScanFresh` — «дописали после прошлого обхода», окно суток, не чаще раза
  в пять минут по одной заметке. Заведена 23.08.2026 по жалобе владельца: пока
  НГС не принимал комментариев, разовый обход был достаточен, а с возвращением
  комментариев заметку из исторической очереди смотрят ОДИН раз — и всё
  дописанное потом остаётся с угаданными рёбрами навсегда (до второго круга по
  117 тысячам заметок дело не дойдёт никогда). Вход по индексу
  `notes_fresh_scan` (миграция 0013). Переставленное ребро с 23.08.2026 доходит
  и до ОТКРЫТЫХ страниц: правка помечает строку `comments.moved_at`, и живой
  добор досылает её тем, у кого она нарисована на старом месте (миграция 0015,
  «переезды» в разделе про `web`).
  С 27.08.2026 у живой очереди есть **третий вход — подсказка приёмника**
  (`ReplyScanner.Nudge`, зовёт `platsink.Sink.PostComment`): очередь ходит ПО
  СЛЕДАМ («в заметке дописали»), а подсказка приходит в тот самый момент, когда
  догадка об адресате появилась, и потому дешевле — обойти надо ОДНУ названную
  заметку, а не перебирать живые. Такт 5 с, не чаще раза в 30 с по заметке (это
  такт самого зеркала у живой заметки — чаще, чем оно туда ходит, заглядывать
  незачем), и берётся ТОЛЬКО дерево: пол меняется раз в жизни и приезжает общей
  очередью, второй запрос стоил бы вдвое и не дал бы ничего. Отметку
  `reply_scan_at` подсказка не ставит — сбив общей очереди отсчёт, мы отложили
  бы пол ровно на то время, пока тред горячий. Заведена потому, что пять минут
  в чужой ветке — это не «немного неточно»: реплику всё это время читают, а
  потом она переезжает у читателя на глазах. Дважды подряд отказавшая заметка
  подсказок больше не слушается (500 сайт отдаёт устойчиво и как раз на самых
  длинных тредах); дальше её судьбу решает общая очередь, где счётчик неудач
  живёт в базе.

- Вход на площадку (Ш4): человек называет номер анкеты НГС и получает
  одноразовый код `T3H-XXXX-XXXX`. **Каналов доставки два, и различаются они не
  удобством, а способом проверки.** Основной — **личное сообщение на НГС** от
  служебного аккаунта (`internal/acct`, имя в `platform.site_account`, пусто —
  первый живой): читать его может только владелец ящика, поэтому достаточно
  переписать код обратно в форму. Запасной — **код в поле «о себе»**: он
  показывается на экране, человек вставляет его в анкету, мы читаем её анонимно,
  и проверка становится ДВУСТОРОННЕЙ (кода в публичной анкете мало — нужна ещё
  кука того, кто проверку начал). Отсюда правило, которое нельзя нарушать:
  показанный на экране код нельзя принимать введённым обратно, иначе вход под
  чужой анкетой стоит одного нажатия. Запасным «о себе» стал 18.08.2026 —
  правка этого поля уходит на **модерацию НГС**, и одобряют её не сразу и не
  наверняка. Адрес лички — `passport_id` из той же мобильной анкеты (не номер
  анкеты!). Нет живого служебного аккаунта — канал молча недоступен, вход идёт
  запасным путём; отправку ограничивает потолок (не чаще раза в 3 минуты, 3 на
  анкету), потому что вход начинает кто угодно, а сообщение получает настоящий
  владелец. Третий путь — приглашение, и выдаётся оно **со страницы**
  `/mod/admin` («Администрирование» в меню участника, только у администратора;
  24.08.2026 — просьба владельца не ходить ради этого в консоль на бою): номер
  участника, срок, пометка себе — и код показывается ОДИН раз тут же, вместе с
  тем, кому он выдан, и адресом `/login/invite`. Ошибку видно на месте и
  отзывает её кнопка «Отозвать» (строка называется временем выдачи: своего
  идентификатора у приглашения нет, а хеш кода показывать нельзя — по нему код
  подбирается перебором). Консольный путь остаётся ради одного случая —
  первого приглашения там, где администратора ещё нет вовсе:
  `go run ./cmd/lovegw platform invite [-bind <user_id>] [-days N]`. `-bind`
  привязывает пришедшего к уже существующей тени, и весь его зеркальный след
  становится своим; привязка к УЧАСТНИКУ (тому, кто уже входил) не запрещена —
  это способ вернуть доступ потерявшему анкету, — но страница про это
  предупреждает, потому что код открывает живую учётную запись. Выдача и отзыв
  пишутся в `audit_log` обоими путями (у консольного актор пуст, как у первого
  назначения администратора), кода в журнале нет. Права —
  `platform role <user_id> user|moderator|admin` (первого администратора
  назначить больше неоткуда). Тексты согласий публикует `platform migrate`.
- Объявление площадки: `go run ./cmd/lovegw platform post -body <файл|-> [-pin]

  наверху ленты. Форму на странице команда не заменяет: объявление пишет тот,
  кто выкатывает, с рабочей машины, где сессии участника нет. Текст только
  файлом или со stdin — в объявлении переносы строк и кавычки, командная строка
  их калечит. Идёт всё через ядро (право писать, потолок частоты, очередь

  форме — включая то, что `platout` отнесёт её в каналы мессенджеров.
- Запись на площадке (Ш5): **участник только пишет**. Заметка (в т.ч. анонимная)
  и ответ в любую точку дерева — **у комментария анонимности нет вовсе** (её нет
  и на НГС: заметку анонимно публикуют, а в треде анонимно отвечали бы людям,
  которые ответить тем же не могут; держится отсутствием поля у `NewComment`); удаление — у модератора, и единственное
  исключение — своя заметка первые 10 минут, ОДИН раз и только пока под ней нет
  ответов (`platform.EditWindow`, `NoteView.Editable` — одно правило на ядро и на
  страницу, иначе кнопка отвечала бы отказом). Причина не в экономии: тред это
  чужие ответы на твои слова. **Чужой текст меняет только АДМИНИСТРАТОР**
  (`platform.EditNoteAsAdmin`, 25.08.2026, та же форма по адресу
  `/n/<id>/edit`), и дверь у правки выше модераторской не по важности:
  скрытие ничего не подменяет и отменяется нажатием, а правка кладёт другие
  слова под чужое имя, и со стороны заметить её нечем — модератор решает про
  СЛОВА (убрать их из разговора), переписать сказанное ближе к тому, чем ведает
  администратор. Понадобилась она потому, что у площадки есть СВОИ заметки —
  объявления (`platform post`) и выпуск дайджеста, — а опечатку в них авторское
  окно не спасает: их читают часами. Правится только НАТИВНАЯ (`ErrNotNative`:
  зеркальная — копия страницы НГС, и молча разойтись с оригиналом значило бы
  соврать читателю о том, что он читает копию), меняется ТОЛЬКО тело — автор и
  анонимность не редакторский вопрос, — а текст становится другим, поэтому
  карточка возвращается в `moderation_queue`, как при авторской правке.
  **Прежний текст не сохраняется НИГДЕ, включая журнал**: правят чужую заметку
  чаще всего затем, чтобы убрать из неё лишнее (чей-то телефон, адрес, имя), и
  копия убранного в append-only `audit_log`, открытом всем модераторам, сделала
  бы это удаление ненастоящим — в журнал идут факт (`ActionEdit`) и причина. На
  странице правка видна пометкой «исправлено» (метка НАША, на НГС правки не
  было, поэтому по правилу Ш5з она объясняет себя заголовком). Цена названа и в
  форме: копия, уехавшая в каналы мессенджеров, останется прежней — `platout`
  уносит заметку один раз и догонять её правкой не умеет.
  **КАРТИНКУ администратор ставит ЛЮБОЙ заметке, включая зеркальную**
  (`platform.SetNoteImageAsAdmin`, 27.08.2026, та же форма `/n/<id>/edit`), и
  это не послабление к правилу про текст, а другое действие с другим поводом: у
  копии с НГС иллюстрация хранится ССЫЛКОЙ на hsmedia.ru, и в день, когда сайт
  перестанет отдавать файлы, на её месте останется пустое место — восполнить его
  иначе нечем (своего файла площадка не принимает нигде, кроме формы новой
  заметки, а завести заметку заново значило бы потерять её тред). Текст копии при
  этом не правится по-прежнему: у зеркальной формы поля тела нет вовсе. А вот
  СНЯТЬ иллюстрацию у копии нельзя (`ErrNotNative`) — это уже расхождение с
  оригиналом, и вдобавок оно не удержалось бы: сверка `platsink` досылает
  недостающие по ЧИСЛУ СТРОК. Отсюда же устройство замены: у зеркальной заметки
  подменяются БАЙТЫ за существующей строкой (её ссылка остаётся ключом сверки, а
  читателю адрес всё равно собирается из sha256), у нативной строка меняется
  целиком. В `moderation_queue` заметка отсюда НЕ возвращается: файл выбрал сам
  администратор, и ставить его же решение себе в очередь значит проверять себя;
  в журнал идут `ActionImage` / `ActionImageOff` и причина. «Убрать своё ИМЯ» остаётся, но другим рычагом —
  отзывом согласия на распространение: он обезличивает заметки, оставляя их на
  виду (см. блок про `platform`). Своё и зеркальное живут в ОДНОМ треде: разделяет
  их полоса id, а человеку различие показывается на АВТОРЕ (тень против
  участника) в форме ответа — «дойдёт ли мой ответ», а не «откуда текст». Чужая
  отметка НГС «не актуальна» (`comments_closed`) писать НЕ запрещает — она стоит
  у 62 % заметок зеркала и в них 75 % всех комментариев; запирает тред только наш
  `notes.locked`. Частота: заметка 1/5 мин и 5/сутки, комментарий 1/10 с и
  30/час, считается по нативным публикациям (скрытые тоже, иначе «скрой и пиши
  заново»). Формы защищены скрытым полем `csrf`, выведенным из токена сессии
  (`web/csrf.go`) — своей куки не нужно, гаснет вместе с сессией. Публикация
  ставит строку в `moderation_queue` ТОЙ ЖЕ транзакцией: классификатор — Ш7, но
  «опубликовано, но в очередь не попало» не должно существовать.
- Watch moderation live: `go run ./cmd/lovegw modwatch [-db path] watch` — пишет в
  отдельную `modwatch.db` моменты, которых нет в архиве: заметка исчезла из ленты,
  комментарий исчез из треда, появилась иллюстрация, закрыли комментарии. Дальше
  `modwatch report` сверяет эти минуты с присутствием людей (кто писал рядом) и
  сравнивает с контрольными окнами того же часа суток; `modwatch events` —
  сырой список, `modwatch status` — наполнение БД, `modwatch bans` — окна
  суточных запретов, выведенные из ритма жертвы (кандидаты, не находки: слепой
  поиск не отличает запрет от обычной паузы, см. шапку `bans.go`),
  `modwatch guests watch|log` — визиты в СВОЮ анкету под своей сессией
  (`guests log -near "2026-08-12 19:38"` даёт список тех, кто заходил вокруг
  момента действия), `modwatch activity watch|scan|report|log` — присутствие
  людей на сайте, детектор запретов в «Заметки» (`activity report`: «молчит, но
  ходит» = закрыли, «молчит и не заходит» = ушёл; `activity log -near` — кто был
  на сайте вокруг момента действия, включая тех, кто ничего не писал). Время
  везде новосибирское, как на сайте. Сайт только читается, с работающим демоном
  всё совместимо (нужен RU-IP); боевую БД трогает лишь `activity` — и только на
  чтение реплик, чтобы набрать круг наблюдения (`-source`; ключ шифрования ему
  не нужен, сессий он не касается).
- Service site accounts (a second, technical profile: backup access for
  authenticated crawls and rare hand-made comments):
  `go run ./cmd/lovegw account login -name reserve` (логин/пароль со stdin),
  `account list|check|forget`, `account cookie -name reserve` (заголовок Cookie
  локальным скриптам — пишет только в пайп),
  `account say -name reserve -note <id> [-reply <comment_id>] "текст"` —
  комментарий на сайт с подтверждением; печатает id своей реплики. Живут в
  своей `accounts.db` (пакет `acct`), ботам не видны. `-account имя[,имя]` у
  `personas gender` — первый живой аккаунт из списка, это и есть резерв.
- Session cookies at rest: `go run ./cmd/lovegw secrets keygen` → ключ в
  `LOVEGW_SECRET_KEY` → `secrets encrypt` шифрует и `sessions`, и `accounts`
  (идемпотентно; `-old-key-env` — ротация), `secrets status` — что открыто, что
  зашифровано. **После шифрования ключ обязателен**: любая команда, открывающая
  боевую БД, падает, если записи не открываются (иначе демон молча выдал бы
  всем «сессия истекла»). Без ключа всё работает как раньше — куки лежат
  открыто.
- One-off import of legacy JSON state (notes / subscribers) into SQLite:
  `go run ./cmd/lovegw import ...` — idempotent (`INSERT OR IGNORE`).
- Windows: `start.bat` / `stop.bat` / `status.bat` / `restart.bat` launch/stop
  the daemon (write-through SQLite is crash-safe, so a hard kill is fine).
- CI/выкатка: `.github/workflows/ci.yml` — build/vet/тесты на каждый push и PR,
  плюс интеграционный набор `platform`/`platsink` против настоящего
  `postgres:18-alpine` сервисным контейнером (руками это требует ssh-туннеля к
  бою, поэтому гонялось редко). `deploy.yml` — выкатка КНОПКОЙ
  (`workflow_dispatch`): сборка бинарника у раннера, проверка «сертификатов
  Минцифры в бинарнике ровно 2», `gzip | ssh`, `Dockerfile.prebuilt`,
  `docker compose up -d platform`, healthz через Caddy и откат на `lovegw:prev`,
  если не ответил. Миграции роботом НЕ накатываются никогда — схему меняет
  админ в известный момент. Секреты (ssh-ключ с root, PEM'ы) — в окружении
  `production`, а не в репозитории: он публичный.
- Deploy: container image via `go/Dockerfile` (multi-stage, `CGO_ENABLED=0` →
  `distroless/static`, ~100 MB: a ~23 MB binary plus a static `ffmpeg` copied in
  for ASR; tzdata baked in via `time/tzdata`). `deploy/` has
  `docker-compose.yml` + systemd unit + runbook; config mounts as `/config.json`,
  state in `deploy/data` bind-mounted to `/data` (owned by uid 65532 — distroless
  runs as `nonroot`), secrets via env
  (`LOVEGW_MIRROR_TOKEN`/`LOVEGW_DM_TOKEN`/`LOVEGW_TG_PROXY`). Compose runs **four**
  services off one image: `lovegw` (the daemon), `modwatch` (the watcher, its
  own `data/modwatch.db`, site read-only), `guests` (визиты в анкету
  владельца: ходит под его сессией из `lovegw.db`, пишет в ту же
  `modwatch.db`) и `activity` (присутствие людей на сайте: круг берёт из
  `lovegw.db` только чтением реплик, ходит анонимно, пишет в `modwatch.db`).
  Границы ресурсов выставлены ОДНОЙ службе — веб-морде (`cpus`,
  `mem_limit`, `GOMEMLIMIT`, `pids_limit`): она единственная, до чего
  дотягивается посторонний. Порядок OOM задан явно — первой умирает морда,
  последними Postgres и демон. A named volume is only needed on a
  Windows host, where bind-mount corrupted the DB; on Linux the files sit on the
  host, which makes a backup a plain `sqlite3 .backup`. With MAX enabled, the
  Минцифры PEMs must be in `go/internal/maxx/cacert/` **before** the build — the
  distroless image carries no Russian root CA.
- Бэкапы (Ш8, с 18.08.2026) — `deploy/platform/backup.sh` кроном в 01:30 МСК:
  `pg_dump -Fc --compress=zstd:3` (5,4 ГБ базы → 760 МБ за 2,5 мин), три базы
  SQLite онлайновым backup API через `python3` (`sqlite3(1)` на хосте нет, а
  `cp` на живой базе даёт копию с разорванной транзакцией) и `tar` хранилища
  медиа; хранится 7 дампов, 14 снимков SQLite, 2 копии медиа. Восстановление
  отрепетировано: `deploy/platform/rehearse.sh` поднял всю базу в отдельную
  `platform_restore` за **423 с**, наполнение сошлось число в число. **Копия
  пока одна и лежит на том же хосте** — offsite (обязательно в РФ, ч. 5 ст. 18
  152-ФЗ) требует решения владельца, куда возить и кто держит ключ. Конфиги и
  `secrets.env` в автоматический бэкап НЕ входят намеренно: там
  `LOVEGW_SECRET_KEY`, и копия ключа рядом с копией базы обнуляет шифрование
  сессий, которое защищает ровно копии.
- `go run ./cmd/lovegw alert [текст…]` — сообщение владельцу в ЛС из внешнего
  скрипта (без аргументов текст читается со stdin). Заведено для бэкапа: он
  живёт в кроне на хосте, и его отказ иначе виден только тому, кто пойдёт читать
  лог. Шлёт во все включённые мессенджеры с заданным `admin_user_id`, порядок
  ботов тот же, что у алертов демона (переписка → команды → постер); успех — это
  «дошло хоть куда-то», но про недошедшее говорится в stderr.
- The site is behind DDoS-Guard geoblocking — non-RU IPs get 403, so crawl/run
  (and the deployed daemon) must run from a Russian IP. Telegram Bot API, blocked
  from inside Russia, is routed through a SOCKS5 proxy (`telegram_proxy`); the
  site stays direct.

## Architecture

- **Storage is SQLite** (`modernc.org/sqlite`, CGo-free) — the single source of
  truth; every write is write-through, so state survives `kill -9`. Schema in
  `internal/store/schema.sql`, versioned via `PRAGMA user_version` (migrations
  in `internal/store/migrate.go`). Since v4, message ids live in
  `message_targets` keyed by `(messenger, kind, ref_id)` with TEXT ids (MAX
  uses string mids); user tables carry a `messenger` column. Telegram values
  are mirrored write-through into the legacy `tg_*` columns for one release.
  Since v7 `subscriptions` is typed — `kind ∈ {keyword, author_notes,
  note_comments}` + `target` (word / `notes.author_id` / `notes.id`), row ids
  preserved across the migration because they live in the payload of «✖»
  buttons in users' chat history. `AddSubscription` enforces
  `SubscriptionLimit` (50 per user, all kinds together) inside a transaction —
  one place covers all four entry points. Since v8 `sessions` carries
  `talks_delivery` / `talks_asked_at` — в какой мессенджер носить личные
  сообщения (`internal/store/delivery.go`). Since v9 there are `pulpit_comments`
  / `pulpit_replies` (амвон, `internal/store/pulpit.go`; FK на `notes` у них
  намеренно нет — свой обход видит заметку раньше зеркала) и `settings` —
  рантайм-флаги вида `pulpit.enabled`: **только флаги, никогда секреты** (те
  живут в env и в шифрованных колонках `sessions`/`accounts`). Since v10
  `sessions.talks_scan` — согласие на чтение личной переписки; пустое значение
  означает «не читаем» (молчание согласием не считается), а миграция переносит в
  него прежнее явное `talks_delivery='on'` и снимает `talks_asked_at` у всех
  остальных — вопрос стал другим. Согласие — свойство сайт-аккаунта, поэтому
  пишется во все сессии паспорта, а читается как «хоть одна `on`»
  (`store.ScanAllowed`): вошедший позже в другом мессенджере получает строку со
  значением по умолчанию, и уже данное согласие от этого пропадать не должно.
  Since v11 — `morning_notes` (утренняя заметка, пакет `morning`): ключ ДЕНЬ, и
  в этом вся однократность — строка заводится `INSERT OR IGNORE`, поэтому
  отдельной проверки «а не публиковали ли уже» не нужно вовсе. FK на `notes`
  нет по той же причине, что у `pulpit_comments`: свою заметку мы видим в ленте
  раньше, чем её вставит зеркало.
- **All site markup selectors live in one const block** in
  `internal/love/parse.go`; a required selector that matches nothing returns a
  typed `MarkupError` (markup-drift detection), while an empty comments page is
  legitimately empty. The site's comment anchor id is `anchor-<n>`.
- Packages:
  - `love` — site client, parsers, auth, cookie sessions.
  - `store` — SQLite; the single source of truth.
  - `tgx` — go-telegram/bot wrapper: per-chat limiters, 429 retry, HTML compose,
    media `file_id` cache. Тело поста УКЛАДЫВАЕТСЯ в предел сообщения (шапка и
    подвал в бюджет заложены и не режутся): Telegram отвечает на длинный текст
    отказом, а очередь приёмника идёт по порядку и на отказе встаёт — заметка
    площадки (потолок тела 20 000 знаков) остановила бы канал насовсем.
  - `maxx` — MAX-side `Sink` over the official `maxbot` v2 SDK
    (`platform-api2.max.ru`): channel posting, manual "autoforward",
    reply-based comments, media upload with URL→token cache, per-chat limiters
    + 429 retry. TLS to MAX needs the Russian Trusted CA chain: official PEMs
    are `go:embed`-ded from `maxx/cacert/` when present at build time (see the
    README there), otherwise the host trust store is used. `updates.go` runs
    long polling (`GetUpdates(marker)`) and dispatches: discussion-chat
    replies → `bridge.Core`, dialog messages and button presses → `dmbot.Logic`.
    Нажатия (`message_callback`, ветка `dispatchCallback`): нажавшего берём из
    `callback.user` — в `update.user_id` SDK кладёт ПОЛУЧАТЕЛЯ сообщения, а
    `update.user` для этого типа не заполняет вовсе; пустой mid (сообщение
    удалили) — рабочий случай. Клавиатуры и правка сообщений — `keyboard.go`;
    снять одну клавиатуру, как `editMessageReplyMarkup`, в MAX нечем: и правка,
    и ответ на нажатие принимают тело сообщения целиком. The mirror bot
    always covers channel, discussion chat and DM commands; only the site's
    personal correspondence (talks) can move to a second bot via
    `messengers.max.talks_token` (the legacy `max.dm_token` is migrated to it
    on load).
  - `mirror` — feed watcher + one goroutine per active note with an adaptive
    poll interval; consumes a list of `Sink`s (fan-out: Telegram and MAX can
    mirror in parallel, each with its own thread per note via
    `message_targets`). A sink implementing `ThreadStarter` opens its own
    discussion thread (MAX has no native channel comments — the bot posts a
    copy of the note into the discussion chat itself). That call happens
    *before* the channel post so the «💬 Обсудить» button can deep-link to the
    note's branch (`maxx.MessageLink`: `https://max.ru/c/<chat_id>/<base64url
    of the mid's last 8 bytes>`); on failure it is retried every poll cycle and
    the button falls back to the chat invite link. The site's «не актуальна» mark is recorded in `comments_closed` as
    metadata only — it appears within minutes of publication while comments keep
    arriving, so it must never drive archival; notes are archived solely by the
    week-based `ShouldArchive` rule.
    **Заметку с ЗАПРЕЩЁННЫМИ комментариями лента не называет вовсе**
    (27.08.2026, заметка 313096, жалоба владельца «на НГС появилась, а к нам не
    зашла»): ссылку на тред сайт ей не рисует, а id заметки лежит ТОЛЬКО в этой
    ссылке — элемент остаётся с текстом, автором и датой, но безымянным, и
    прежний разбор молча его пропускал («заметку без id пропускаем»). Заметка не
    доходила ни в каналы, ни на площадку, и в логе о ней не было ни строки.
    Теперь безымянные считает сам парсер (`love.Feed.Unnamed`), а ИМЯ им даёт
    МОБИЛЬНАЯ лента (`love.ParseMobileFeedIDs`), где текст заметки сам по себе
    ссылка на неё и рисуется независимо от того, можно ли в тред писать; тело
    зеркало дочитывает обычной десктопной страницей треда, дальше заметка идёт
    наравне с остальными. Мобильную версию спрашивают не каждый обход, а на
    изменение ленты (`feedShape`): безымянная заметка висит в окне часами, и всё
    это время ответ тот же. Ниже нижнего края окна ленты зеркало не спускается —
    там уже не «сайт показал, а мы не увидели», а история. Не показала и
    мобильная — warn в лог с советом `pull <id>`: угадывать id по соседям
    нельзя, в ленте бывают дыры (в том же замере не было ни 313090, ни 313088).
    A mirrored comment is posted as a reply to
    its addressee's message, so the messenger renders the original as a quote:
    the addressee is the «Ник, …» prefix (`love.AddressPrefix`) resolved against
    the note's already-mirrored commenters — the site's own `parent_id` points at
    the branch root and agrees with the addressee only a third of the time.
    Правило выбора одно на всех (`love.Addressees`, им же живёт сверка

    второй половиной служит кука, выданная вместе с кодом. Вход не переносит ни
    строки: id строки равен id анкеты, тень завело зеркало, и вход — это UPDATE

    участники, ни на что не соглашавшиеся. **Согласий два** (`consent.go`),

    подставляются ДО публикации, а опубликованная редакция неизменяема:
    расхождение текста при том же номере версии — отказ `platform migrate`,
    потому что молча переписанный документ обесценивает все прежние согласия.

    нельзя было правкой трёх флагов, потому что оба документа обещали обратное, —
    выпущены `distribution.v2` и `processing.v3`, и прежние подписи перестали
    годиться (`Has` требует `Version >= version`). Отсюда же `publishGuard`:

    (`ErrConsentOutdated`), и стоит проверка в ЯДРЕ, а не в форме, — писать можно
    и из мессенджера, а второй список правил в `bridge` однажды разошёлся бы с
    этим. Реакция и жалоба через неё не идут намеренно: реакцию не видит никто,
    кроме счётчика, а жалоба — обращение к модератору, и требовать за неё
    подпись значило бы закрыть человеку жалобу на само изменение.

    миграция 0016): заметки человека переезжают на свежую безымянную
    анкету-«могилу» и остаются на виду, комментарии не трогаются вовсе
    (`anonymizeOwnNotes` в `rights.go`, той же транзакцией, что и сам отзыв).
    До этого дня отзыв уводил ВСЕ публикации в `StatusHiddenOwner` — и скрытая
    заметка уносила со страниц весь тред, то есть чужие ответы на чужие слова,
    ровно то, чем площадка обосновала «скрываем, а не удаляем» у модератора и
    «переносим, а не стираем» у обезличивания; отзыв был единственным
    исключением из общего правила. Вместе с рубильником ушли `users.hide_all`,
    `users.visibility_dirty`, порционный проход и его доводка в `platmod`:
    заметок у автора тысячи, а не 138 тыс., они идут по полному индексу
    `notes_author_all` и укладываются в срок веб-запроса целиком. Цена решения
    названа честно и в самом документе: **обезличивание одних заметок слабое**
    — человек отвечает в собственной теме под своим ником, и первая же его
    подписанная реплика говорит читателю, чья это заметка; полное
    обезличивание, вместе с комментариями, остаётся у `AnonymizeUser`, по
    обращению. Могила заводится СВЕЖАЯ на каждый отзыв (помнить «его прошлую»
    значило бы хранить то самое соответствие), время у неё огрублено до суток

    записало бы соответствие метками времени), а в `audit_log` не пишется
    ничего. Публиковать отозвавшему нельзя, и говорит ему об этом
    `ErrConsentRevoked` — отдельно от `ErrConsentOutdated`: «подпишите новую
    редакцию» тому, кто сам нажал «Отозвать», звучит как поломка.

    список категорий и таблица «что автомат гасит сам» (`AutoHideable`) живут

    убрать чужие слова обязано меняться правкой, которую видно в diff; грубости,

    могила» не пишет НИГДЕ, включая журнал: записав его, мы своей же рукой
    сохранили бы ту дополнительную информацию, отсутствие которой и делает
    обезличивание обезличиванием.

    случилось; `events`, append-only, пишется ТОЙ ЖЕ транзакцией, что и
    действие — рядом с `enqueueCheck` и `audit()`), ПОВОД (кому это интересно;

    раздачи) и КАНАЛ (о нём ядро не знает ничего). Правила адресации живут

    правил больше одного и они дорожают. Отсекается на раздаче, а не на показе:
    сам себе, тень (некуда), обезличенный, скрытое. **В `events` НЕТ колонки со
    свободным текстом от участника** — обмен произвольными сообщениями это
    149-ФЗ и реестр ОРИ, и держит границу отсутствие колонки, а не дисциплина.
    У события реакции `actor_id` не заполняется вовсе (правило Ш5г буквально), а
    нажатия схлопываются медленным проходом в одно событие на объект и знак.
    Зеркальные публикации дают события только СВЕЖИЕ (`EventHorizon`, час):
    правило про данные, а не про вызывающего, — тем же приёмом идут живой поток,
    сверка и перенос всего зеркала. Скрытие снимает НЕПРОЧИТАННЫЕ поводы той же

    конфига вместо общей `llm.model`.
    **Провайдер — РОССИЙСКИЙ, и это не настройка вкуса** (23.08.2026,
    `moderation-llm-must-be-russian` в памяти): опубликованное согласие обещает
    людям «не вывозит данные за пределы России», а на проверку уходит
    написанное ими же, — значит с Claude автомат включить нельзя, не выпустив

    `Version >= version`). Клиент — `rullm` поверх Yandex AI Studio; ветка

    `platmod` о провайдере не знает ничего и знать не должен — иначе политика
    решений начнёт зависеть от того, чья модель отвечает.

    про сам текст, а уместность — вопрос вкуса. Нет ключа — очередь просто
    копится и читается человеком, это рабочее состояние, а не авария. Второй
    работы — доводить отложенные проходы по авторам при отзыве согласия — у
    службы больше нет: отзыв не ходит по комментариям с 25.08.2026 (см. блок
    про `platform`), и доводить стало нечего.
  - `platbus` — тикер шины событий (эпик F): раздача поводов (5 с), разбор
    реакций (5 мин), уборка состарившегося (сутки). Живёт у ДЕМОНА, а не у
    морды: горутина, поднятая у обоих, делала бы одну работу вдвоём. Выключателя
    нет намеренно — молчащая шина это не «фича выключена», а площадка,
    переставшая говорить людям, что им ответили.
  - `platout` — ОБРАТНОЕ направление: написанное на площадке уходит в каналы
    мессенджеров. Нужно оно с того дня, как НГС перестал принимать комментарии:
    писать теперь можно только здесь, а аудитория живёт в канале, — и без этого
    обхода на странице идёт беседа, а в канале тишина. Приёмники те же
    (`mirror.Sink` без самой площадки, иначе петля), и это требование ВИДА:
    заметка площадки обязана выглядеть в канале ровно как заметка НГС.
    **Учёт отправленного — в SQLite `message_targets`**, а не в Postgres: там
    уже записано, где в мессенджере лежит каждый зеркальный комментарий, а
    нативная реплика сплошь и рядом отвечает зеркальной — полосы id не
    пересекаются, поэтому одна таблица отвечает на вопрос «где это сообщение» и
    про НГС, и про нас. Курсор живёт В ПАМЯТИ, стартует на границе нативной
    полосы (и не выходит за её ВЕРХНИЙ край: выше лежит восстановленное, см.
    полосы идентификаторов) и двигается только по непрерывному началу
    отправленного: заметка без
    пойманного треда задерживает свои комментарии, но не теряет их (у зеркальной
    заметки, запощенной до подключения приёмника, треда не будет никогда —
    отсюда срок `threadGrace`, час, после которого комментарий пропускается).
    Такт 15 с. Ссылка на страницу площадки едет ОТДЕЛЬНЫМ полем
    (`store.Note.SourceURL`), а не припиской к тексту (переделано 22.08.2026):
    у заметки, написанной здесь, другого адреса нет вовсе, а длинное тело
    композер режет под предел сообщения — приписанную к тексту ссылку обрезка
    съела бы первой, то есть ровно там, где она нужнее. Подвал теперь собирают
    оба приёмника одинаково: ссылка на оригинал, подпись канала, «Подписаться».
    **Ссылок на НГС в постах больше НЕТ** (27.08.2026, решение владельца): имя
    автора заметки и шапка комментария вели на анкету love.ngs.ru, а теперь
    стоят просто именем — `platout` не заполняет ни `store.Note.AuthorID`, ни

    которой ссылка вернётся первой же правкой композера. Само поле `AuthorLink`
    живо: по нему дайджест ЗЕРКАЛА опознаёт человека, числового id у
    комментария НГС нет.
    Подписки на такую заметку не предлагаются
    (`kbd.Subscribable`): они живут в SQLite и знают только заметки НГС.
    Встречное направление — не здесь, а в `bridge`: ответ из треда уходит на
    площадку при отказе сайта и всегда — у своей заметки. Оба конца сходятся на
    одной таблице `message_targets`, она же гасит эхо.
  - `web` — SSR-морда площадки. **Ссылок на НГС она не ставит нигде**

    ТЕКСТОМ (справка, документы, подсказка на входе) решением не тронуты.
    Мера здесь не «красиво», а **«человек не
    заметил переезда»**: вид переносится с love.ngs.ru по замерам, а не по
    памяти, — колонка автора слева (квадратный аватар 100×100, ник ПОД ним),

    попадают объявления площадки и выпуск дайджеста, и одна простыня съедает
    экран, за которым лежат ещё девятнадцать записей. Механизм ТОТ ЖЕ, что у
    простыни в треде (галочка с подписью, `longBodyRunes`, текст отдаётся целиком —
    сворачивается ПОКАЗ), а на своей странице заметка не сворачивается никогда.
    **Дерево отдаётся целиком**
    (891 реплика — одна страница, 96 мс), потому что ветка, обрезанная на
    середине, перестаёт быть веткой; постраничка есть только у линейного вида —

    убыванию id: порядок по id верен внутри одной полосы идентификаторов и неверен
    между ними — нативная реплика позапрошлой недели имеет номер больше пришедшей
    с НГС сегодня, и всё написанное здесь вставало наверх страницы независимо от
    того, когда это было сказано. Числа и цвета взяты из
    `index.css`/`main.css` НГС (снято 18.08.2026) и закреплены
    `fidelity_test.go`: каждый тест называет один факт об оригинале и источник
    (записанная страница / стили / экран владельца).
    **Мобильная вёрстка — не приложение к десктопной, а её проверка**:
    18.08.2026 аппарат с крупным системным шрифтом (viewport 288 CSS-пикселей)
    показал страницу заметки в ДВА ЗНАКА шириной. Виноват был десктопный резерв
    `padding-right: 150px` под словесный переключатель «Дерево / Линейный»;
    переключатель стал ИКОНКАМИ (на НГС он тоже иконки — два пустых `<a>` с
    одним `title`), резерв ужался до 76px и на телефоне снимается совсем, а сам
    переключатель уходит в свою строку. Тем же заходом: `flex-wrap` в шапке
    (комментарий обещал перенос, а свойства не было — кнопки наезжали на
    название) и ник шириной по своей колонке. Правило на будущее: любое число в
    пикселях, отнимающее ширину у ТЕКСТА, обязано иметь мобильную ветку.
    **Подвал прижат к низу окна** (`body` — flex-колонка, `.main` тянется):
    самая частая короткая страница — заметка без комментариев, и на ней подвал
    повисал посередине экрана. Тянется именно содержимое, а не пустая распорка,

    **Закреплённые заметки** идут отдельным запросом (`PinnedNotes`, свой
    частичный индекс) и приписываются к ПЕРВОЙ странице, а из ленты уходят

    ленты индекс `notes_feed` и превратил каждый её показ в сортировку 117 тыс.
    строк ради одной строки наверху. Цена записана честно — пока заметка
    закреплена, на своём хронологическом месте её нет. У модератора запрос свой

    закреплённые по `pinned_at`, а закреплённые отбирались по `status = 0`, —
    значит скрытая закреплённая заметка не показалась бы ему НИГДЕ.
    **МОРДОЛЕНТА** (`faces.go`, 30.08.2026, просьба владельца) — полоса лиц над
    лентой, и имя у неё не выдумано: так её звали на НГС сами участники («фоты
    мои по мордоленте не катаются», «мордолента уже третьи сутки не двигается» —
    обе фразы лежат в архиве комментариев). Там это была полоса фотографий на
    странице раздела; у нас в ней живут ЖИТЕЛИ, и по той же причине, по которой у
    них вообще появилась своя страница: люди приходят в раздел к ЛЮДЯМ, а лента
    заголовков этого не показывает. Три решения, и каждое можно было принять
    иначе. Только с ФОТО (`JOIN media`, а не LEFT): мордолента есть лента ЛИЦ, и
    силуэт занял бы в ней место, ничего не сказав, — заодно полоса показывает
    владельцу, кому аватар уже поставлен. Только ПЕРВАЯ страница — тот же довод,
    что у закреплённых, и та же выгода: на страницах 2…5933 лишнего запроса нет
    вовсе. Порядок — по ПОСЛЕДНЕМУ сказанному слову
    (`platform.personaFacesQuery`): полоса с вечным порядком за неделю становится
    частью фона, а жаловались на НГС как раз на то, что она стои́т; молчащий
    житель уходит в конец, но не пропадает. Отказ полосы ленту не роняет (как у
    иллюстраций), а пустая не рисуется вовсе.

    содержимого, внутри `div.lv-top-tape__visible-part` с ОДНИМ рядом фотографий
    100×100 и НИ ОДНОЙ подписью — имя лежит в `alt` и всплывает при наведении
    (там это qtip, у нас `title`: он работает без JS). Отсюда три правки первой
    версии: подписи под лицами убраны, ПОЛОСЫ ПРОКРУТКИ не видно (она разрезала
    бы ряд лиц пополам, и на сайте её не было), а полоса встала НАД карточкой,
    соседкой `.main`, а не внутри неё. Поле переехало из данных ленты в ОБЩУЮ
    часть страницы (`page.Faces`) по тому же доводу, что и счётчик реплик в
    шапке: рисует полосу КАРКАС. **Листается ряд при этом по-настоящему**
    (уточнение владельца: «явно горизонтальный скролл не должен отображаться, но
    сама возможность пролистывания на десктопе и в мобильной версии должна
    остаться») — пальцем и тачпадом без всякого скрипта, а стрелки у краёв
    (те же `lv-top-tape__nav` с сайта, тень со стрелкой) рисует `app.js`: без
    него полоса всё равно листается, а мёртвых кнопок площадка не печатает
    нигде. Полосу прокрутки прячут ТРИ разных свойства — договориться о ней
    браузеры так и не смогли, и забытое означает видимую полосу у части
    читателей. **Про машину полоса больше НЕ объявляет** (решение владельца: подпись

    не своя, а перенесённая: про жителей сказано значком песочницы у самой
    заметки, на странице жителя и в `/help#narod`.
    Курсорное пролистывание
    было и заменено номерами сознательно: OFFSET хуже технически, но «ещё» не
    даёт ни вернуться, ни знать, где ты. **На телефоне постраничка держится

    разрывают подряд идущие, встаёт своё многоточие (`Mob`), иначе «1 3 4 5»

    наверх к меню») и несёт название площадки (`SiteName`, «Зазеркалье»), вкладки

    липкая шапка в две строки съедает пол-экрана треда. Знак называет себя сам —
    `title` и `aria-label` стоят на ссылке, иначе скрытое показом слово унесло бы
    имя площадки и от читалки. Счётчик — спутник липкости, а не украшение: тред показывается
    целиком (891 реплика на самой длинной заметке), и до заголовка «Комментарии
    N» из его середины не домотать так же, как и до меню; значком с числом,
    потому что ширина строки на телефоне кончается раньше всего, а объяснение
    даёт `title` (правило Ш5з). Живой добор подкручивает оба числа сразу. Плата
    за липкость записана: якоря получают `scroll-margin-top` — иначе реплика, на
    которую пришли по ссылке «#», встаёт ПОД шапкой; на узком экране вкладки ужимаются
    кеглем, а `flex-wrap` остаётся страховкой. Пары стоят ОДНИМ блоком с
    перегородкой (`.grp`): «Лента / Справка» — один переключатель разделов,
    колокольчик с меню — один угол «про меня»; порознь они читались как четыре
    несвязанные кнопки. Фон красит блок, плашки внутри прозрачны, скругление у
    крайних — `overflow: hidden` там нельзя, под меню участника выпадает список. Справка стоит только в шапке
    (23.08.2026): вкладка видна с любой страницы и сверху, а дубль в подвале
    занимал место, которое нужнее бумагам. **Подвал теперь держит документы, и
    только их** — «Соглашения», «Политика конфиденциальности», «Отказ от
    ответственности» (`web/legal.go`): бумаги ищут внизу по привычке всего
    остального интернета, и стоять они обязаны на КАЖДОЙ странице — политику
    обработки закон велит опубликовать так, чтобы её прочёл ЛЮБОЙ (ч. 2 ст. 18.1),
    то есть за вход её убирать нельзя. Соглашения страница не хранит своей копией,
    а берёт у ядра (`platform.CurrentConsentDocs`) — это те же тексты, что
    подписывают при входе; свои два документа лежат файлами в `web/docs/`, и
    разбирает их та же `docHTML`, что показывает согласие на экране входа.
    Правило для правящего: перенос строки в файле — это `<br>` на странице,
    поэтому абзац пишется одной строкой (тексты согласий рядом свёрнуты
    по-старому, и переписать их нельзя — опубликованная редакция неизменяема).
    **Простыня сворачивается ПОКАЗОМ** (реплика длиннее `longBodyRunes` = 1500
    знаков, решение владельца 23.08.2026): видно начало, дальше — кнопка. Именно
    показом, а не запретом писать: в базе 10,7 млн зеркальных реплик, переписать
    их нельзя, а запрет чинил бы только будущее, оставив ровно ту страницу, с
    которой пришла жалоба; санитарный потолок `platform.MaxBodyRunes` при этом
    на месте и решает другую задачу. Разворачивает скрытая галочка с подписью, а
    не скрипт (без JS страница обязана работать), а пришедшего по анкору
    `:target` разворачивает сам — он шёл читать именно эту реплику.
    **Форма ответа стоит ПОД адресатом**, а не внизу треда (23.08.2026): на НГС
    «Ответить» уводило к общей форме в конце страницы, и оттуда приходилось
    листать обратно к месту разговора. Место выбирает СЕРВЕР (строка треда
    `.replyrow` с отступом самой реплики), а не скрипт, — иначе без JS осталась
    бы прежняя дорога; ссылка ведёт на `#c<id>`, то есть человек видит, кому
    отвечает. Внизу форма остаётся для ответа НА ЗАМЕТКУ.
    **Открывается она БЕЗ ПЕРЕЗАГРУЗКИ** (`replyform.go`, `GET /n/<id>/reply?to=<cid>`,
    23.08.2026): нажатие «Ответить» перерисовывало ВЕСЬ тред — до 5000 строк ради
    одной формы, — и человек терял место, на котором читал. Ссылкой оно при этом
    остаётся: без JS дорога прежняя, страница просто перезагружается, — а
    разметку скрипт НЕ СОБИРАЕТ, он просит у сервера готовую строку, и рисует её
    тот же `parts/replyrow.gohtml`, что и страницу. Приём тот же, что у живого
    добора, и по той же причине: второго способа превратить наш текст в HTML не
    заводится. Отсюда же поход в базу за адресатом (`CommentViewByID`): форме
    нужно то, чего в разметке реплики нет, — ТЕНЬ её автор или участник, а метка
    «ещё не переехал сюда с НГС» отвечает на единственный вопрос отвечающего,
    дойдёт ли его ответ. В потолках наплыва это `costPage`, а не `costThread`:
    одна реплика по индексу против дерева целиком. Набранное при переходе от
    одного адресата к другому переносится в новую форму, а отказ (реплику снесли,
    сессия истекла) отдаётся честным 404 — на нём скрипт уходит по той же ссылке
    обычным переходом, и человек видит настоящую причину.
    Ходит в `platform` напрямую, а не в свой же API по петле — но через
    **интерфейс `Store`**, и это же список того, что морда умеет делать с
    данными: она только читает, а страницы проверяются `httptest`'ом без
    Postgres. Страницы собираются в буфер целиком (ошибка шаблона обязана дать
    честные 500, а не обрубок с кодом 200) и не кэшируются вовсе. Текст
    хранится плоским и рендерится нами, поэтому XSS убран структурно — из
    форматирования только абзацы, переносы, автоссылки на http/https и разметка
    ранних лет НГС, чужой схеме в `href` взяться неоткуда. **Старая разметка
    разбирается по ДАТЕ, а не по полосе id** (`web/bbcode.go`): `[b]`, `[i]`,
    `[u]`, `[s]`, `[color=…]` сайт показывал до 02.06.2014 (замер по 1,64 млн
    комментариев архива: обращение «Для `[b][i]`Ник`[/i][/b]`» обрывается
    02.06.2014 13:07:44 UTC, дальше идёт «Ник, », и разметка людей кончается
    там же), а после печатал буквально — таким этот текст остаётся и у нас,
    иначе переезд «улучшил» бы оригинал. Разбирает стек с ленивым возвратом, а
    не замена по регулярке: в архиве разметка перекрёстная
    (`[b][i]…[/b][/i]`) и незакрытая, а страницу мы собираем строкой — утёкший
    `<b>` сделал бы жирным всё после карточки. Цвет приезжает КЛАССОМ по тем же
    причинам, что и глубина ветки, поэтому список цветов закрытый: незнакомый
    не красит. **В написанном ЗДЕСЬ разметка разбирается всегда** (21.08.2026,
    решение владельца: закреплённая заметка «`[b]`Хотелки`[/b]`» вышла на
    страницу скобками) — рубеж остаётся правилом про ЧУЖОЙ текст. Своего
    синтаксиса площадка при этом не выдумывает: знаки те же, что у сайта, — они
    у переехавших в пальцах, а второй набор рядом переучивал бы людей ради
    чистоты замысла. Узнать о них неоткуда (на НГС теги умерли в 2014-м),
    поэтому под обеими формами стоит справочник, и образцы в нём прогнаны ТЕМ ЖЕ
    разбором, что и тело заметки. **Заголовок вкладки** снимает знаки разметки и коды смайлов
    (`stripMarkup`) — плоский текст показать их не может, — но ровно там, где
    страница их РАЗБИРАЕТ: у чужой заметки после заката скобки остаются, потому
    что вкладка обязана совпадать с карточкой, а не улучшать её.
    Флаг `era.siteMarkup` отделяет «разметку
    рисовал сайт» от «разметка работает»: обращение образца 2013 года
    «Для `[b][i]`Ник`[/i][/b]`» снимается показом только в текстах НГС.
    В каналы мессенджеров нативный текст уходит РАЗМЕЧЕННЫМ (22.08.2026):
    знаки НГС превращает в разметку канала `platout` — он один знает
    происхождение строки, — а композеры приёмников получают готовое тело полем
    `store.Note.TextHTML` и экранируют только сырое. Разбор общий и живёт в
    `chantext.FromSiteMarkup`: показывается то, что понимают ОБА канала (`<b>`,
    `<i>`), у `[u]`/`[s]`/`[color]` пары нет — знак снимается, слова остаются.
    Смайлы `:::popcorn:::` в канале по-прежнему коды: картинку в текст
    сообщения не вставить, а подменять их эмодзи значит выбрать за автора
    другой рисунок.
    **Смайлы сайта** (`:::popcorn:::`,
    `web/smiles.go`) — второй такой набор и в архиве заметнее разметки: они у
    6–11 % комментариев 2013–2017 годов, у одного «popcorn» 9 581 вхождение в
    замере. Рубеж у них СВОЙ (сентябрь 2017, дальше ноль), отсюда и «эпоха
    текста» из двух флагов вместо одного. 64 картинки скачаны с НГС 18.08.2026
    и вшиты в бинарник (`assets/smile`, 147 КБ): это часть вида страницы, а не
    чьё-то вложение, — и они совпали БАЙТ В БАЙТ с копией 2015 года из старого
    парсера (`dump/lnParser`). Размер каждого читается из заголовка GIF и
    ставится атрибутами (набор разнокалиберный, от 15×15 до 100×20).
    Неизвестный код остаётся текстом, как оставался на сайте.
    **CSP без `unsafe-inline` запрещает и атрибут `style`**, поэтому глубина ветки приезжает КЛАССОМ `d1…d12`, а
    отступ считает `calc()` (на НГС это inline `padding-left`); из того же
    запрета следует «ни npm, ни CDN». Обращение «Ник, » дорисовывается ПОКАЗОМ
    из ребра `reply_to_id` (в теле его нет) — иначе переименование и
    обезличивание не меняли бы подпись в чужих ответах; у комментариев до
    02.06.2014 обращение рисовал САМ сайт («Для `[b][i]`Ник`[/i][/b]` текст»),
    и показ его снимает (`platform.TrimLegacyAddress`) — иначе обращение вышло
    бы дважды. Снимается именно показом: 10,7 млн строк уже в базе, и
    переписывать их ради вида нечестно. **У переименовавшихся обращение остаётся
    в теле и в современной форме**: приём срезает его сверкой с ником
    (`TrimAddress`), а в теле стоит ник НА ТУ ДАТУ, — отсюда «Паноптикум, Рантье,
    привычное…», один человек старым ником и новым. Показ второго обращения не
    рисует, но «автор назвал адресата сам» решает **не форма строки, а
    свидетельство треда** (`address.go`): токен считается ником, если им в этой
    заметке обращались к ОДНОМУ И ТОМУ ЖЕ человеку РАЗНЫЕ люди (повтор от одного
    и того же — это его привычка говорить «да, …», а не чьё-то имя) либо он
    совпадает с ником участника. Поверх стоит вето — короткий список зачинов и
    междометий: они повторяются в разговоре сами по себе и свидетельство
    подделывают. Правило по форме («всё до первой запятой»)
    прожило час: на живой странице оно приняло за ники 62 фразы из 227 («Вы не
    представляете, как я люблю холодок»), и замер, которым оно было себе
    разрешено, оказался неверен по методике — считал совпадения со списком частых
    зачинов, а зачины это длинный хвост НЕПОВТОРЯЮЩИХСЯ фраз. Одиночное
    обращение старым ником в коротком треде по-прежнему выходит дважды: это
    дешевле, чем порезать чужой текст по догадке. Статика вшита в
    бинарник и адресуется хешем содержимого (`style.<hash>.css`, `immutable` на
    год); медиа в бою отдаёт Caddy мимо Go. **Чтение открыто всем**
    (18.08.2026), слоя «за воротами» в роутере нет; **вход** (`login.go`) —
    отдельная страница, на которую ведёт кнопка в правом верхнем углу шапки,

    третьим пунктом «Настройки», у нас его нет намеренно: отдельной страницы
    настроек площадка не заводит, ник, фото и согласия живут на той же `/me`, а
    единственная настройка, которой там не место (тема), стоит прямо в меню.
    Переключатель тем переехал сюда из подвала 23.08.2026 по решению владельца:
    тема — настройка «про меня», и место ей там же, где остальное про меня. Плата
    записана честно: **у гостя переключателя нет вовсе**, и с 30.08.2026 она

    достаются: `.acctmenu button:not(.tbtn)` — иначе hover пункта стирал бы
    подсветку выбранной темы. **Фото — кнопкой
    «Обновить аватар»** (`me.go`), и это не загрузка файла: площадка идёт в
    анкету НГС и берёт то, что человек и так показывает там. Причина в том, что
    само оно сюда больше не приезжает — аватар приносило зеркало вместе с
    комментарием, а комментариев на НГС нет с 17.08.2026; замер по боевому
    зеркалу говорит, насколько это живое (у одной участницы 56 разных файлов за
    четыре недели). Кнопки нет там, где она заведомо откажет: у вошедшего по
    приглашению (анкеты НГС нет вовсе) и при недоступном сайте. Пустая анкета
    прежнее фото НЕ снимает — вернуть его было бы неоткуда, — а отказ НГС рисует
    ту же `/me` с объяснением, а не 500: чужой сайт не наша поломка.
    **СНЯТЬ фото — соседняя кнопка «Убрать фото»** (28.08.2026, жалоба
    участника): из правила «пустая анкета фото не снимает» выходил тупик —
    стёрший фото В АНКЕТЕ оставался здесь с прежним навсегда, само оно сюда
    больше не приедет, а кнопка отвечала ему «здесь всё осталось как было».
    Разница между двумя кнопками не в осторожности, а в том, ЧЬЯ это рука: чужая
    (пустая анкета) фото не отнимает, своя вправе. На НГС путь не ходит вовсе,
    отсюда всё остальное: стоит как обычная запись (не как вход, см. `goesToNGS`),
    работает при мёртвом сайте и у вошедшего по приглашению, а показывается там,
    где снимать есть что. **Байты из хранилища НЕ удаляются**
    (`platform.ClearAvatar` снимает привязку): имя файла есть его содержимое, на
    ту же картинку ссылаются чужие строки, а уборки каталога у площадки нет
    вовсе. Ссылка `ngs_avatar_url` снимается ВМЕСТЕ с байтами — иначе `platform
    media` (он берёт тех, у кого ссылка есть, а байтов нет) вернул бы снятое фото
    следующим же обходом. Чего это не обещает: пока фото стоит в анкете НГС, его
    вернёт первый же приехавший оттуда комментарий — зеркало приносит аватар
    вместе с репликой, и сказано об этом на самой `/me`. Приём
    СВОЕГО файла появился 26.08.2026, но только для ЗАМЕТКИ, а не для аватара

    до 1600, EXIF снимается перекодированием через ffmpeg (webp; сборка без
    libwebp — молча jpeg). Публикуется СРАЗУ, как текст, — премодерации нет
    (решение владельца), и платой за это служит правило «заметка с картинкой
    попадает к модератору в очередь ВСЕГДА». Аватар по-прежнему только из анкеты
    НГС. **С 28.08.2026 файл уходит на сервер РАНЬШЕ заметки** (`web/shotdraft.go`,
    `POST /shot`): по одному выбору, пока пишется текст, — а форма несёт лишь
    номер черновика, и кнопка отправки на время закачки неактивна. Причин три, и
    все замерены на живой форме: отказ по самому файлу («это не картинка»,
    «слишком много точек») приходил ПОСЛЕ написанной заметки и вместе с потерей
    выбранного (браузер файл обратно не отдаёт); десять мегабайт с телефона
    ползут минуту, и всё это время экран молчал — ровно как «зависание», с
    которого разговор и начался; те же мегабайты занимали слот морды (их
    двенадцать) вместе с транзакцией публикации. **Черновик лежит В ПАМЯТИ**
    (полчаса, 32 штуки и 24 МБ, один на человека — новый выбор вытесняет
    прежний), а не в хранилище, и это решение владельца: на диске он пережил бы
    рестарт, но уборки каталога у площадки нет вовсе — выбранный и не
    опубликованный файл остался бы там навсегда, а дверь открыта любому
    участнику. Взамен черновик переживает ОТКАЗ публикации (бан, частота,
    истёкшая редакция согласия) и возвращается на перерисованную форму
    карточкой — ради этого всё и делалось. Превью показывает УЖЕ
    перекодированное (`GET /shot/<id>`, из памяти, только владельцу): у
    исходника другой размер, другой поворот и данные съёмки внутри. Разметку
    карточки рисует СЕРВЕР (`parts/shotdraft.gohtml`, тот же шаблон для ответа
    на предзагрузку и для формы после отказа) — тот же приём, что у формы ответа
    и живого добора. Прежняя дорога жива: без JS файл едет телом формы, как
    раньше, и потому потолок тела у прокси нужен ВСЕМ трём путям (`/shot`,
    `/new`, `/n/<id>/edit`) — список этот обязан совпадать с `isNoteUpload` в
    `web/guard.go`, и разъехались они ровно однажды, 27.08.2026: правку добавили
    в Go и забыли в Caddyfile, отчего честная картинка в 2,9 МБ получала 413,
    обрезанная на первом мегабайте. **Пустое фото — силуэт, а не буква**
    (`silhouette.go`, 18.08.2026): на НГС на этом месте стоит силуэт ПО ПОЛУ
    (`male300px.png` / `female300px.png`, под анонимной заметкой серый
    `anonymous300px.png`) — три файла сняты с сайта и вшиты в бинарник, как
    смайлы, потому что это часть ВИДА страницы, а не чьё-то вложение. Четвёртый,
    нейтральный, НАШ: пол у нас известен не всегда (приезжает обходом дерева и
    входом), и мужской «по умолчанию» назвал бы мужчинами половину площадки. У
    анонима силуэт выбирается РАНЬШЕ, чем смотрят на ссылку фото; в хранилище
    медиа силуэт по-прежнему не кладётся. В тёмных палитрах силуэт пригашен
    (`--sil-fade`), а фото — никогда: силуэт это фон, фото содержание.
    Раскрывает меню
    `details`/`summary`, а не скрипт: без JS оно обязано открываться, иначе
    «Выход» однажды перестанет быть доступен вовсе; скрипт лишь закрывает его
    по клику мимо и по Escape. **Модерация** (`mod.go`, Ш7) — страница
    очереди `/mod`, журнал `/mod/log`, карточка участника `/mod/u/<id>` и
    кнопки «скрыть»/«вернуть» под КАЖДОЙ репликой страницы заметки: модератор
    работает там, где читает, — решать по цитате в очереди, не видя разговора
    вокруг, значит путать ссору с угрозой. **С 26.08.2026 «там, где читают» —
    это и ЛЕНТА** (жалоба владельца): под каждой её заметкой стоит та же
    полоска, что и на странице заметки (`parts/modbar.gohtml`, ветка
    `IsNote` — один шаблон на оба места, иначе набор кнопок разъедется), а
    **скрытая заметка не пропадает, а ЗАТЕНЯЕТСЯ** (`.nhid`, как `.chid` у
    реплики; гасится содержимое, а не строка целиком — `opacity` заводит свой
    слой, и вернуть полоске полную силу изнутри было бы нечем). До этого дня
    скрытая заметка исчезала из ленты и у того, кто её скрыл: вернуть её можно
    было только из очереди, то есть по цитате. Закрепление стоит там же и
    оттого на своём месте: место в ленте видно только из ленты. Читателя это не
    касается — «Пожаловаться» в ленте нет вовсе (жалоба про КОНКРЕТНЫЕ слова, а
    лента показывает начало текста), она осталась на странице заметки. Мера здесь — «очередь читается за
    минуту»: одна страница со всем сразу, действия кнопками в строке и никаких
    экранов подтверждения (скрытие обратимо, а лишнее нажатие в пересчёте на
    сутки дороже ошибки). Постороннему `/mod` отвечает «нет такой страницы», а
    не «нужны права»: существование закрытой двери — само по себе сведения.
    **Администрирование** (`admin.go`, `/mod/admin`) — соседняя дверь, а не
    раздел очереди: модератор решает про СЛОВА, администратор — про то, кто их

    чего мы избежали у реакций. Автору скрытого на `/me` видны причина и кнопка
    «на пересмотр», а список берётся из ОЧЕРЕДИ, а не обходом его комментариев
    (53 с у участника со 138 тыс. реплик). Ядро вход не показывает, а только
    исполняет, поэтому у морды
    четыре интерфейса: `Store` (только чтение публичных страниц), `Auth`
    (операции над данными ОДНОГО человека), `Writer` (что участник вправе
    изменить) и `Moderator` (что позволено модератору, плюс горстка
    администраторских — роли и приглашения: заводить пятый список ради них
    значило бы размножить конструктор, а различие держит проверка права в ядре,
    а не место метода) — смешивать их значило бы
    потерять это различие, а каждый список сам по себе есть исчерпывающий ответ
    на вопрос «что площадка позволяет». `Moderator` может быть nil: тогда
    страниц модерации нет и кнопок под репликами тоже. Клиент НГС приходит третьим (`Site`) и может быть nil: тогда
    форма ввода анкеты не показывается вовсе и остаются приглашения — штатное
    состояние площадки после смерти сайта, а не авария. Сессия читается ОДИН
    раз за запрос (`withViewer` кладёт человека в контекст), потому что её
    спрашивают шапка, права страницы и запросы к ядру. **Потолки наплыва — `guard.go`**, и стоят они не ради морды: ядро на
    хосте одно, и всё, что она отберёт, отбирается у зеркала. Потолка три —
    частота по клиенту с ЦЕНОЙ маршрута (тред дороже ленты, вход дороже всего:
    он ходит на НГС и шлёт человеку ЛС), 12 запросов в работе разом (страница
    треда собирается в буфер целиком) и срок запроса; плюс потолок тела формы и
    длина ленты, посчитанная не чаще раза в 30 с (это count по 117 тыс. строк на
    каждый заход). Ключ корзины — хеш адреса на случайной соли запуска: сырых
    адресов площадка не хранит нигде, а сам адрес берётся из ПОСЛЕДНЕЙ записи
    `X-Forwarded-For` — первую пишет сам клиент. Отказ отдаётся простым текстом
    с `Retry-After`: он обязан быть дешевле работы, иначе он и есть работа; в
    лог идёт сводка раз в минуту, а не строка на запрос.
    **Справка и правила** (`/help`, `help.go`) — единственная страница, которую
    пишет человек, а не запрос к базе, и открыта она ВСЕМ, включая не вошедших:
    правила, которые видно только изнутри, — это не правила, а сюрприз. Правила
    раздела перенесены с love.ngs.ru (редакция 18.04.2019) и приведены к тому,
    как всё устроено здесь; два отличия названы в самом тексте — у нас скрывают,
    а не удаляют, и решение модератора можно оспорить. Числа (окно правки,
    потолок закреплённых) и реквизиты оператора приезжают из ядра и конфига, а
    не написаны словами: справка, разошедшаяся с поведением кнопки, хуже
    отсутствующей. **В ленте**: у закрытого обсуждения та же надпись, что у
    чужой отметки НГС «не актуальна» (читателю оба состояния значат одно —
    заглянуть можно, вступить нельзя), а у вошедшего рядом с «Комментарии N»
    стоит «Добавить комментарий», как на сайте, — и под НЕАКТУАЛЬНОЙ заметкой её
    нет при любой причине: строкой выше уже сказано «ознакомиться с
    обсуждением», и звать в законченный разговор следующей же ссылкой значит
    спорить с самим собой. Права писать это не меняет: отметка НГС его
    по-прежнему не отнимает (Ш5), и форма на странице такой заметки работает —
    решение принято о ПОКАЗЕ, а не о запрете. Закреплённая заметка помечена
    прямо в списке («Закреплено»), а не вынесена в отдельный блок: старая запись
    наверху без метки читается как поломка сортировки.
    **События** (`events.go`, `live.go`, `hub.go`, эпик F) — страница `/events`
    со списком поводов и отметкой прочитанного формой, плюс **колокольчик** в
    шапке: единственная метка площадки, которой на НГС не было, поэтому по
    правилу Ш5з она объясняется заголовком при наведении и разделом в `/help`.
    Счётчик упирается в потолок `platform.UnreadCap` («99+»), чтобы запрос не
    зависел от того, сколько человек не заходил. **Живой канал** `/live` — SSE
    и только вошедшим, и это не про права, а про арифметику: так число
    долгоживущих соединений ограничено числом участников. Он идёт МИМО семафора
    морды и мимо срока запроса (`longLived` в `guard.go`) — двенадцать слотов
    при пуле в четыре соединения десяток вкладок занял бы целиком, — а взамен
    имеет свои потолки (64 всего, 2 на человека, 5 минут на соединение) и НЕ
    ходит в базу ни разу: читает из хаба, который спрашивает Postgres ОДИН раз
    независимо от числа страниц. Сервер шлёт по нему СИГНАЛ, а не HTML:
    хаб один на процесс и никого не знает, а строка у каждого своя — модератор
    видит скрытое, автор свою реакцию, гость не видит «Ответить».
    **О новом хаб узнаёт ЗВОНКОМ, а не тактом** (23.08.2026,
    `platform/live.go`): пишущий делает `NOTIFY` той же транзакцией, что и
    запись факта, хаб держит `LISTEN` на ОТДЕЛЬНОМ соединении вне пула (пятая
    часть пула, ушедшая в вечное ожидание, отбиралась бы у страниц, а через них
    у зеркала) и по звонку идёт читать журнал теми же курсорами. **Звонок — это
    звонок, а не данные**: payload пуст и не читается вовсе, поэтому потерянное
    уведомление ничего не теряет, двойное ничего не удваивает, а второго пути
    содержимого на страницу не заводится. Через базу, а не прямым вызовом,
    потому что процессов ДВА: морда пишет нативную реплику, демон — зеркальную и
    повод, и вызов в памяти закрыл бы половину случаев, оставив вторую на такте.
    **Такт не убран, а разрежен и стал двухскоростным**: при живой подписке 20 с
    (страховка от потерянного звонка), без неё — прежние 2 с, то есть деградация
    это ровно прежнее поведение, а не поломка; переход в обе стороны пишется
    одной строкой в лог, а режим (`notify` | `poll`) показывают `healthz` и
    `platform doctor`. Замер сквозного пути «реплика записана → сигнал у
    слушателя»: медиана 10 мс, p95 15 мс на разреженном потоке; на сплошном
    p95 упирается в пол частоты `hubRingFloor` (100 мс), который держит расход
    в двадцати запросах к базе в секунду при любом шторме.
    **Источников сигнала ТРИ, и третий — переезд ветки** (`LiveMover`,
    24.08.2026): обход мобильного дерева заменяет угаданное зеркалом ребро
    настоящим, и ветка на открытой странице обязана уехать на своё место.
    Отметка `moved_at` и заголовок `X-Fresh-Moved` для этого были с миграции
    0015, не было ПОВОДА за ними сходить — добор идёт по сигналу, а сигналы
    рождались только из `events`, куда переезд не пишется и писать его незачем
    («ветка встала на место» не то, о чём говорят участнику). Пока разговор
    продолжался, переезд приезжал ЗАОДНО со следующей репликой, и потому дефект
    выглядел как «иногда»; стоил он жалобы владельца на затихший тред, где ветка
    осталась угаданной до перезагрузки. Спрашивает хаб **только про открытые
    треды** (`MovedNotesSince`), и это не экономия: индекс `comments_moved` ведёт
    с `note_id`, поэтому «все переезды после T» — это перебор 10,7 млн строк, а
    список открытых тредов у хаба и так есть и ровно определяет, кому такой
    сигнал вообще может пригодиться. Миграции не понадобилось.
    Обёртка лога отдаёт `Unwrap()` — без него `http.ResponseController` не видит
    ни `Flush`, ни дедлайнов настоящего писателя, и поток не работает вовсе.
    **Живой добор** (`fresh.go`, 23.08.2026) — вторая половина: получив сигнал,
    страница идёт за ГОТОВОЙ строкой на `/n/<id>/fresh` либо `/fresh` и
    дописывает себя без перезагрузки и без нажатий (прежняя полоса «показать»
    убрана по решению владельца — «как в мессенджерах»). Рисует строку ТОТ ЖЕ
    шаблон, что и страницу (`parts/comment.gohtml`, `parts/note_item.gohtml`),
    и в этом всё устройство: второго способа превратить текст в HTML не
    заводится, значит не заводится и вторая поверхность XSS вместе со вторым
    местом, где однажды забудут про эпоху разметки, смайлы и маскирование
    анонима. Скрипт только выбирает МЕСТО: в дереве — среди СЕСТЁР по
    возрастанию id (`data-parent`/`data-depth`), потому что сегмент
    материализованного пути это и есть id, дополненный нулями, — «в конец ветки»
    расходилось с обновлением на смешанном треде, где пришедший с НГС ответ стоит
    выше уже лежащих своих; в линейном виде и в ленте — сверху,
    но ниже закреплённого; уже стоящая на странице строка пропускается по id,
    чем заодно гасится эхо своей же реплики. Курсор для клиента непрозрачен
    (`data-fresh` → `?after=` → `X-Fresh-After`), и он ПАРА в обоих случаях: у
    ленты «время, id», у треда — по числу на полосу идентификаторов
    (`platform.FreshAfter`, запрос ветвится на UNION ALL из двух range-scan).
    Одним числом полосы не упорядочиваются: нативный id больше любого ngs'ного,
    включая завтрашний, — и общая граница после первой же реплики, написанной
    ЗДЕСЬ, уезжала в нативную полосу, после чего приходящие с НГС комментарии не
    догоняли страницу никогда (в мессенджере идут, на странице их нет до
    обновления; заметка 313056, чинено 23.08.2026). Полоса поднимает и нижний
    край нативной ветки: пустая граница значит «своих реплик на странице нет», а
    не «неси всё», иначе ветки перекрываются и реплика приезжает дважды. Саму
    границу страница СПРАШИВАЕТ У ЯДРА (`ThreadFreshAfter`, максимум по каждой
    полосе у всей заметки), а не считает по показанным строкам: в линейном виде
    на странице ОКНО из тридцати самых свежих, и полоса, в него не попавшая,
    получила бы границу «с начала» — первый же сигнал притащил бы наверх страницы
    самые старые реплики этой полосы. Спрашивается она ДО чтения реплик: реплика,
    пришедшая между двумя запросами, попадёт и на страницу, и в добор, а повтор
    гасится по id. Запрос свой (`CommentsSince`/`NotesSince`), а не «дай тред
    заново»: дерево отдаётся целиком до 5000 строк. Перед добором клиент ждёт
    случайные 0–200 мс — сигнал приходит всем открытым вкладкам в одну
    секунду, и без разброса популярный тред устроил бы отказ сам себе. Окно
    ужато впятеро вместе с переходом на звонок (23.08.2026): секунда разброса
    поверх мгновенного сигнала съедала бы ровно то, что он выиграл, а
    арифметика на худший случай сходится — живых потоков у площадки 64 ВСЕГО, и
    при добора́х по десятку-другому миллисекунд в двенадцать слотов морды они
    укладываются с запасом. **Растить потолок потоков, не пересчитав это число,
    нельзя.**
    Дописывается только ПЕРВАЯ страница ленты и линейного вида: остальные —
    срез истории. Отказ добора страницу не роняет (пустой кусок и прежний
    курсор), а сдвиг прокрутки при вставке выше видимого разбирает сам браузер
    (`overflow-anchor`), поэтому его никто не отключает.
    **Вторая половина добора — ПЕРЕЕЗДЫ** (`CommentsMoved`, миграция 0015,
    23.08.2026): строки, которые на странице уже стоят, но с тех пор сменили
    место. Дерево перестраивается ПОД открытой страницей — зеркало ставит ребро
    по обращению «Ник, …» и ошибается примерно вполовину, а `reply-scan` заменяет
    догадку настоящим ребром раз в минуту, — и по границе id такая строка не
    приезжает никогда: id у неё прежний. На боевой заметке 313058 это выглядело
    так: Kowalski 63238879 нарисован на глубине 4, обход переставил его на 2, и
    следующая строка треда, его собственный ответ 63238886, приехала с глубиной
    3 — МЕНЬШЕ, чем у родителя строкой выше (жалоба владельца; после
    перезагрузки дерево правильное). Отсюда отметка `comments.moved_at`,
    третья составляющая курсора (пара «время, id»: одна транзакция обхода
    штампует все свои строки одним `now()`, и обрезанная потолком порция обязана
    продолжиться с середины отметки) и заголовок `X-Fresh-Moved` со списком тех
    строк порции, что суть переезды. Строка приезжает ГОТОВОЙ разметкой, а не
    парой чисел: вместе с местом у неё меняются глубина, подпись адресата и
    иногда тело, — то есть тот же единственный путь рендера. Страница снимает её
    со старого места и ставит заново (в линейном виде и в ленте — заменяет на
    месте: там порядок по времени); переезда строки, которой на странице нет, она
    не ставит вовсе. **Место чтения при этом сохраняется** (27.08.2026, вопрос
    владельца «а если я её читаю — где её потом искать?»): высота, на которой
    строка стояла на экране, замеряется ДО перестановки и возвращается ПОСЛЕ
    прокруткой — двигается окружение, а не читатель. Прокрутка К НОВОМУ месту
    была бы тем самым рывком страницы, от которого бережёт `handsBusy`, поэтому
    «перевод фокуса» отвергнут в пользу неподвижности. Порция переездов
    применяется ЦЕЛИКОМ или не применяется вовсе (тот же довод, по которому
    `ApplyReplyTree` кладёт заметку одной транзакцией): переставив родителя и
    оставив потомка, страница нарисует ветку глубиной меньше родительской — ровно
    ту картинку, из-за которой переезды и заведены. Строку, в которой стоит
    курсор или выделение, переезд ЖДЁТ: узел снимается со страницы вместе с
    ними, а второй раз он не придёт (курсор добора ушёл, `moved_at` прочитан), —
    поэтому отложенные переезды лежат в памяти страницы до `selectionchange`
    либо `focusout`. Виден переезд короткой рамкой (`.moved`), а не подсветкой
    нового: текст прежний, и вопрос у читателя другой — «почему вокруг всё
    поменялось»; сказано об этом и в `/help`. Отметку ставит только ВИДИМОЕ изменение: смена одного
    `reply_source` показу безразлична, а гнать из-за неё через живой канал весь
    тред при первом обходе заметки незачем. Чего это не чинит: сигнал рождается
    от событий, поэтому последний переезд в затихшем треде доедет до открытых
    вкладок только со следующей репликой.
    **Индексация ОТКРЫТА с 23.08.2026** (решение владельца), и открыта она не
    правкой трёх флагов: прежние редакции согласий обещали людям «страницы
    закрыты от поисковых систем, в поисковой выдаче ваших слов не будет», —
    поэтому вместе с запретом выпущены `distribution.v2` и `processing.v3`, а
    публиковать теперь можно только по действующей редакции
    (`platform.ErrConsentOutdated`, см. ниже). Закрытым остаётся ЛИЧНОЕ и
    служебное — `/me`, `/events`, `/mod`, `/login`, `/consent`, `/report`,
    `/live`, `/fresh`, форма ответа: список один (`web.privateRoots`) и на
    заголовок `X-Robots-Tag`, и на `robots.txt`, потому что разъехавшись они
    дали бы страницу, закрытую в одном месте и открытую в другом. **Карта сайта**
    (`sitemap.go`, `/sitemap.xml` + `/sitemap/<N>.xml` по 50 000 адресов) —
    единственная страница площадки, написанная не для человека: своим ходом
    робот дошёл бы до заметок только через постраничку ленты, а это 5 933
    страницы по двадцать записей. «Менялось» в ней — время последней РЕПЛИКИ:
    тред живёт дольше заметки. У заметки объявлен КАНОНИЧЕСКИЙ адрес — дерево без
    параметров: линейный вид и его страницы показывают те же реплики иначе
    разложенными, и без указания поисковик выбрал бы главным из них любой. У
    ленты канонического адреса нет намеренно — её страницы разные по содержанию,
    и свести их к первой значило бы спрятать от поиска весь архив. Цена открытия названа честно и в самом
    документе: со страниц площадки отзыв согласия убирает имя сразу, а из
    чужого кэша — когда поисковик придёт снова. Темы — токены `:root` плюс `data-theme` из куки;
    переключатель это форма с POST, а не ссылка (как и выход), и живёт он в меню
    участника, а не в подвале. Тем **четыре, и
    они двух родов**: «Светлая» и «Тёмная» — палитра НГС (числа с сайта,
    закреплены `fidelity_test`), «Бумага» и «Графит» — свои, заведены
    18.08.2026 по просьбе владельца, и мера у них другая — читаемость вместо
    соответствия (служебный текст 4,6:1 против 2,85:1 у НГС). Правило набора
    одно и оплачено прежним сокращением с четырёх тем до двух: **кнопка обязана
    показывать то, чего не показывает другая** — «Классика» и «Светлая» отдавали
    одну и ту же палитру, и нажатие это не подтверждало. Стережёт это уже не
    дисциплина, а тест: `TestThemePalettesAreDistinct` сравнивает склеенные
    токены, а не имена, и `TestDarkPalettesRestateWhatBaseWroteForWhite` требует
    от тёмной палитры своих `--bb-*` и `--hl` — наследуются они от голого
    `:root`, где стоят словами автора (`blue`, `purple`) и рассчитаны на белый
    лист. Подсветка комментария по анкору с тех пор тоже токен (`--hl`), а не
    правило на тему: селектор держал бы цвет только у той палитры, про которую
    вспомнили. **Тема по умолчанию — «Графит»** (решение владельца 30.08.2026,
    `web.defaultTheme`): до этого дня умолчания не было вовсе — атрибут
    `data-theme` не ставился, и вид площадки определяла настройка чужой
    операционной системы. Плата названа прямо: «как в системе» больше не
    работает НИ ДЛЯ КОГО, и человеку со светлой системой площадка открывается
    тёмной, а сменить тему он может только войдя (переключатель в меню
    участника). Взамен у площадки есть свой вид — один и тот же у гостя, у
    поисковика и на чужом экране. Умолчание при этом не пятая палитра, а одна
    из четырёх кнопок: нажавший «Графит» руками и не нажимавший ничего видят
    одно и то же. Отсюда две уборки, которые важнее самой правки: из стилей
    ушли ОБА правила вида `:root:not([data-theme])` — и палитра «как в
    системе», и подсветка кнопки, — потому что сервер теперь знает тему
    всегда, а второе место, где она решается, было бы вторым мнением; и в
    каждой палитре встал `color-scheme`, иначе полосы прокрутки и галочки
    рисовались бы по системе читателя — на тёмной странице светлыми, и с
    30.08.2026 это доставалось бы КАЖДОМУ гостю. **Чего из
    оригинала нет намеренно**: огонёк «онлайн» и боковая колонка новостей НГС —
    первое площадка не заводит по решению эпика E, второе чужое. Кнопку
    «пожаловаться» с НГС мы тоже не переносили, но своя жалоба в Ш7 всё же
    появилась (`/report`), и это не отмена решения, а другой довод:
    классификатор по архиву не гоняется, значит 10,7 млн зеркальных реплик
    модерировать больше нечем.

    само). Тянется ЛЕНИВО, в фоне: показ только спрашивает `os.Stat`, отчего

    картинки и недоступную сеть разом. Площадки — закрытым списком в коде

    миллионы запросов к чужим хостам.
  - `bridge` — reply→site comment: messenger-agnostic `Core` (at-most-once
    via `processed_replies`, per messenger) + the Telegram handler with
    auto-forward capture (linking a channel post to its discussion thread).
    The auto-forward update arrives once and can be lost to a Bot API failure,
    stranding a note's comments in the queue forever (happened to note 312859
    on 3 Aug 2026), so there is a fallback: the first reply to the thread root
    carries that same forward in `reply_to_message`, and the link is recovered
    from it. Отметка at-most-once ставится ДО отправки, поэтому не ушедший
    комментарий не уйдёт уже никогда — и об отказе сайта **говорят автору**
    (`notify`, отдельным текстом от подсказки про `/login`): 17.08.2026 сайт
    отвечал 500 на любой комментарий, и чужие ответы терялись молча, а человек
    был уверен, что написал. Автоповтора нет намеренно: 500 не означает, что
    сайт комментарий не принял. **С 18.08.2026 отказ сайта не конец пути**:
    ответ уходит на площадку от имени того же человека, а у заметки, написанной
    НА ПЛОЩАДКЕ, других путей и нет — на НГС её не существует. Куда нести,
    решает не настройка, а то, чему отвечают (полоса идентификаторов), и
    порядок «сначала сайт» выбран сознательно: пока НГС принимает комментарии,
    ответ обязан появиться и там, а на площадку его принесёт зеркало — копия
    выйдет ровно одна. Цена записана честно: «принял и соврал 500» дал бы на
    площадке дубль, и размен сделан в пользу «ответ не пропадает». Автор
    реплики обязан быть **участником площадки** (`writeGuard`: `kind =
    member`), иначе публиковать его слова у себя мы не вправе — согласие даётся
    там и только им самим; такому человеку уходит приглашение войти, и момент
    для него лучший из возможных. Идентичность берётся из
    `sessions.site_profile_id`: id участника площадки РАВЕН номеру анкеты. Эхо
    гасится отметкой `message_targets` на своё же сообщение — исходящий обход
    копию в этот мессенджер не понесёт, а в остальные понесёт. Публикация на площадке идёт под сроком (15 с): на том конце
    горутина обработчика апдейта мессенджера, и ждать занятую базу дольше —
    значит остановить мост. Про переезд
    ответа человеку говорят ОДИН раз за жизнь процесса (`told` в памяти):
    молчать нельзя, а повторять на каждую реплику — это письмо на каждое
    сообщение.

    он стоит в утренней тишине: вечер пятницы идёт на подъём к суточному пику
    21:00–22:00, и срез в 19:00 рассекал его пополам; обоснование замером —

    интерфейс `Source` — `platdigest` поверх Postgres, когда площадка есть, и
    `StoreSource` поверх SQLite зеркала, когда её нет. До этого дня сводка
    считалась только по зеркалу НГС, а написанное на площадке в `notes` и

    (`RecordHorizon`), а не за всю историю: в базе архив с 2009-го, и «рекорд
    за всё время» — это тред 2013 года, который не побьют никогда.
    **Выходит выпуск НА ПЛОЩАДКЕ нативной заметкой**: у сводки появляется
    адрес и тред там, где сообщество живёт, а в Telegram и MAX её несёт

    тред (Ш5б) — до этого пост дайджеста обсуждался в автофорварде, которого
    мост не опознаёт, и обсуждение не доходило никуда. Плата принята

    обрежется со ссылкой на оригинал), и ссылки ведут на площадку, а не в треды
    мессенджеров. Тело — плоский текст со знаками НГС (`RenderPlatform` +
    `chantext.ToSiteMarkup`): ссылки с подписью в заметке не существует,
    поэтому подпись и адрес печатаются рядом. Публикация идемпотентна по
    `message_targets` (приёмник `platform`, kind `digest`), свежий выпуск
    закрепляется наверху ленты и снимает закреп с прошлого (`PinIssue`; мест
    всего `MaxPinned` = 5). Подписант — участник площадки
    (`digest.author_profile_id`, пусто — анкета владельца из секции `pulpit`):
    `CreateNote` требует автора, а у сводки должен быть тот, с кого спросят.
    Публикация прямо в каналы (`Publish`, сплит серии, per-sink ссылки на
    треды) осталась для работы БЕЗ площадки — без неё заметке взяться неоткуда.
    Планировщик (`RunSchedule`, секция конфига `digest`, дефолт выключен) в
    слот выпуска строит черновик; при настроенной секции `llm` рубрики
    заполняет Claude (`GenerateEditorial`: structured outputs, ответ
    валидируется как правки админа; брак — до трёх попыток с причиной брака в
    промпте, дальше откат на полуручной цикл: вырожденный ответ бывает разовым,
    а ошибку запроса SDK ретраит сам и переспрашивать её незачем), а
    `auto_publish: true` сразу публикует выпуск. Иначе —
    ЛС админу и премодерация через CLI. Пропущенный слот догоняется в
    течение 48 ч, старше — пропускается.
  - `platdigest` — площадка как источник выпуска (`digest.Source` поверх
    Postgres). Отдельный пакет по той же причине, что `platsink`/`platmod`:
    ядро площадки не обязано знать про еженедельную рубрику. Здесь же живут
    правила, которых у зеркала не было: **граница показа** (считается только
    `status = 0` — скрытое модератором или автором в сводку не идёт ни числом,
    ни цитатой) и **аноним остаётся анонимом** (маскирование в SELECT, как в
    ядре; в «новые лица» анонимные заметки не идут вовсе — иначе выпуск
    деанонимизировал бы автора соседством чисел). Планы двух запросов —
    недельного окна и «прошлого человека» — закреплены тестом: без индексов
    миграции 0011 первый читает таблицу на 3 ГБ, а второй — всю историю
    участника со 138 тысячами реплик.
  - `news` — внутренние новости проекта: текст админа уходит постом в каналы
    **мимо сайта** (заметки на love.ngs.ru не появляется, в `notes` ничего не
    пишется). Ввод — `/news` в ЛС командному боту, публикация идемпотентна по
    `message_targets` (kind `news`, ref_id — метка времени), так что при сбое
    одного мессенджера повтор досылает только его. Тред обсуждения новость не
    заводит: в Telegram комментарии всё равно появятся автофорвардом канала,
    но на сайт они не уйдут — `bridge` не опознаёт такое сообщение ни как
    заметку, ни как комментарий.
  - `pulpit` — «амвон»: собственная реплика владельца под каждой новой заметкой
    сайта, и по возможности первая. **Голос — прикольщик** в образе надзирателя
    из будки («Паноптикум» — ник владельца; образ идёт вскользь, иначе через
    неделю это одна и та же шутка, а сам ник живой и подставляется в промпт из
    `currentNick`): работа одна — рассмешить, и меняется форма, а не голос.
    Формы — это **приёмы стендапа** (обманутое ожидание, буквально, правило
    трёх, сравнение не туда, встречный вопрос, сценка, я тоже дурак, не тот
    эксперт), у каждого в промпте свой КОРОТКИЙ образец: длина примера задаёт
    длину ответа вернее инструкции. Набор менялся дважды по отзывам владельца:
    формы вида «неожиданный вывод» просили ЗАМЕТИТЬ смешное и давали наблюдение
    сверху (остроумно и не смешно), формы вида «довести до конца» чинили
    позицию, но по устройству длинные — выходили три абзаца, «слишком много
    нужно прочесть». Отсюда правило устройства: **сетап и панч, панч последним,
    ударное слово в конце, после панча НИЧЕГО** (ни пояснения, ни добивки), одно-два
    предложения, потолок 180 рун и 4 строки. Оттуда же запрет афоризма («дело не
    в X, а в Y», «тревожит не то, что…») — он в валидаторе, а не только в
    промпте. **Реплика пишется в два прохода**: черновик, затем правка
    (`punchUp`, свой системный промпт — вычеркнуть всё после панча, переставить
    ударное слово в конец, резать сетап; НИЧЕГО не добавлять, правленая реплика
    короче черновика); провал правки не отменяет реплику, уходит черновик. Первым голосом был проповедник, и он прожил ровно
    одну реплику: её сняли через 15 минут, владельцу дали сутки запрета (см.
    память `pulpit-first-comment-deleted-ban`) — судили не скорость и не формат,
    а сам тон нравоучения. Отсюда главное правило нового голоса, записанное в
    `quipSystem`: смешным должно быть ПОЛОЖЕНИЕ, а не человек — шутка над
    автором это то же нравоучение, только с ухмылкой. Имя «амвон» осталось за
    МЕСТОМ, с которого говорят (таблицы, конфиг, команда), а не за тем, кто на
    нём стоит. **Красная линия**: под настоящей бедой (смерть, болезнь, насилие,
    суицид) модель возвращает `skip=true`, строка уходит в `skipped:no_joke` — и
    отказ шутить не переспрашивают, в отличие от брака. Служба под общим
    errgroup демона, мессенджер-агностична. **Свой клиент сайта и свой обход
    ленты**: у общего `love.Client` лимитер один на всё, и заметка добиралась
    до зеркала за p90 = 619 с при медианных 164 с до первого чужого
    комментария; колбэк `mirror.Config.OnNewNote` остаётся страховкой, оба
    входа сходятся на `TryClaimPulpitNote`. **Тумблер живёт в БД**
    (`settings['pulpit.enabled']`), а не в конфиге: выключает автоматика (в
    контейнер `/config.json` монтируется снаружи), включает админ кнопкой
    `/pulpit`, и переключение обязано пережить рестарт. Однократность держится
    на состоянии: заметку занимает один INSERT, переход `queued → posting`
    пишется ДО отправки, и застрявшая в `posting` строка не переотправляется
    никогда — её судьбу решает верификация треда (своя реплика опознаётся по
    `AuthorID`). **Предохранитель** (`fuse.go`): запрет писать в «Заметки»
    ничего не убирает с площадки, анкета жива, сайт отвечает 200 — единственный
    след в том, что реплика не появилась в треде. Три таких промаха подряд
    (сбой загрузки, снесённая заметка и **не дошедший POST** промахом НЕ
    считаются) или две вычищенные реплики гасят фичу, диагноз подтверждается
    `love.ProfileControl`, админу уходит ЛС. **Полоса ограничена не только
    числом строк, но и ВРЕМЕНЕМ** (`fuseHorizon`, двое суток) — правило
    оплачено ложным выключением 23.08.2026: строк амвон пишет мало и почти все
    нейтральные (пропуски холодного старта), поэтому тридцать строк окна
    оказались неделей с лишним, и две чистки с разницей в восемь дней сложились
    в одну полосу. **И проверять реплику надо в ТОМ КРАЮ треда, где она лежит**
    (`threadWindow`, `love.FetchOldestComments`): своя реплика в треде самая
    старая — амвон пишет первым, — а обычная страница отдаёт тридцать
    ПОСЛЕДНИХ, и в живом обсуждении своя уезжала за край окна за полчаса, после
    чего перепроверка объявляла её вычищенной. Срабатывало тем вернее, чем
    удачнее была реплика; поверх стоит ещё и **правило охвата** (`pageCovers`,
    то же, что у `modwatch`): пропажа считается удалением только у объекта,
    которого страница вообще МОГЛА показать. Про POST правило оплачено случаем
    17.08.2026: сайт отвечал 500 на любой комментарий (включая чужие, через
    мост), тред при этом читался прекрасно — и «реплики нет» засчиталось
    промахом, хотя причина известна и невиновна. Поэтому сбой отправки пишется
    на строку причиной `send_failed` (состояние остаётся `posting`: сайт мог
    реплику и принять, ответив ошибкой), а `outcomeOf` считает такое отсутствие
    нейтральным — полосу оно не растит и не разрывает. Тот же факт учитывают
    ещё двое: **суточный потолок** не считает строки, про которые верификация
    уже сказала «не долетело» (`PulpitSentSince`; потолок меряет появления в
    тредах, а не попытки — иначе шторм выбирал бы все 8 за час, и к моменту
    выздоровления сайта амвон молчал бы до полуночи), и **пауза на шторм**:
    после двух не дошедших POST подряд новые заметки не берутся десять минут
    (`writePaused`, `actIdle` — строки в БД нет, заметка просто ждёт), потому
    что каждая попытка стоит генерации и правки в Claude. Пауза — экономия, а
    не предохранитель: живёт в памяти, снимается первой же успешной отправкой и
    рук не требует. Стоит она ПОСЛЕ холодного старта в `decide`: иначе шторм в
    момент рестарта оставил бы ленту непомеченной, и по его окончании амвон
    ответил бы разом под всё старьё. **Автовосстановления нет**: срок запрета неизвестен,
    включать обратно — только руками. Ответы тем, кто ответил нам, — по монетке
    (`reply_probability`), и монетка бросается ровно один раз на реплику (PK по
    `pulpit_replies.reply_to_id`), иначе 15 % за десяток тактов превращаются в
    80 %. Обращение «Ник, » подставляет инструмент, а не модель.
    **Что площадка делает с текстом комментария** (замер 15.08.2026 по 61 177
    живым комментариям; знание нужно не только амвону): переносы строк работают
    — сайт делает `nl2br`, поэтому пустая строка между абзацами держится;
    пробелы схлопываются, и отступ живёт **только через NBSP** (его подставляет
    `normalize`, модель про это не знает — иначе начнёт сыпать U+00A0 в
    середину фраз); эмодзи сайт подменяет картинками `<img class="emojione">`;
    **BB-коды больше не работают** — `[b]`/`[i]` печатаются буквально (на 61 177
    комментариев ноль), HTML сайт экранирует сам; префикс обращения он выделяет
    жирным сам, и жирный для этого не нужен; длинное тире и кавычки-ёлочки есть
    у полупроцента комментариев, то есть выдают машину — `normalize` меняет их
    на дефис и обычную кавычку.
  - `morning` — утренняя заметка: одна «доброе утро» в сутки на love.ngs.ru от
    анкеты владельца. Публикуется НА НГС (решение владельца 24.08.2026), потому
    что оттуда зеркало разносит её и на площадку, и в оба канала: текст
    существует один раз, у него один адрес и один тред, а в ленте НГС утро
    остаётся там, где ещё живут люди. Однократность держит ПЕРВИЧНЫЙ КЛЮЧ по
    дню в `morning_notes` (схема v11): ни второй прогон планировщика, ни
    рестарт, ни ручной догон второй заметки не дадут, а строка заводится сразу
    в `posting` — ДО отправки, потому что `love.Client.PostNote` возвращает одну
    лишь ошибку без id, и «сайт принял, но ответил сбоем» неотличимо от «не
    принял». **Чужое утро сильнее нашего**: перед публикацией живая лента НГС
    проверяется на приветствие, написанное кем-то другим сегодня (закрытый
    список зачинов по первым ШЕСТИ словам тела — мерка в знаках ошибалась на
    рассказе «…он сказал мне доброе утро»), и если оно есть — служба молчит и
    пишет владельцу. Тем же списком проверяется и СВОЯ заметка: не начинается с
    приветствия — брак, потому что ритуал узнаётся по первым двум словам.
    **Вид заметки снят с живого образца** (t3h.ru/n/313059, утро того же дня,
    написанное человеком): приветствие со значком, день недели и число, дальше
    поводы КАЖДЫЙ со своей строки и со своим эмодзи, в конце вопрос читателю.
    Не перенесена оттуда только простыня пожеланий — владелец оговорил
    «лаконичнее». Потолок длины его же решением ходил 1200 → 900 → **1800**
    знаков; на второй половине пути он перевалил рубеж `web.longBodyRunes`
    (1500), за которым лента площадки сворачивает текст показом, — и это
    записано как цена, а не как недосмотр. Потолок при этом не цель: заметка
    пишется в ДВА прохода, и второй (`punchUp`, тот же приём, что у амвона)
    заметку РЕЖЕТ — вычёркивает всё после панча, ставит ударное слово в конец
    строки, срезает разгон; провал правки её не отменяет, уходит черновик. Эмодзи здесь не украшение, а
    ИНТОНАЦИЯ (ни курсива, ни голоса у текста на сайте нет), поэтому их пол
    (`minEmoji`) стоит в валидаторе, а не только в промпте. Юмор описан
    ПРИЁМАМИ с короткими образцами, а не словом «юмор»: тот же урок, что у
    амвона, — «с юмором» модель понимает как бодрый тон.
    Валидатор здесь строже, чем у амвона, и это возможно ровно потому, что
    факты подаём мы: дата и день недели В ПРИВЕТСТВИИ обязаны быть
    сегодняшними, любой год в тексте — найтись среди поданных поводов, а номер
    повода в поле `used` — подтвердиться словом из его названия в самом тексте.
    Строго проверяется именно приветствие: «до субботы далеко» — шутка про
    календарь, а не ложь про сегодня (сплошной запрет забраковал три попытки
    подряд на живом прогоне 24.08.2026, и заметка не вышла бы вовсе), а ложью
    чужой день становится рядом со словом «сегодня» — вот это и ловится. Предохранитель
    как у амвона в уменьшенном виде: заметку ищут в ленте по автору и началу
    текста, два промаха подряд в пределах 48 часов гасят тумблер с ЛС владельцу,
    а не дошедший POST промахом НЕ считается (17.08.2026 сайт отвечал 500 на всё
    подряд). Вчерашняя заметка проверяется ПОПУТНО, в той же ленте, перед
    публикацией сегодняшней — отдельного обхода это не стоит; правило охвата
    обязательно, за нижним краем ленты о заметке судить нельзя.
    **В промпт не уходит ни строки, написанной участниками** — модель здесь
    Claude, то есть запрос покидает Россию, а согласия площадки обещают
    обратное (тем же доводом модерация уехала на Yandex, см. `rullm`); рубрика
    «а вчера у нас обсуждали…» потребовала бы новой редакции согласий и
    повторной подписи ВСЕХ.

  - `narod` — жители площадки: персонажи, реплики которых пишет модель (эпик

    **Ядро не импортирует ни `platform`, ни `archive`**, и это не вкус: без
    первого тот же оркестратор гоняется реплеем архивных тредов на машине
    разработчика, где Postgres не поднят вовсе (площадка приходит интерфейсом
    `Stage`); без второго карточка персонажа остаётся ДОКУМЕНТОМ-контрактом, а
    не проекцией внутренностей архива — разъехавшись, они разъехались бы молча.
    Собирает карточку из архивной карты письма `cmd/lovegw` (он и так знает оба
    мира), а полноту переноса стережёт парный тест.
    **Карточек два сорта, и различие правовое.** СЛЕПОК — портрет реального
    участника архива с его ником и образцами писем; живёт только в офлайн-
    калибровке (реплей старой заметки со сверкой с оригиналом) и наружу не
    выходит никогда: это была бы имперсонация живого человека на открытой
    площадке. КОМПОЗИТ — житель: числовые цели смешаны из нескольких доноров,
    дословных образцов нет вовсе, ник и биографию пишет владелец. Правило «в
    live выходят только композиты» живёт ДВАЖДЫ (`CheckLive` и проверка
    конфигурации), потому что цена ошибки не поломка, а публикация.
    Каталог — данные: добавить жителя значит положить файл, список нигде в коде
    не перечислен (DoD брифа, проверяется тестом). Живут карточки в `data/`
    (репозиторий публичный, а они выведены из писем живых людей), марку
    `do_not_publish` ставит конструктор — пути породить карточку без марки нет.
    **Ошибки в реплику вносит ПОСТПРОЦЕССОР, а не модель** (`InjectErrors`,
    детерминированно от зерна): просьбу «пиши с ошибками» модель исполняет
    карикатурой и каждый раз по-новому, а у человека ошибка одна и та же
    годами — он не знает, что это ошибка. Место в конвейере строгое: генерация →
    `sitetext.Normalize` → евалы → внесение ошибок → публикация (раньше евалов
    нельзя — `Normalize` чинит ровно то, что мы вносим).
    Состояние мира — своя SQLite (`data/narod.db`, схема в `worldschema.sql`):
    журнал реплик, граф отношений, эпизоды-«счёты», брошенные монетки, отложенные
    намерения. Отдельная база потому, что у каждого калибровочного прогона свой
    мир, а рантайм-тумблер живёт не здесь, а в `settings` боевой базы —
    выключатель обязан работать и тогда, когда мир не открылся.
    Замеры под неё живут в `archive`: `voice_errs.go` (характерные ошибки —
    сравнительно с нормой корпуса, иначе общая манера эпохи запишется человеку в
    ошибки), `voice_latency.go` (через сколько отзывается; без него жители
    сбегаются в тред за минуту, и это выдаёт машину раньше текста),
    `decay.go` (вероятность продолжения после тишины — иначе разговор либо
    обрывается на второй реплике, либо не кончается никогда).
    **Ники соседей — не слова автора** (замер 27.08.2026): у собеседницы,
    обращающейся по имени в 72 % реплик, характерными словами вышли ники соседей
    по треду, а список уходит в промпт — персонаж начал бы звать людей их
    настоящими никами. Сеет их `SiteNickTokens`: именно СЛОВА (составной «Хатуль
    мадан» целым ником не ловится) и именно с ИСТОРИЕЙ (`users.name` хранит
    только текущий, а обращались тем, что был тогда).
    Команды: `narod card <p<id>|u<id>>` — слепок донора, `narod compose
    <рецепт> [-verify]` — житель из слепков плюс сторож близости к донорам
    (перекос весов, единственный донор, чужое слово в словаре, совпадение ника),
    `narod show` — карточка так, как её увидит модель (вместе с блоком настроения:
    команда обещает показать её РОВНО так, как видит модель, а больное место и
    запрет мата живут не в брифе), `narod world` — состояние мира, `narod enroll`
    — анкета жителя на площадке, `narod seed` — заметка-песочница,
    `narod portrait` — английский промпт для генерации АВАТАРА (`portrait.go`:
    камеру считает жребий по слугу, внешность спрашивают у модели, а ник и
    `Frustration` не уходят ей никогда — запрос собирается из `portraitFacts`,
    а не из `Bio`).
    **КУБИК ЖИВЁТ ЗДЕСЬ** (`decide.go`), а не в калибровочном харнессе, хотя
    вырос именно там: на калибровке и в бою обязана играть ровно одна формула, и
    `narodsim` берёт её псевдонимами — расхождение невозможно физически, тип один
    и тот же. Переехал он 29.08.2026 вместе со службой: боевой оркестратор не
    вправе импортировать реплей (тот тянет архив), а формула нужна обоим.
    **Пайплайн боевой генерации СВОЙ** (`gen.go`), отдельный от калибровочного, и
    это не дубль: калибровочный меряет ГОЛОС через атрибутор архива, а для этого
    нужен archive.db на 4,7 ГБ, которого на хосте площадки нет и не будет.
    Разделение труда: голос меряется ОДИН РАЗ, на калибровке, и вшивается в
    карточку числами; в бою остаются проверки, которым архив не нужен — форма,
    приметы машины, стоп-лист имён, мат. Порядок строгий: генерация →
    `sitetext.Normalize` → евалы → `InjectErrors` → публикация, и после инъекции
    только неоткатывающие проверки. `skip` обязателен и част.
    **Служба** (`service.go`) — два такта, `Stage` интерфейсом, режимы live и
    dry-run; журнал ДО публикации (реплика на площадке без записи в журнале делает
    жителя противоречащим себе, и починить это потом нечем).
  - `platnarod` — площадка как СЦЕНА (реализация `narod.Stage` поверх Postgres),
    по образцу `platsink`/`platdigest`. Читает ТОЛЬКО песочницы — не ради
    опрятности, а как границу ответственности: житель не должен видеть обычных
    заметок, иначе однажды в них и заговорит; это второй забор к ядерному
    правилу. Тред отдаёт ПО ВРЕМЕНИ, а не обходом дерева: кубику нужен номер
    реплики по порядку разговора, потому что замер отклика снят именно по нему.
    Публикует ЧЕРЕЗ ЯДРО (`CreateComment`), а не INSERT'ом: реплика жителя обязана
    пройти всё то же — право писать, потолки, замок, гейт песочницы, очередь
    модерации той же транзакцией и событие шины.
  - `profanity` — словарь канонического мата, ЛИСТОВОЙ и без зависимостей.
    Выделен из `platmod` 29.08.2026, потому что список нужен ДВОИМ, у которых
    общего пакета нет и быть не может: автомату — чтобы СУДИТЬ чужую реплику,
    народу — чтобы НЕ ПИСАТЬ. Два словаря мата, расходящиеся молча, дали бы
    площадку, на которой запрещено не то, что она гасит.
  - `sitetext` — приведение НАШЕГО текста к виду, который не испортит НГС
    (типографика в дефис и прямые кавычки, NBSP на месте отступов, схлопывание
    пустых строк), и приметы генерации, которым до сайта доезжать нельзя
    (`<thinking>`, обрывки хода мысли, слово из двух алфавитов, фигурная
    скобка, BB-коды, HTML). Выделен из `pulpit` 24.08.2026, когда те же правила
    понадобились утренней заметке: правила задаёт САЙТ, а не жанр реплики, и
    две их копии разошлись бы молча — сайт не отвечает отказом на длинное тире,
    он просто печатает его в нашем тексте.
  - `chantext` — общее HTML-подмножество каналов (`<b>`, `<i>`, `<a href>`):
    валидация, длина (видимая в рунах, `UTF16Len`/`VisibleUTF16Len` — в мере
    самих мессенджеров) и обрезка без порчи разметки, бюджет сообщения 3500
    рун. Здесь же `FromSiteMarkup` — знаки НГС из текста площадки в разметку
    канала: тем же набором, что показывает морда, но в том, что понимают ОБА
    мессенджера. Общий для `digest`, `news` и `platout`.
  - `asr` — автораспознавание голосовых в тредах: голосовое (и кружок) в
    группе обсуждения — а также запощенное в канал заметок, оно приходит
    автофорвардом (квота таких пишется на id канала) — расшифровывается и
    уходит реплаем на исходное сообщение; что делать с текстом, решает автор
    (ни кнопок, ни состояния). **Только Telegram**, и MAX не подключён
    СОЗНАТЕЛЬНО: там расшифровка встроена в клиент (кнопка «Т» и на канале, и
    в чатах, без всякой подписки), а в Telegram она только по Premium — то
    есть в MAX это был бы оплаченный дубль бесплатного. Не «доделывать»
    MAX-сторону. Побочные факты на случай пересмотра: у аудио-вложений MAX нет
    длительности (только url и token), то есть потолок и квота в секундах без
    скачивания файла не считаются, а нативная расшифровка приезжает в поле
    `transcription` схемы Bot API, которое SDK v2.2.4 теряет при разборе.
    Пакет messenger-agnostic (транспорт — замыкания `Fetch`/`Reply` в
    `asr.Job`), так что подключить мессенджер без своей расшифровки дёшево.
    Телеграм-сторона — `tgx.VoiceHandler` + `Mirror.DownloadFile`/`ReplyText`
    (хук ставится `SetVoiceHandler` до старта поллинга).
    `Service` — воркер-пул с очередью (хендлер апдейта только ставит задачу,
    переполнение — drop + лог) и защитой от расходов: потолок длительности,
    суточная квота в секундах на пользователя и кэш расшифровок по
    `file_unique_id` (таблицы `asr_transcripts`/`asr_usage`, миграция v6) —
    пересланное голосовое не оплачивается повторно. `Transcriber` — клиент
    Nexara (OpenAI Whisper-совместимый API, ретраи с backoff, `ErrAuth` на
    401/402 → разовый алерт админу); провайдер российский, поэтому идёт
    напрямую, мимо `telegram_proxy`. `Converter` — ffmpeg пайпом stdin→stdout
    (в образе статический бинарник, путь в `LOVEGW_ASR_FFMPEG`). При любом
    сбое в треде тишина и запись в лог; единственное сообщение об отказе —
    превышенный потолок длительности. `asr.enabled=false` — гейт как раньше.
  - `llm` — онлайн-клиент Claude API (официальный `anthropic-sdk-go`):
    `GenerateJSON` со structured outputs, дефолтная модель `claude-opus-5`,
    обработка refusal/обрыва; транспорт — `tgx.ProxyTransport(telegram_proxy)`
    (api.anthropic.com недоступен с RU-IP, ходим через тот же прокси, что и
    Bot API). Ключ — `llm.api_key` / env `LOVEGW_LLM_KEY`. Общий клиент для
    дайджеста и будущего поиска (C4). **Автомат модерации на нём больше не
    работает** — см. `rullm` ниже; тот же довод накрывает и дайджест (после D7
    LLM-рубрики цитируют реплики площадки), это открытый вопрос к владельцу.
    **Расход считает сам клиент** (`Usage`: вызовы, вход, выход и отдельно
    записанное/прочитанное из кэша) — счёт приходит помесячно и общий на всё, а
    «во что обошёлся ЭТОТ прогон» спрашивают сразу после него: калибровочный
    прогон эмуляции стоит десятки долларов, и решать по нему, брать ли модель
    дешевле, можно только зная цифру. Считается ДО разбора ответа — отказ
    классификатора и обрыв по бюджету оплачены так же, как удача. В лог идёт
    строка на запрос уровнем Debug (подробность на разбор, а не событие).
    **Кэш-точка на системном блоке** (`Config.CacheSystem`) по умолчанию
    ВЫКЛЮЧЕНА, и это арифметика, а не осторожность: запись в кэш стоит 1,25
    цены входа, чтение — 0,1, то есть окупается со ВТОРОГО запроса, а
    одиночному вызову (рубрика дайджеста, утренняя заметка) второго не будет
    никогда. Включена там, где повтор ДОКАЗАН устройством прогона, — у
    `personas voice`: раунды идут встык и с одним и тем же системным промптом
    (`systemFor` зависит от режима, а не от раунда). Амвону не поставлена
    намеренно: он пишет под разные заметки с промежутком в минуты и часы, и
    пятиминутный кэш до второго вызова обычно не доживает. Короткий префикс (у
    `claude-opus-5` граница 512 токенов) не кэшируется молча — без ошибки и без
    наценки.
  - `rullm` — тот же контракт `GenerateJSON`, но поверх **Yandex AI Studio**
    (OpenAI-совместимый `llm.api.cloud.yandex.net/v1`, ключ заголовком
    `Api-Key`, модель как URI `gpt://<folder_id>/<model>`). Заведён 23.08.2026
    не ради цены: в модель уходит текст участников, а согласие обещает не
    вывозить данные за пределы России, — поэтому переезд был условием того,
    чтобы Ш7 вообще можно было включить. **Прокси здесь нет намеренно**:
    российский сервис доступен с RU-IP прямо, как love.ngs.ru, — и модерация
    перестаёт зависеть от прокси, который держится ради Telegram. `strict: true`
    в схеме стоит потому, что проба на живом API показала: AI Studio его
    соблюдает (enum категорий, `additionalProperties: false`, номер на каждую
    строку пачки) — цикл валидации ответа не понадобился. Повтор только на 429 и
    5xx: у вызывающего свои три попытки на строку, и отказ по ключу их бы сжёг.
    Запрос несёт **зерно выборки** (`seed`, константа): одной температуры 0 для
    повторяемости не хватает, а вердикт, меняющийся от прогона к прогону, не
    значит ничего — ни объяснить его автору, ни повторить на стенде нельзя.
    Дефолт — `yandexgpt-5.1/latest`, и выбран он ПРОГОНОМ СТЕНДА по десяти
    моделям (23.08.2026, живой тред): 17 с против 38–318 у остальных, вдвое
    меньше автоскрытий, чем у прежнего дефолта `yandexgpt-lite` (тот выбирался
    по пачке из десятка строк — замер был слишком мал). Решило же не место в
    таблице, а воспроизводимость: модели С РАЗМЫШЛЕНИЯМИ (`gpt-oss-120b` кладёт
    в ответ `reasoning_content`) плавают даже с зерном — пять прогонов по одним
    и тем же 115 репликам дали пять разных наборов скрытого. Правило на будущее:
    модель классификатора выбирается прогоном стенда НЕСКОЛЬКО РАЗ подряд,
    одиночный прогон не отличает придирчивость от разброса. И цену смотреть
    ЗАОДНО со скоростью: 5.1 из линейки Pro и стоит 0,80 ₽/1k против 0,20 у
    Lite — на бою это копейки (около сотни публикаций в сутки), но повторные
    прогоны всей очереди на ней разорительны.
  - `talks` — личная переписка сайта: один поллер под общим клиентом сайта
    фанит входящие ЛС в личку включённых мессенджеров, ответы реплаем/командой
    уходят на сайт. **Читаем только с согласия человека** (`delivery.go`,
    `store.ScanAllowed`): поллер ходит по сайту под его кукой, а
    `getMessagesHistory` помечает сообщения прочитанными (собеседник видит
    «просмотрено») и всё это время держит человека онлайн — не читать бота
    достаточным отказом не является, поэтому без согласия сайт-аккаунт не
    трогают вовсе (ни списка диалогов, ни истории, ни `SiteIdentity`). Гейт
    стоит в `plan()` **после** `live()`: отсеянного админом не спрашивают.
    Обратное направление (`send.go`) согласием не закрыто намеренно —
    отправляет человек сам, и на сайте от этого ничего не помечается.
    **Получатель у сайт-аккаунта ровно один**: то же чтение истории гасит
    непрочитанное, и второй сессии достанется пустота. Сессии связывает
    `sessions.site_passport_id` (нет — поллер снимает его сам на первом обходе,
    одна попытка за запуск: старые сессии его не хранят). Правило выбора —
    `store.PickDelivery`: явный выбор человека сильнее всего, пока его нет —
    самый свежий вход. **Вопрос человеку один, а не два**: кнопка «читать и
    присылать сюда» — это сразу и согласие, и выбор мессенджера, поэтому
    `Config.AskScan` (замыкание на `dmbot`, у поллера кнопок нет) заменил собой
    прежний вопрос «куда носить»; спрашивают один раз на сессию, отметка живёт в
    `talks_asked_at`, неотвеченный вопрос оставляет переписку непрочитанной.
    Недостижимость (заблокировал бота) снимает сессию с обхода только пока
    выбора не было: у выбравшего это «ЛС не доставляются», а не «отнесём в
    другой мессенджер». `talks.exclude_users` в конфиге — запрет админа поверх
    согласия: попавшего в список даже не спрашивают.
  - `dmbot` — РюмкинЪ; messenger-agnostic dialog engine `Logic` (state in
    `dialog_states`, transport behind an interface — Telegram wrapper here,
    MAX goes through `maxx.Mirror`). Commands: `/login`, `/add_note`,
    `/add_anonymous_note`, `/status`, `/subscribe`, `/unsubscribe`, `/mysubs`.
    Плюс `/delivery` (`delivery.go`) — личные сообщения сайта: читать ли их и
    куда носить. Три состояния экрана: чтения нет («📬 Читать и присылать
    сюда»), читаем и носим сюда («🚫 Не читать мою переписку»), читаем и носим
    в другой мессенджер (плюс «📬 Присылать сюда»). Текст в каждом состоянии
    называет цену — сайт помечает ЛС прочитанными и показывает человека в сети.
    Кнопки «🔕 Не присылать сюда» **больше нет**: согласие даётся кнопкой
    «читать и присылать сюда», а она гасит доставку остальным сессиям аккаунта,
    — значит отказ от доставки гасил бы последнюю живую и останавливал обход
    целиком, то есть делал ровно то же, что «не читать», только называясь
    иначе. Именно эта двусмысленность и была причиной завести отдельное
    согласие. Глагол `argDeliveryOff` при этом жив: кнопки прошлых релизов ещё
    висят в чатах. Выбор мессенджера исключающий, второй гасит
    `store.SetTalksDelivery` одной транзакцией по паспорту сайт-аккаунта — она
    же проставляет согласие. Команда есть и у бота переписки — ЛС доставляет
    именно он; тем же сообщением и теми же кнопками спрашивают согласия поллер
    (`AskTalksScan`) и сам `/login` — момент, когда человек отдал боту доступ к
    аккаунту, для этого вопроса и есть самый уместный.
    Плюс `/profile` (`profile.go`) — своя анкета на сайте: заблокировать и
    вернуть. Состояние **не хранится в БД** (анкету блокируют и на самом сайте,
    флаг бы соврал) — и показ, и применение читают его живьём, а после действия
    перечитывают: сайт отвечает 200 и на отказ, так что «состояние не
    изменилось» — единственный надёжный признак неудачи. Кнопка на экране —
    ровно та, что стоит на сайте: подпись и поле формы приезжают со страницы
    настроек (`love.ProfileControl`), а они у сайта в двух состояниях разные.
    Блокировка идёт через подтверждение, разблокировка — сразу. Способность
    необязательная (`SiteProfile`, type-assertion по образцу `SiteIdentifier`):
    нет её у клиента — нет и команды ни в меню, ни в `/start`. У бота переписки
    команды нет: сайт ему не передаётся.
    Плюс админская `/news` (`SetNews`, пакет `news`): текст → превью →
    подтверждение кнопкой «Опубликовать» (слово «да» осталось запасным путём) →
    пост в каналы. Она видна только
    `messengers.<m>.admin_user_id`, в `/start` не значится, черновик ждёт
    подтверждения прямо в `dialog_states` (`news:<id>\n<html>`) и переживает
    рестарт; при сбое канала состояние остаётся под повтор.
    Плюс админская `/pulpit` (`pulpit.go`, `SetPulpit`): состояние амвона,
    счётчики, последняя реплика со ссылкой на анкор и кнопка включения/
    выключения. Так же не в меню команд и не в `/start`. Пакет `pulpit` отсюда
    **не импортируется**: ручке нужны только «переключить» и «показать отчёт»
    (интерфейс `PulpitControl`), а отчёт собирает сама служба — иначе
    диалоговому ядру пришлось бы знать её состояния и предохранитель.
    Выключение мгновенное, включение после срабатывания предохранителя — через
    подтверждение с текстом причины (образец `askProfileBlock`).
    Кнопки (`callback.go`, общие типы в листовом пакете `kbd`): `/start` даёт
    главное меню, `/add_note` спрашивает авторство (`await_note_kind`),
    `/mysubs` — список с «✖» на каждую подписку и «Добавить» (слово спрашивается
    диалогом, `await_subscription`: в payload оно не влезет, поэтому кнопка
    несёт id строки `subscriptions`), `/talks` — кнопки «открыть» с
    перелистыванием по 8. У каждого приглашения есть «Отмена». Меню команд
    мессенджера публикует `PublishCommands` на старте демона (Telegram
    `setMyCommands`, MAX `PATCH /me/commands`) — после подключения talks-роутера,
    от него зависит, попадут ли в список `/talks`, `/talk` и `/delivery`;
    админская `/news` в меню не значится. Правило правки сообщений: главное меню — пульт, его не
    затирают никогда (список диалогов из меню приходит новым сообщением, а
    перелистывание уже правит его), одноразовый выбор превращается в
    приглашение, список подписок перерисовывается на месте.
    Подписка по заметке (эпик B) заводится из-под поста канала; вход несёт id
    заметки, а вид («✍️ На автора» / «💬 На эту заметку») спрашивается уже в
    ЛС — `offerSubscribe`, единая дорога для трёх входов. В Telegram это
    **ссылка в подвале поста**, `t.me/<РюмкинЪ>?start=sub_<id>`
    (`kbd.StartSub`, разбор в ветке `/start`). Deep-link, а не callback: постер
    и РюмкинЪ — разные боты, постер в ЛС писать не может, а переход заодно
    стартует бота у того, кто его не запускал. И **именно ссылка, а не
    inline-кнопка**: своя клавиатура у поста вытесняет родную кнопку
    «Комментарии» — Telegram рисует их в одном месте и показывает что-то одно,
    а вход в обсуждение нужнее (проверено на живом канале 11.08.2026). В MAX
    бот один и родных комментариев у канала нет, поэтому там callback-кнопка
    рядом с «💬 Обсудить». У анонимной заметки вход есть (подписка на её
    комментарии осмысленна), но вариант «на автора» не предлагается.
    Нажатия разбирает `HandleCallback` —
    зеркало `HandleText`: таблица глаголов (что ответить, кому доступен, где
    доступен, что делает), payload `1:<verb>[:<arg>]` только ASCII и не длиннее
    64 байт (предел Telegram), ответ мессенджеру всегда в роутере и **до**
    работы — публикация в каналы идёт секунды, за это время нажатие протухнет.
    Свойство `public` (единственный такой глагол — `kbd.VerbSubscribe`)
    разрешает нажатие вне диалога; его спрашивает `maxx` через
    `AllowsOutsideDialog`, и там же гасит mid — сообщение под кнопкой это чужой
    пост канала, править его нельзя. Кнопка «🔕 Отписаться» в ЛС-уведомлении
    (`UnsubKeyboard`, глагол `unsub1`) отвечает только тостом и сообщение не
    правит: текст со ссылкой ещё нужен, а в MAX снять одну клавиатуру, не
    переписав тело целиком, нечем.
    **Идемпотентность держится на `dialog_states`**, отдельной таблицы
    обработанных нажатий нет и не нужно: у нажатия нет побочного эффекта,
    который нельзя вывести из состояния, а дедуп по payload сломал бы штатный
    повтор `/news` после сбоя канала. Единственная настоящая гонка —
    параллельные апдейты Telegram (`go-telegram/bot` запускает обработчик в
    горутине) на read-then-write внутри `news.Publish`; закрыта мьютексом по
    пользователю (`lockUser`), тест на два одновременных нажатия это стережёт.
    `NewTalksLogic` is the second role — a talks-only bot (`/talks`, `/talk`,
    `/delivery`, reply→site delivery, admin alerts) that keeps its own `dialog_states`
    namespace (`<messenger>:talks`) so a stuck `pm:<id>` cannot break the
    command bot; sessions, subscriptions and peers stay keyed by messenger, so
    it sees the login made in the command bot. The command bot keeps a
    reply-only router (`SetReplyRouter`) for DMs it delivered before the split.
  - `modwatch` — наблюдатель за действиями модерации (своя `modwatch.db`, схема
    v1). Поля «модератор» на сайте нет, а по речи опознаются только болтливые;
    действие же видно всегда, но архив его не хранит — это снимок уцелевшего.
    Сборщик опрашивает ленту и свежие треды и пишет ЧТО и КОГДА произошло
    (`events`: note_gone / note_returned / comment_gone / image_added /
    comments_closed / note_published / nick_changed) вместе с окном неопределённости
    `[prev_seen, detected]` и контекстом действия: возраст объекта, тишина в
    треде перед ним и число известных реплик (миграция v2 + расчёт на лету для
    старых записей). Контекст нужен, чтобы отделять руку от автоматики:
    закрытие комментариев сайт ставит и сам, но проверка показала, что ни
    фиксированного таймера, ни порога по числу реплик нет (наблюдённые закрытия
    на 3ч50м/181 реплике и 6ч55м/389; в архиве доля закрытых 75–85 % во всех
    корзинах), поэтому вид не выкидывается, а фильтруется `-age-min/-age-max`. Ключевое правило детекции — **охват**: исчезновение
    считается удалением только у объекта с id больше самого старого из
    присутствующих сейчас, иначе уход за нижний край страницы был бы принят за
    снос. **Публикация на сайте устроена так:** простой текст выходит сразу, а
    заметка с картинкой — только после премодерации; если автор дописал картинку
    к уже опубликованному тексту, заметка уезжает на проверку, ПРОПАДАЯ из ленты,
    и возвращается одобренной (`note_returned`). Поэтому `note_gone` с
    последующим возвратом — не действие модератора, и `Analyze` такие события
    отбрасывает (`dropReturned`), а `image_added` — действие АВТОРА, из набора
    `moderationKinds` исключено. `Analyze` — case-control: для каждого события окно присутствия
    сравнивается с тем же окном, сдвинутым на целые сутки (тот же час — та же
    посещаемость), поправка на «активные всегда онлайн» встроена в конструкцию;
    дисперсия считается по сглаженной доле, иначе «был только при действиях» дал
    бы z = 0. Единица наблюдения — **окказия** (заметка + такт опроса), а не
    событие: чистку треда наблюдатель видит разом и штампует всем пропажам один
    `detected_at`, поэтому независимыми их считать нельзя (иначе z растёт как
    √N — на 11.08.2026 это 53 события в 33 окказиях). Контрольные окна
    подбираются не только по часу суток, но и **по числу реплик**: комментарий
    удаляют в живом треде, и без выравнивания окна действий вдвое люднее
    контрольных, то есть нулевая гипотеза уезжает с ×1 на ×1.9. Метод слеп к
    модератору, который не комментирует; верхушку z нельзя читать как список
    имён — порог не откалиброван на множественную проверку, а анкеты, живущие
    короче периода наблюдения, не попадают в контроль и получают значимость
    даром (см. память `modwatch-report-batch-artifact`).
    **Присутствие** (`activity.go` + `silence.go`, схема v4) — второй, отдельный
    от событий канал. Запрет писать в «Заметки» ничего не убирает с площадки и
    потому в `events` невидим, а это самое частое наказание; зато в анкете есть
    `last_activity` (`love.Activity`, мобильный vhost). Поле живое, наш
    анонимный просмотр его НЕ двигает (контроль: анкеты, прочитанные трижды,
    остались со старыми отметками) и «Приватность» его не прячет — под ней сайт
    лишь показывает людям другое поле, `last_activity_for_hide`. Правило
    `ClassifySilence` решает по СВЕЖЕСТИ последнего захода (`Fresh`, сутки), а
    не по хвосту после последней реплики: перестал заходить — «ушёл», а если
    перед этим ещё ходил (`After` ≥ `Margin`) — «ушёл позже». Первая версия
    смотрела как раз на хвост и записала в жертвы Игоря u1514601, который просто
    ушёл на полдня позже, чем замолчал. **Но свежей отметки мало**: у
    вернувшегося из отъезда она такая же, поэтому «запрет?» ставится, только
    если след покрывает `MinSeenDays` (2) РАЗНЫХ суток молчания, иначе «мало
    данных». Это цена ошибки с Актрисой u1431505: её признали закрытой по одному
    снимку, а она вернулась в тот же вечер, 13.08 в 21:27 — снимок поймал первый
    день на площадке после отсутствия (сутки считаются от последней реплики,
    `seenDays`, — так не нужен пояс площадки). Третий порог — `MinMissed`:
    сколько реплик человек не написал против своего же темпа, иначе список
    забивают редкие комментаторы (темп средний за окно, поэтому у затухавшего
    постепенно он завышен — наказание выглядит обрывом на полном ходу).
    Отличить запрет от «читаю, но не пишу» отчёт не может; доказывает
    возвращение — наказание кончается ровно на сроке. `ActivityWatcher` обходит круг активных
    комментаторов (набирается `RosterSource` — по зеркалу, реже по своим
    репликам) порциями по очереди `checked_at`, анонимно и строгим темпом
    (клиент как у `personas gender`: мобильный vhost, jar, джиттер); сбой такта
    его обрывает — 403 приходит волной. Таблица `activity` копит отметки у себя,
    потому что сайт хранит только последнее действие: это заодно даёт
    присутствие тех, кто ничего не пишет, — ту самую слепоту `Analyze`.
  - `secret` — шифрование значений на диске (AES-256-GCM из stdlib, формат
    `enc:v1:<base64 nonce‖ciphertext>`). Ключ живёт ВНЕ базы (env
    `LOVEGW_SECRET_KEY` / `secret_key_file`) — в этом весь смысл: в копии БД его
    нет. Защищает копии и бэкапы (боевую базу бэкапят `sqlite3 .backup`, и её
    копия уезжает на рабочую машину), а не хост, где ключ лежит рядом. AAD
    привязывает шифротекст к строке (`sessions:telegram:<id>`,
    `accounts:<имя>`), поэтому переставить чужую сессию в свою строку нельзя.
    Значение без префикса читается как есть — так живут записи, сделанные до
    включения шифрования. Точек шифрования ровно две:
    `store.SessionCookies` и `store.UpsertSession`; всё остальное (bridge,
    dmbot, talks, profile) ходит через них и о шифровании не знает.
  - `acct` — сервисные аккаунты сайта: технические сессии в своей `accounts.db`
    для обходов под авторизацией и редких ручных комментариев. **Не в
    `sessions`** намеренно: `store.TalksOwners` берёт ВСЕ валидные сессии без
    разбора мессенджера, и служебная строка немедленно попала бы в обход ЛС,
    начав гасить непрочитанное на сайте. Отдельный файл к тому же можно
    принести на рабочую машину без боевой БД, где лежат живые куки
    пользователей. Формат кук — общий с `sessions` (`love.CookiesToJSON`),
    строка остаётся взаимозаменяемой.
  - `legacy` — one-shot importer of old JSON state.
- Reply→site and note-post reuse saved cookie sessions; a 401/403 marks the
  session invalid and DMs the user to re-`/login`. Admin alerts require
  `admin_tg_user_id` set in config.

  каждую публикацию, а очередь модератора живёт и без него; `provider` — чей API
  увидит тексты участников, по умолчанию **`yandex`** (`api_key` — env
  `LOVEGW_MODERATION_KEY`, `folder_id` — каталог Yandex Cloud, секретом не
  является), и `anthropic` оставлен только ради стенда: боевой выбор задан
  согласием, а не вкусом; `model` — смысл зависит от провайдера
  (`yandexgpt-5.1/latest` либо `claude-haiku-4-5`), и `effort` обязан быть ПУСТ
  у обоих (Haiku 4.5 отвечает на него ошибкой запроса, у Яндекса его нет вовсе);
  имя модели Anthropic при `provider: yandex` — отказ на сборке клиента, а не
  невнятный отказ AI Studio в бою; `daily_requests` считает ЗАПРОСЫ, а не
  публикации, — это прямая единица счёта денег. Инструменты модератора от секции
  не зависят вовсе: они часть ядра и морды. Подсекция `bus` — шина событий (эпик F):
  только `interval_s` и `batch`, то есть темп, а не поведение; гейта `enabled`
  у неё НЕТ намеренно — она ничего не тратит, а выключенная означала бы, что
  площадка молча перестала говорить людям, что им ответили).
  The `messengers`
  section gates which sinks run (`max` / `telegram`, each with `enabled`);
  legacy flat `mirror_bot`/`dm_bot` configs still load as telegram-only.
- Bot roles per messenger: everything that predates talks stays on the original
  bots (Telegram poster + РюмкинЪ, MAX mirror bot), and `talks_token` moves only
  the site's personal correspondence — plus admin alerts — to a separate bot.
  Without `talks_token` nothing changes: talks runs on РюмкинЪ / the MAX mirror bot.
- Network split: love.ngs.ru needs a Russian IP (403 otherwise), but Telegram's
  API is blocked from inside Russia. A box that reaches both needs nothing
  special. For split networks, `telegram_proxy` in config
  (`http`/`https`/`socks5://…`) routes only the Bot API through a proxy while the
  site goes direct — built in `internal/tgx/proxy.go`, wired into both bots and
  `doctor`.

## Secrets warning

Real credentials live only in the local working copy: bot tokens in
`go/config.json`; live user session cookies in the SQLite DB (`data/`,
`sessions` table) and technical ones in `accounts.db`. All are gitignored —
never print, commit, or copy these values into new files, examples, or logs, and
never weaken the project section of `.gitignore`. (Retired Python state such as
`config.json` and `sessions/` may still linger locally; it is gitignored too.)

Куки шифруются на диске, если задан `LOVEGW_SECRET_KEY` (пакет `secret`). Ключ
хранить **отдельно от бэкапов базы** — иначе шифрование бессмысленно: оно и
защищает ровно копии. Потеря ключа = потеря всех сессий (всем заново `/login`,
сервисным аккаунтам — `account login`). Единственные две команды, которые
намеренно выводят секреты: `secrets keygen` (новый ключ — его надо как-то
передать оператору) и `account cookie` (заголовок для локальных скриптов, и он
отказывается писать в терминал — только в пайп).
