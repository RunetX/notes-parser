# Бриф: служебно-словарные (регистро-независимые) признаки атрибуции

## Зачем

Атрибуция авторства (`personas attribute/verify/calibrate`) сейчас стоит на двух
сигналах: **стиль** (символьные 3-граммы, `style_profiles`) и **лексика**
(TF-IDF по словам, `lexis_profiles`). Оба — поверхностные и **зависят от темы и
регистра**: как только автор пишет в непривычной манере, косинусы уплывают.

Показательный провал: заметка 312743 (подтверждённо авторская, но в рубленом
разговорном регистре вместо обычной развёрнутой рефлексии) — настоящий автор на
месте **#2713 из 8922**, с рецент-фильтром **#175 из 697**. Ни стиль, ни лексика
её не ловят.

**Служебные слова** (предлоги, союзы, частицы, местоимения, формы «быть») —
классический сигнал форензик-атрибуции (Mosteller–Wallace, Burrows’ Delta)
именно потому, что употребляются **бессознательно и стабильно вне зависимости от
темы и настроения**. Это единственная фича, бьющая по смене регистра. Задача —
добавить её третьим сигналом.

## Дизайн

### Признаки (фиксированный вектор на автора)

1. **Частоты служебных слов**: относительная частота каждого слова из
   фиксированного списка (см. ниже), т.е. `count(word)/total_tokens`. Размерность
   = длина списка (~200).
2. **Структурные фичи** (несколько чисел, добить в тот же вектор): средняя длина
   предложения (в словах), средняя длина слова (в буквах), доля запятых на слово,
   доля «!», «?», «…», «—», «(» на предложение, TTR на первых N словах. ~8–10 фич.

Итоговый вектор = [частоты служебных слов ‖ структурные фичи].

### Метрика: Burrows’ Delta (рекомендуется)

Классика для служебных слов — **Delta**: z-нормировать КАЖДУЮ фичу по среднему и
сигме корпуса, расстояние = средний модуль разности z-значений (Manhattan на
z-скорах). Меньше Delta = ближе автор. Для интеграции в существующий пайплайн,
где всё на «чем больше — тем ближе», использовать **–Delta** или преобразовать в
сходство `1/(1+Delta)`.

- Хранить пер-фичевые mean/std корпуса (в `funcwords_meta`, как `lexis_meta`),
  чтобы z-нормировать запрос тем же преобразованием.
- Альтернатива попроще (если Delta усложняет комбинирование): косинус по
  z-нормированному вектору. Начать можно с косинуса ради единообразия с двумя
  другими сигналами, но **померить обе** на LOO (Delta для служебных слов обычно
  сильнее).

### Хранение (миграция v15)

```sql
CREATE TABLE funcword_profiles (
    user_id  INTEGER PRIMARY KEY REFERENCES users(id),
    tokens   INTEGER NOT NULL,   -- всего слов учтено
    dims     INTEGER NOT NULL,
    vec      BLOB NOT NULL,      -- dims × float32 LE (сырые относительные частоты + структурные)
    built_at TEXT NOT NULL
);
CREATE TABLE funcword_meta (      -- одна строка id=1: пер-фичевые mean/std для Delta/z
    id    INTEGER PRIMARY KEY CHECK (id = 1),
    dims  INTEGER NOT NULL,
    mean  BLOB NOT NULL,          -- dims × float32
    std   BLOB NOT NULL,          -- dims × float32
    built_at TEXT NOT NULL
);
```

`min-tokens` порог: служебные частоты нужны на объёме; ставить ~300–500 слов
суммарно (иначе шум). Вынести флагом `-func-min-tokens`.

### Интеграция в скоринг (третий сигнал)

- `AttributionCandidate` += `FuncZ`, `FuncCos` (или `FuncDelta`), `HasFunc`.
- `Attribution` += `FuncProfiles`, `FuncCosMean`, `FuncCosStd`, `FuncWeight`.
- `combineScores` → три сигнала:
  `combined = wStyle·zStyle + wLex·zLex + wFunc·zFunc`, веса нормировать; при
  отсутствии профиля сигнала — нейтральный фон z=0 (как уже сделано для лексики).
- Добавить `funcwordAttributor` (по образцу `lexisAttributor`) с `vec`/`cosinesOf`.
- Прокинуть в `AttributeText`, `AttributeIdentityNotes` (`scoreNote`),
  `CalibrateNotes`/`looOne`, `VerifyText` (`suspectScore`).
- Флаг `-func-weight` (дефолт подобрать по LOO), дефолтную развесовку сделать,
  например, style 0.3 / lex 0.3 / func 0.4 — но **подобрать на held-out**.

## Список служебных слов (стартовый, ~150; расширить до ~250)

Предлоги: в во на с со к ко от ото до из изо у о об обо для за над под подо при
про через без между около перед после среди ради сквозь по возле вокруг кроме
вместо благодаря согласно вопреки.
Союзы: и а но или что чтобы как когда если потому так тоже также либо ни зато
однако хотя пока чем будто словно ведь раз чуть коли ежели притом причём.
Частицы: не ни же бы б ли вот вон даже только лишь уже ещё разве неужели именно
почти вроде типа мол дескать якобы будто бишь -то -либо -нибудь ка.
Местоимения: я ты он она оно мы вы они это тот этот такой который кто что чей
себя свой мой твой наш ваш весь каждый любой сам самый всё все кто-то что-то
кое-кто никто ничто некто нечто иной другой.
Формы «быть» и связки: был была было были есть будет буду будешь будем суть.
Частотные наречия/указатели: там тут здесь тогда теперь сейчас потом уже очень
так вот здесь туда сюда оттуда отсюда везде нигде всегда никогда иногда.

> Слова с дефисом (`кто-то`, `-нибудь`) и `ё→е` учесть при токенизации.
> Хранить список в коде константой (как `defaultDisclosurePatterns`), с флагом
> `-funcwords file` для переопределения (по образцу `-patterns`/`-topics`).

## Критерий успеха (обязательно измерить)

Прогнать `personas calibrate -notes 305964,306067,306075,306085,306127,312743
-author p852 -active-days 730 -min-author-notes 1` ДО и ПОСЛЕ добавления фичи
(с `-func-weight`):

- Базлайн (сейчас, стиль+лексика+рецент+жанр): медиана ранга **4** (без жанра —
  11); 312743 остаётся регистро-выбросом (≈#175 при одном рецент-фильтре, жанр
  сужает пул до ~324, но саму смену регистра не лечит).
- Успех: медиана падает и/или 312743 заметно поднимается (например, в верхние
  десятки среди живых). Если 312743 не двигается — честно зафиксировать, что для
  этого текста достигнут предел стилометрии, и не натягивать веса на один пример.

## Подводные камни

- **Короткий текст** служебные частоты оценивает шумно — держать порог токенов и
  предупреждение (как `shortQueryNgrams`).
- **Delta требует пер-фичевого z** по корпусным mean/std — хранить в
  `funcword_meta`, применять к запросу тем же преобразованием (иначе поедет, как
  было бы с центрированием стиля).
- **Не тюнить веса на тесте**: `-func-weight` подбирать так, чтобы не
  переобучиться на 6 заметках; в идеале — на отдельном held-out.
- **Токенизация**: служебные слова — это слова длиной от 1 буквы, форма важна
  (не лемматизировать: «был/была/было» — разные фичи, и это ОК).
- Диск `archive.db` на H: — проход по ~10 млн комментариев минуты; операция
  разовая, идемпотентная (перестройка с нуля, как `lexis build`).
