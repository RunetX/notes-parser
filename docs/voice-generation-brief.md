# Бриф: `personas voice` — генерация текста в манере участника

**Статус (2026-08-05): реализовано, снято три живых прогона.** Результат
**отрицательный по главному вопросу**: черновик воспроизводит не манеру, а
словарь (два прогона в режиме `note`), а в режиме `comment` мерить вообще нечем —
атрибутор не узнаёт и настоящие комментарии автора. Цикл обратной связи работает.
Подробности — в разделах «Первый/Второй/Третий живой замер»; что уточнилось по
ходу реализации — в конце файла.

## Зачем

Аналитический слой архива читает только **из** людей. Отсюда две дырки:

1. **Стилевой профиль нечитаем.** `style_profiles`/`lexis_profiles` —
   хешированные необратимые векторы. По ним нельзя сказать, *как* по мнению
   системы звучит человек, и нельзя проверить профиль глазами.
2. **Атрибуцию нечем атаковать.** `personas attribute` умеет «текст → вероятные
   авторы», но нет способа проверить, ловит ли он голос вообще. Проект уже знает,
   что такие тесты склонны говорить «ДА» всем (`personas verify` на топ-авторах
   бесполезен) — состязательная пара нужна именно поэтому.

Инструмент строит **читаемую стилевую карту** из сырого текста и генерирует по
ней текст, который прогоняется через собственную атрибуцию архива и сравнивается
с тем, как та узнаёт *настоящие* тексты того же человека. Побочно это первый
онлайн-вызов LLM в ветке `personas` (до сих пор там только офлайн-цикл «выгрузка
JSONL → внешняя разметка → импорт»).

**Границы (решение заказчика).** Только CLI, вывод в файл и консоль. Пути
публикации нет ни на сайт, ни в мессенджеры: инструмент имитирует письмо живого
частного человека, поэтому каждый артефакт носит штамп «машинная генерация, не
публиковать», а отсутствие пути публикации закрепляется тестом на импорты.

## Интерфейс

```sh
lovegw personas [-db …] [-seed N] voice card    <p<id>|u<id>|user_id>
lovegw personas [-db …] [-config …] [-topic "…"] [-control p<id>] voice note    <token>
lovegw personas [-db …] [-config …] -reply-to <comment_id> [-control p<id>] voice comment <token>
```

`card` — детерминированная карта **без LLM и без конфига** (работает без
API-ключа, полезна сама по себе, служит входом для остальных). `note`/`comment` —
карта + образцы → LLM → K черновиков → замкнутый цикл через атрибуцию.

**Терминологическая мина:** в `internal/tgx/voice.go` «voice» — это голосовое
сообщение (ASR). Действие CLI всё равно `voice` (для домена слово верное), но
каждый новый файл открывается комментарием, что здесь «голос» = авторская манера
письма.

### Два подготовительных рефакторинга

**1. Вынести ядро скоринга из `scoreNote`, НЕ меняя его сигнатуру** (иначе правка
расходится в `AttributeIdentityNotes`):

```go
// rankTextScores скорит текст против всех профилей уже загруженного слоя.
// cf != nil && cf.on() — фон (mean/std косинуса) считается только по
// правдоподобным кандидатам, как в VerifyText; nil — по всем (поведение scoreNote).
func rankTextScores(text string, sa *styleAttributor, la *lexisAttributor,
    lexWeight float64, cf *candidateFilter) (textRanking, bool)
```

Тело — середина текущего `scoreNote` (`:128-146`) с заменой `meanStd` на
`meanStdFiltered`/`meanStdMapFiltered` при `cf.on()` (та же подстановка, что уже
делает `suspectScore` `verify.go:135-143`). `scoreNote` становится обёрткой на
`rankTextScores` + `countGreater`. При `cf == nil` поведение побитово прежнее.

Причина, по которой цикл обязан жить **внутри** `internal/archive`, сильнее, чем
«нужны неэкспортированные функции»: `styleAttributor.vec` центрирует запрос тем
же средним, что профили (`:252-260`), а `lexisAttributor` намеренно **не**
центрирован. Вынеси их наружу — и однажды кто-нибудь отцентрирует лексику «для
симметрии», молча убив атрибуцию (регрессия задокументирована в `:281-286`:
медиана ранга 2→55).

**2. Две экстракции.** `loadLexisIDF(ctx, genre)` из `loadLexisProfiles`
(`lexis.go:178-187`) — карте нужен только вектор IDF, грузить ради него ~160 МБ
профилей нельзя, `voice card` должен работать вообще без профилей.
`digestLLM` → `cmd/lovegw/llmclient.go` как `llmClient(cfg)` (3 вызова), иначе
`personas_voice.go` импортирует `tgx` сам и тест-страж теряет смысл.

## Дизайн

### Стилевая карта (детерминированная, без LLM)

`VoiceShape` — механика письма в одном жанре; всё измеряется, ничего не
оценивается: это цели для генерации и материал для диффа.

- **Объём**: `Dist` (p10/p25/median/p75/p90) по рунам, предложениям, словам в
  предложении, длине слова, абзацам. Квантили, не среднее: распределения
  длиннохвостые.
- **Пунктуация**: знаков на 1000 рун (`, . ! ? … — - : ; « " ( )`).
- **Скобочная подпись отдельно от частот**: доля текстов с серией `)` длиной
  ровно 1/2/3/4+ и с `((`. «)» против «))» режет 1092 автора до 5 за проход —
  самый острый из дешёвых признаков, и «частота на 1000» его размывает.
- **Регистр и финал**: доля текстов без финальной точки, целиком строчных,
  начатых со строчной, слов КАПСОМ, текстов с «ё».
- **Разметка сайта**: `[b]`/`[i]`/`[u]`, `:::код:::` (`smileyRe`), топ смайлов.
  **Решение: генерация воспроизводит разметку как есть.** `normalizeStyle` её
  сохраняет (`stylometry.go:356`), то есть она входит в измеряемый сигнал —
  черновик без `:::agree:::` измеримо не этот человек. Markdown валидатор режет.
- **Эмодзи**: измеряем и **запрещаем** в черновике, если у автора 0 (корпус
  старше эмодзи, модель иначе насыпет). Детект — диапазоны рун, без зависимости.
- **Обращения** (комментарии): доля реплик с `love.AddressPrefix != ""`.
  Корпусные 93,6 % (`addressee.go:14`) — среднее по сайту, нужна личная доля.
- **Ритм**: часы и дни недели местного времени. В генерацию **не идёт** (у
  черновика нет даты) — так и написать в карте, чтобы никто не прочёл его как
  цель генерации.

**Характерная лексика без прохода по корпусу.** `loadLexisIDF` → `idf, dims`; по
текстам автора `forEachWord` → `bucket = hashWordRunes(w)%dims`, копим
`count[word]` и `bucketWords[bucket]`; `TFIDF = (1+ln count)·idf[bucket]` — та же
формула, что `tfidfVec` (`lexis.go:128`), то есть ранжирование в одном
пространстве с атрибутором. Проход по 10,7 млн комментариев не нужен. Честные
пределы печатать рядом со списком: корзины общие, редкая корзина может подарить
вес частому слову, а ловим мы только **внутриавторские** коллизии (флаг
`Collision`); `forEachWord` требует букв ≥2, поэтому «и», «в», «не» невидимы —
это пробел брифа funcwords, не наш.

**Корпус и усечение.** `ORDER BY id DESC LIMIT -recent` (дефолт **2000** на
жанр): `idx_comments_author` не покрывает `text`, у тяжёлого автора 25 тыс.
комментариев — случайное чтение на строку на медленном диске H:. Печатать **и**
`Texts`, **и** `TotalHave`, чтобы усечение не было невидимым.

**Отбор образцов — послойный, seeded, с held-out.** Ключ текста `FNV(seed, id)`:
тот же `-seed` на той же БД даёт ту же выборку. Образцы берутся послойно по длине
(корпус режется на `samples` корзин по рунам, из каждой — текст с минимальным
ключом), иначе промпт уезжает в один регистр. **Пересечения образцов и полосы нет
по построению.** `-samples 0` — полноценный режим: промпт несёт только измерения,
ни одна дословная строка частного человека не уходит во внешний API (и
приватностный вентиль, и эксперимент «двигается ли ранг от живых фраз»).

### Режим комментария

`LoadVoiceThread(ctx, noteID, replyToID, limit)`: по `replyToID` берём
`note_id`/`parent_id`/`author_id`, затем `LoadNote` и ветка одним запросом
(`c.id = ? OR c.parent_id = ?`) с `LEFT JOIN comment_addressee`. `parent_id` —
корень **ветки**, не адресат (совпадает лишь в 34,8 %), поэтому адресат = автор
реплики, на которую отвечаем, а адресаты чужих реплик — из слоя.

В промпт: заметка (ник + текст до 1500 рун), ветка стенограммой с пометкой
«← отвечаем на эту», **собственные реплики цели в этой же ветке** помечены `self`
(её живой голос в этом самом треде — лучший доступный образец), ник адресата,
целевая длина из карты (медиана обычно 40–200 рун — модели надо прямо сказать,
что это одна-две фразы, а не эссе).

**Префикс подставляет инструмент, не модель.** Модель возвращает только тело;
при `AddressPrefix ≥ 0.5` и `ReplyToID != 0` → `Rendered = "<Ник>, " + text`.
Скоринг идёт по `Rendered` (это то, что появилось бы на сайте, и префикс — часть
измеряемого сигнала). Валидатор отвергает тело, где префикс уже есть, — так ник
физически нельзя выдумать.

### Вызов LLM

Seam как в дайджесте: `archive` **не импортирует** `internal/llm`. Схема
`{"drafts":[{"text","idea"}]}` + `additionalProperties:false`. Системный промпт
по-русски, отдельные хвосты для заметки и комментария; жёсткие правила: никаких
новых фактов о человеке, не копировать образцы, измерения — это **цели**,
разметка сайта воспроизводится, markdown запрещён, эмодзи только если они есть в
измерениях, ровно K вариантов, различающихся **содержанием**. Промпт-тело —
`WriteVoiceBrief(w, card, kind)` по образцу `digest.WriteMaterials`. Ответ
валидируется до использования, брак — ошибка целиком.

**В промпт идут только ключи тем** из `identity_facts` (`dacha`, `kids`), **без
цитат-доказательств**; ни `IdentityRelations`, ни досье, ни `nick_history`.
Голосу нужна манера, а не биография — биография в промпте превращает
стилометрический эксперимент в другую вещь.

### Замкнутый цикл

Профили грузятся **один раз** (~10–60 с на H:), дальше скоринг — одно скалярное
произведение на профиль (~30 мс). Полоса 30 + 3 черновика × 2 раунда + полоса
контроля ≈ 70 скорингов ≈ 2 с. Поэтому цикл внутри `archive`: через
`AttributeText` профили перезагружались бы на каждый черновик.

**Эталонная полоса (`VoiceBand`)** — те же ранги, снятые тем же путём, по
held-out реальным текстам той же личности. Без неё «ранг 37» не значит ничего: на
машинном тексте атрибуция заведомо слаба (`attribute_batch.go:281-286`).

**Полоса оптимистична, и это надо считать, а не оговаривать.** Held-out тексты
входят в стиль-профиль автора (leave-one-out нарушен — тот же caveat, что в
`AttributeIdentityNotes` `:47-50`), а черновик — нет. Поэтому для каждого текста
полосы считаем **контаминацию** = `ngrams(текста) /
style_profiles.ngrams(автора)` (первое возвращает `addCharTrigrams`, второе лежит
в таблице). У автора с 200 заметками это ~0,5 % и полоса почти честная; с 4
заметками — 25 %, и полоса бессмысленна. При медианной контаминации выше
`BandContaminationMax = 0.05` **полоса не строится вовсе**, а отчёт говорит
почему, вместо нечитаемого числа.

**Критерий приёмки — квантиль полосы, не константа.** `bandQuantile(band, rank)`
= доля реальных текстов автора, которые атрибутор узнаёт **хуже** черновика.
Принят при `q ≥ -accept` (дефолт **0.25**) и `rank > 0`. Никаких «ранг ≤ 10»: у
одного автора его заметки лежат на 1–26, у другого на 40–3000.

**Страж копирования.** `wordShingles` — пересечение 5-грамм слов черновика с
образцами; выше `-max-copy` (дефолт 0.30) черновик отвергается. Без него модель
пересказывает образец и «побеждает» атрибутор дословностью.

**Обратная связь второго раунда** — только отклонения выше допуска (10 %
относительных на частотах, шаг квантиля на длинах): дельты длины/предложений/
запятых, отсутствующие `))`, лишняя финальная точка, **не использованные
характерные слова** и **слова, которых у автора нет ни разу** (полный словарь
автора карта уже построила — проверка по map), текущий ранг, квантиль полосы и
кого атрибутор назвал вместо автора. Раундов максимум 3 (Goodhart, см. ниже).

**Контроль.** `-control <token>` скорит каждый черновик против второй личности и
строит **её собственную** полосу. Печатаемое правило: *если q контроля не ниже q
цели — атрибутор на машинном тексте не различает людей, и вердикт цикла
отбрасывается целиком.* Без `-control` отчёт предупреждает, что прогон без
контрольной группы и его вердикт не интерпретируется.

**Жанр эталона.** `note` → `GenreNotes` (register-matched; слой должен быть
построен). `comment` → `GenreAll` — ближайший существующий. Третий жанр
`comments` — **follow-up, не в этом объёме** (~4 строки в `genre.go` + пересборка
профилей); полоса реальных комментариев сама покажет, нужен ли он.

### Флаги

`-genre` (дефолт по режиму), `-drafts 3`, `-rounds 2`, `-samples 6`, `-band 30`,
`-control ""`, `-lex-weight 0.5`, `-recent 2000`, `-seed 1`, `-accept 0.25`,
`-max-copy 0.30`, `-top-words 40`, `-topic ""`, `-reply-to 0`, плюс существующие
`-note`, `-in`, `-active-days`, `-min-author-notes`, `-out`, `-db`, `-config`.

**Каждый новый флаг со значением обязан попасть в карту `reorderArgs`**
(`personas.go:100-112`): `topic`, `reply-to`, `drafts`, `rounds`, `samples`,
`band`, `recent`, `seed`, `control`, `accept`, `max-copy`, `top-words`. Иначе
`personas voice note p852 -topic "про дачу"` разберёт `p852` как значение флага.

### Вывод и штамп

`dump/voice/<identity>-card.json`; `<identity>-<mode>-<stamp>.json` (журнал:
карта, полосы, каждый раунд с промптом, каждый черновик с измерениями, диффом,
скорами, вердиктом); `<identity>-<mode>-<stamp>.txt` (лучший черновик,
шапка-предупреждение, в режиме комментария — форма «Ник, …» и тред). Штамп
`VoiceStamp{Machine:true, DoNotPublish:true, Warning:…}` ставит конструктор, не
вызывающий: пути, порождающего артефакт без штампа, нет. Отчёт человеку — в
`os.Stderr`, JSON — через `writeJSONFile` `personas.go:405`.

## Guardrails

- В новом коде нет вызовов `love.PostNote`/`love.PostComment`, `store.Open` не
  зовётся вовсе (в отличие от `personas_gender.go`, которому нужны куки).
- **Тест-страж**: разобрать `personas_voice.go` через `go/parser` и проверить, что
  в импортах нет `internal/store`, `internal/love`, `internal/tgx`,
  `internal/maxx`, `internal/dmbot`, `internal/mirror`, `internal/news`,
  `internal/bridge`; та же проверка `internal/archive/voice*.go` на
  `internal/llm`. Дешёво и держится во времени, в отличие от обещания в
  комментарии.
- **Приватность в комментарии к коду**: при `-samples > 0` инструмент отправляет
  дословные тексты частного человека во внешний API; `-samples 0` существует
  чтобы это выключить, журнал фиксирует, какие id ушли.
- **Если публикацию когда-нибудь откроют** (чтобы это было решением, а не
  случайностью): инъекция `love.Client` на уровне CLI (`archive` его не
  получает); `DoNotPublish` из константы становится осмысленным флагом с
  отдельным «одобрено человеком» артефактом; ключ идемпотентности вроде
  `message_targets`, потому что POST на сайт не повторяется и не идемпотентен;
  временно-корректный ник через `nick_history` вместо `users.name`; шаг
  подтверждения человеком по образцу «да» из `news`.

## Подводные камни

1. **Цикл может не принимать вообще ничего.** Атрибуция на машинном тексте
   заведомо слаба. Мерить: распределение `bandQuantile` по ≥5 целям, как часто
   второй раунд улучшает ранг. Ничего не проходит — честный вывод «атрибутор не
   узнаёт машинный текст», и это результат; порог не опускать.
2. **Goodhart по хешированной метрике.** Раунды взбираются по 3-граммам и
   tf-idf-корзинам: модель может поднять ранг, набив характерные слова и `))`,
   выдав пародию. Против — страж копирования, лимит раундов, `idea` каждого
   черновика в журнале; плюс мерить число слов из карты на 100 слов по раундам.
   Автоматической замены чтению глазами нет.
3. **Hub-смещение лексики назовёт не того.** Нецентрированный косинус любит
   крупные профили. Мерить: три несвязанные цели, сравнить `TopID` — если это
   каждый раз один человек, колонка «топ-1» шум, информацию несёт только ранг
   против полосы.
4. **Режим комментария будет почти случайным.** Реальные комментарии коротки,
   большинство ниже `shortQueryNgrams = 300` (`personas_attribute.go:27`), а
   `all`-профили для них регистрово несовпадающие. Мерить медиану полосы и число
   коротких текстов в ней; медиана в тысячах — `GenreComments` не улучшение, а
   предпосылка.
5. **Полоса оптимистична** даже под порогом контаминации. Сверить пару целей с
   `personas calibrate -notes … -author p<id> -genre notes`, чей leave-one-out
   ранг — честное out-of-sample число.
6. **В характерной лексике будет мусор**: глобальные коллизии корзин
   недетектируемы. Пересмотреть топ-30 на цели с ground truth. Высокая доля
   мусора — решение слой funcwords из соседнего брифа, а не подкрутка здесь.
7. **Дрейф эпохи.** `-recent 2000` смешивает годы: манера, сменившаяся в 2019,
   усредняется. Построить карту по половинам спана и сравнить
   `Punct`/`Runes`/`ParenRuns`; заметная разница — нужен флаг временного окна, а
   полоса должна браться из той же эпохи, что образцы.
8. **Отказы модели.** Имитация реального (пусть псевдонимного) человека может
   упираться в классификаторы. Мерить долю отказов; систематические отказы — факт
   о задаче, а не баг промпта, который надо обойти.

## Первый живой замер (2026-08-05)

Цель — u294456 «А.С.Сенин 60» (1091 заметка), контроль — u175869 «Гадёныш»
(310 заметок), эталон `notes`, тема «музыка, под которую хорошо начинается
утро», 3 черновика, модель claude-opus-5.

**Полосы разошлись на порядок, и это первый результат.** У цели ранги реальных
заметок 2 / 35 / **404** / 1150 / 3722 из 4136 (контаминация 0,1 %), у контроля
1 / 1 / **2** / 15 / 3201. То есть собственные тексты Сенина атрибутор узнаёт
медианно на 404-м месте, а Гадёныша — на 2-м. Атрибуция на цели слаба сама по
себе, и **квантили двух личностей несопоставимы напрямую**: одна и та же доля
означает для них разное. Прямое сравнение рангов честнее — инструмент теперь
помечает случай «контроль выше цели».

**Черновики прошли лексикой, а не манерой.** У всех трёх `styleZ` отрицательный
(−0,92 / −1,58 / −0,84) при положительном `lexZ` (2,16 / 2,33 / 1,75): по
символьным 3-граммам тексты похожи на автора **хуже среднего**, а вверх их
тянет совпадение словаря. Ровно предсказанный в «Подводных камнях» Goodhart:
модель, получив список характерных слов, набивает их («lovesongs», «певец»,
«танцы», «рок»). Вердикт «ПРИНЯТ» по квантилю (47 % при пороге 25 %) в этом
случае вводит в заблуждение, поэтому теперь он несёт оговорку про
отрицательный styleZ прямо в шапке текстового артефакта.

**Различающая сила неустойчива.** По прямым рангам цель выигрывает у контроля
в 2 случаях из 3 (603 против 944; 908 против 1681), но черновик №2 оказался
ближе к контролю (1079 против 323). На трёх черновиках это не сигнал.

**Два опасения не подтвердились:** hub-смещение не проявилось — топ-1 у каждого
черновика свой (три разные анкеты), а не один и тот же крупный профиль; страж
копирования показал 0 % пересечения с образцами, то есть пересказа нет.

**Не проверено этим прогоном:** цикл обратной связи (раунд 1 принял сразу,
второго не было) и режим `comment`.

**Что это значит.** Инструмент и измерительная часть работают; вывод по существу
— профили ловят словарь и тему, а не человека. Порог не трогать: правильный
следующий шаг — сравнить `styleZ` черновиков с `styleZ` реальных текстов полосы
и, если разрыв систематический, признать, что имитация манеры этим слоем не
измеряется, а не подкручивать `-accept`.

## Третий живой замер (2026-08-05): режим `comment` и негодная полоса

Цель — u175869 «Гадёныш», контроль — u294456, эталон `all`, комментарий первого
уровня к живой заметке 312883 (заведена в архив через `grab`), 3 черновика,
2 раунда.

**Подводный камень №4 подтвердился полностью, и он хуже, чем ожидалось.** У
полосы цели ранги реальных комментариев 612 / 7855 / **8391** / 8876 / 9210 из
9215, и **26 из 30** текстов полосы короче порога объёма. То есть атрибутор не
узнаёт даже НАСТОЯЩИЕ комментарии автора. Полоса контроля неотличима
(884 / 6924 / **8310** / 9041 / 9192) — различающей силы в жанре комментария нет
вовсе. По правилу из брифа `GenreComments` теперь **предпосылка**, а не
улучшение: без register-matched слоя измерять комментарии нечем.

**Из этого — правка инструмента, а не оговорка в отчёте.** Первый прогон
напечатал «ПРИНЯТ: узнаётся лучше 83% реальных текстов» по полосе, медиана
которой лежит на 8391-м месте из 9215: квантиль полосы выглядит убедительно
всегда, в том числе когда мерить нечем. Поэтому `BuildVoiceBand` теперь
отказывается ещё в двух случаях (`bandUnusableWhy`, рядом с контаминацией):

- больше половины текстов полосы короче `voiceShortNgrams` — их ранги шумят;
- медиана полосы дальше `bandMedianMaxShare` (0,5) списка — слой не узнаёт и
  настоящие тексты автора, эталона нет.

Непригодная полоса не даёт приёмки (`Accepted` уже требовал `Band.Usable`),
и вердикт прямо говорит, что сравнивать не с чем. Повторный прогон так и
отработал: 6 черновиков, ни один не «принят», ранги 8127–9213, `styleZ` от
−1,71 до −2,70, контроль не ниже цели — плюс печатается предупреждение, что
вердикт цикла отбрасывается целиком.

**Что заодно оказалось не реализовано.** Режим `comment` умел только ответ
внутри ветки (`-reply-to`), а самый обычный случай — комментарий первого уровня
к заметке — был недоступен. Добавлен `-note <id>`: контекстом идёт заметка плюс
корневые реплики как «уже сказанное», адресата нет (обращение не подставляется),
системный промпт свой. Тесты — `TestLoadVoiceNoteThreadTopLevel`,
`TestVoiceTopLevelPromptDiffers`, `TestBandUnusableReasons`.

**Набивка словаря видна и здесь:** во втором раунде в черновики приехали «тока»
и «актриса» — прямо из списка характерных слов (там же ритуальные «клуб
пятничных неудачников», «color/red/green» из разметки).

## Почему «совсем не похоже» — и что из этого исправлено (2026-08-05)

Отзыв на живой комментарий был «совсем не похоже на Гадёныша». Разбор промпта
показал четыре причины, и три из них — прямые дефекты, а не предел метода.

**1. Комментарий учился на заметках.** Корпус образцов, словаря и полосы шёл от
ЖАНРА эталона, а у режима комментария жанр `all` = заметки + комментарии.
Следствия в живом прогоне: среди шести образцов лежала 378-рунная **заметка**, а
список характерных слов возглавляли формулы его заметочного формата («клуб»,
«пятничных», «неудачников», «объявляется», «открытым»). Введён отдельный от
жанра параметр `VoiceCardParams.Kind` (род текста, который пишем): образцы,
словарь и разрез идут от рода, слой атрибуции остаётся за жанром.

**2. Реплики подавались без того, на что они отвечают.** Комментарий на 87 рун
сам по себе не показывает манеру — вся манера в том, как человек цепляется за
чужие слова. Образец-реплика теперь подаётся парой «на что отвечает → что
ответил»; цель ответа берётся из слоя `comment_reply` (настоящая цель с мобильной
версии), при его отсутствии — из `parent_id`, а у реплики первого уровня
контекстом идёт сама заметка.

**3. Шести образцов на коротких текстах мало.** Число образцов теперь считается
по медиане корпуса (`voiceAutoSamples`): <150 рун → 24, <400 → 12, иначе 6.
`-samples` по-прежнему перебивает, `-samples 0` остаётся приватностным вентилем.

**4. Инструмент сам заказывал набивку.** В диффе стояла строка «не использованы
характерные слова автора: …», то есть цикл обратной связи прямо велел насыпать
список — ровно то, что давало styleZ < 0 при lexZ > 0. Теперь:

- список подаётся как «привычные слова, берётся только то, что ложится само»,
  рядом печатается **норма самого автора** (`VocabRate`, слов из списка на 100
  слов) и потолок;
- дифф двусторонний: перебор называется перебором, недобор — недобором;
- черновик с частотой выше нормы × `VocabStuffFactor` (3) отбраковывается **до
  скоринга**, иначе цикл учится обходить меру;
- из словаря убраны токены разметки (из `[color=red]` `forEachWord` достаёт
  «color» и «red» — они и возглавляли список) и слова из одного текста
  (`Docs < 2`: разовая тема, а не привычка).

**5. Пятая причина нашлась только по образцам.** Когда реплики поехали в промпт
парами, стало видно, чем автор пишет на самом деле: «шило в жопе не утаишь»,
«Бысто наотношались. Как покакать.» — грубо, коряво, с нарочными опечатками,
фраза рублена. Модель же выдавала гладкий литературный текст с симметричной
шуткой в конце. В `voiceSystemBase` добавлено правило не приглаживать регистр:
приглаженный текст не похож ни на кого конкретного. После этого черновики пошли
со строчной, с «щас», «тока» и его грубостью, при той же медиане длины.

**Что показал контрольный замер после правок (прогон 2026-08-05, 18:31).**
Черновики стали узнаваемо ближе к автору **на глаз**, а числа при этом не
улучшились: `styleZ` у самого похожего черновика −1,26, а у гладкого
литературного из прошлого прогона было −0,96. То есть на репликах в 80–100 рун
стилевой слой не отличает похожее от непохожего — ровно то, о чём говорит
негодная полоса (30 из 30 текстов ниже порога). Вывод: правки оценивать глазами,
пока нет `GenreComments`; подгонять их под `styleZ` было бы подгонкой под шум.
Побочно: набивка после правок держится на 6–7 слов на 100 при норме автора 3,04 —
под потолком ×3, то есть страж не мешает, но и разгуляться не даёт.

Чего эта правка **не** лечит: слабость самой атрибуции на комментариях (полоса
негодная, см. третий замер) — это следующий шаг, `GenreComments`.

## Что уточнилось при реализации

- **В корпусе лежат неразобранные HTML-сущности**: `&quot;` в 6059 заметках,
  плюс `&amp;`/`&nbsp;`. Без раскодировки карта уверяла, что автор начинает
  заметки со слова «quot», а частота кавычки была занижена вдвое (2.96 против
  6.41 на 1000 рун). `voiceTexts` раскодирует; атрибуции это не касается — она
  работает по сырому тексту профилей.
- **Коллизии корзин универсальны, но не мешают.** При 4096 корзинах на десятки
  тысяч слов корзину делят практически все слова, и фильтр «показывать только
  без коллизий» опустошал список. Знак ошибки другой, чем казалось: вес корзины
  — **нижняя** оценка редкости слова (частое слово в корзине тянет IDF вниз),
  поэтому верх списка надёжен, а низ ничего не значит. Фильтр убран.
- **`love.AddressPrefix` считает обращением любую раннюю запятую** («всё как
  всегда, ничего нового» → «обращение» из 14 рун). От этой доли зависит,
  подставлять ли ник в черновик, поэтому префикс сверяется с реальными никами
  (`siteNicks`); без сверки доля завышается примерно в полтора раза.
- **`NoFinalPunct` считает по терминаторам, а не по буквам.** Текст, обрывающийся
  скобкой-улыбкой («день))») или двоеточием смайла, — это «точку в конце не
  ставит»: для генерации важно ровно это.
- Полоса строится из held-out, а образцы — из другой части корпуса; гарантия
  непересечения закреплена тестом, а не порядком вызовов.
- **Structured outputs не принимают ограничения массива.** `minItems`/`maxItems`
  в JSON-схеме дают `400 invalid_request_error` («For 'array' type, property
  'maxItems' is not supported»). Python/TS SDK вырезают такие ключи молча, Go
  отправляет как есть — поэтому ошибка вылезает только на живом запросе. Число
  вариантов задаётся текстом промпта и проверяется на нашей стороне; схему
  стережёт тест `TestVoiceSchemaHasNoArrayConstraints`. То же касается
  `minLength`/`maxLength`/`minimum`/`maximum`.
